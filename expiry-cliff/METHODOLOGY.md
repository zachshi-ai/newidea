# METHODOLOGY · 到期悬崖学

> expiry-cliff 的每一条规则都在回答同一个问题：名义有效期撒的谎，怎么用确定性算法把它纠正回来。本文记录规则背后的动机、边界与已知局限。

## 1. 立场：度量凭证，不催办人生

到期管理工具最容易越界成「催办管家」：弹窗、推送、焦虑贩卖。本件刻意停在账本：它不推送、不评分、不决定什么「值得办」。四档判定（OVERDUE/CLIFF/CAUTION/CLEAR）描述的是**消费行为的分界**——一份 OVERDUE 的护照不是「待办事项」，是一个事实：它现在买不了国际机票。办与不办、办哪份先，是家庭的优先级判断，工具的辖区止于把「谁先坠崖、还差几天」算准。

## 2. 提前量：有效期里的暗物质

每类凭证的真实可用边界都不在卡片上。护照的六个月规则、签证的入境缓冲、驾照换证的体检周期、域名赎回的宽限期、TLS 证书的部署提前量——这些**边际（margin）**是有效期里的暗物质：真实存在、从不印在卡面、只在失效瞬间现形。

工具用一张显式的默认表把暗物质变成参数（passport 180 / visa 90 / driver_license 60 / id_card 30 / domain 30 / tls_cert 21 / warranty 14 / membership 7 / insurance 0），并给了两层覆盖：行级 margin 列（每份凭证自己的规矩）与 `--category-margin`（你家所在的司法辖区规则不同）。优先级：**行级 > 命令行 > 默认表 > 未分类 0**。

未分类按 0 处理是刻意的：一张不知道规矩的卡，名义到期日就是它唯一诚实的边界——把它按六个月规则错杀，等于用猜测污染账本。margin 0 的凭证照常入账、照常参与闸门，只是它的有效视界与名义到期日重合。

## 3. 为什么有效剩余不用比例、不用指数

`有效剩余 = 到期日 − margin − 今天`，一个减法。不用衰减曲线的理由与 alarm-fatigue 的罚分同理：**账本要能心算**。「还有 29 天」意味着本周该动手，不需要查表；一条 e^-t 曲线意味着每次都要解释。天数是凭证世界的母语。

四档边界（0/30/90）同样是行为分界不是统计结果：<0 是「已经不能用了」，<30 是「本周就办」（大多数续办流程的耗时上限），<90 是「这个季度」，≥90 是「忘掉它」。边界可以争论，但它们必须存在——没有档位的原始天数清单，会在第 14 行失去读者的注意力。

## 4. 出行闸门：合取失效的算法化

一次出行是 **N 份凭证同时有效**的合取命题：护照有效 × 签证有效 × 驾照有效 × 保险有效，任何一项为假整个计划为假。人脑对合取命题的系统性地失灵（每份「大概没问题」连乘起来没人负责）——闸门就是替你负责的连乘器：

```
对每份凭证：effective_end ≥ 归期 且 生效日 ≤ 出发日，否则 FAIL
```

两个细节：**归期而非出发日**是检查基准——你要的是归途那天还站着；**未生效凭证按生效日检查**——出发时还没生效的签证和已过期的护照一样致命，只是措辞不同（`does not start until`）。

exit 4 属于闸门而非 horizon：horizon 永远成功（账本没有「失败」状态），闸门是唯一「能拒绝什么」的出口——**度量只有能拒绝什么东西时，才算被当真了**（这条从 alarm-fatigue 的 `--fail-under` 借来，方向相反）。

## 5. 续期节奏：你自己的行政人格

同名凭证的多段有效期，是一份现成的、从未被读过账本：

- **中位周期**（`median(end − start)`）：你实际上多久续一次。护照 ~10y、车险 ~1y——它同时是「这份凭证的行政体重」。
- **惯常提前量**（`median(上一段到期日 − 这一段生效日)`）：你习惯在到期前多少天动手。0 意味着「压着截止日办」，正数是安全垫。
- **断档**：某段生效日晚于上一段到期日，差值就是你不设防的天数，show 里如实显示为 `lapsed Nd`。

惯常续办窗口（↻）是节奏的直接应用：有效剩余 ≤ 你的惯常提前量时标记。「办早了白丢有效期」的焦虑由个人基线回答，不由全局默认值回答——一个习惯提前 46 天续护照的人，看到「还有 45 天」就该动手了。

## 6. 「今天」的处置：默认真实，钉死可复现

horizon 的参照日默认 `--as-of 今天`——这是本仓库第一个默认值里含「今天」的点子，因为到期问题的语义本身就是时间索引的。但仓库的复现传统不能破：**钉死 `--as-of` 即逐字节可复现**。样例报告全部钉在 2025-12-01，CI 的 `--check` 校验以此为前提。这是「今天」的正确用法：属于真实使用，不属于交付物。

## 7. 边界情形的处置

| 情形 | 处置 | 理由 |
|---|---|---|
| 同名凭证多个持有人（两本护照） | 独立条目（键 = 名称+持有人+类别），show 用「名称 持有人」查询，纯名称查询报歧义并列出持有人 | 护照是人的不是家的；合并会把两个人的有效期算成一个怪数字 |
| 同名多段有效期（历史续期） | 取 end 最大的一段为「当前段」，全部段进 rhythm 与 show 历史 | 当前段定义是「让你合法最久的那段」，不是「最近开始的那段」——补办常改 start 不改 end |
| 断档（两段之间有空窗） | 如实显示 `lapsed Nd`，不抹平 | 不设防的天数是账本的一部分，抹平它等于篡改历史 |
| 未生效凭证（start > 今天） | FUTURE 档，排表尾；闸门检查生效日 ≤ 出发日 | 「还没生效」是正常状态不是错误 |
| 未分类凭证 | margin 0，照常入账 | 名义到期日是它唯一诚实的边界 |
| margin 列写非整数 | 报错带行号 | 静默忽略一个写错的提前量 = 假装它不存在的暗物质 |
| 两段有效期部分重叠 | 合法（提前续办的常态），重叠天数就是提前量 | 重叠是续期节奏的信号，不是脏数据 |

## 8. 已知局限

- **登记表是手工的**：本件的前置成本是「把家里凭证的到期日敲进一张 CSV」。它是一本要维护的账——这正是它诚实的地方：没有任何零依赖、纯本地的工具能自动读出你护照上的日期，声称能做的都在把你的证件照片上传到别人的云。
- **提前量按类别一刀切**：六个月规则因国家而异（有 3 个月的），签证因目的地而异。默认表是最保守的常识值，`--category-margin` 与行级 margin 是逃生门——工具给你参数，不假装知道你下个月去哪里。
- **续办耗时没有建模**：账本说「还有 29 天」，但换发护照可能要排 4 周的队。节奏（rhythm）间接编码了它（你的提前量已经包含你对排队时长的经验），但 v1 不显式区分「可用边际」与「办理时长」。
- **单日粒度**：时区边界上「今天」可能有 ±1 天的歧义；对以月计的提前量无害，对 0 天边界上的 CLIFF 判定请自己留出一天的余量。
- **account 之间不可比**：两家的 CLEAR 凭证数量不可比——登记粒度不同（有人记域名有人连月饼券都记）。账本是镜子，不是排名。

## 9. FAQ

**Q: 为什么不做成带提醒的服务？**
提醒要求常驻进程、通知权限、以及一个记得给你发邮件的服务器——最后一样意味着你的到期日存在别人的机器上。本件是账本不是管家：一年看两次 horizon，出行前跑一次 trip，已经覆盖了失效事故的绝大多数窗口。

**Q: 提前量为什么是类别默认而不是全局统一？**
因为「六个月规则」们天然按凭证类型分布：护照类有国际条约式的硬边际，保险类几乎是 0（脱保即失效，但没有「剩余不足拒保」一说）。全局统一一个 90 天，等于对保险虚报危机、对护照谎报太平。类别表让每一类凭证用它自己的方言说话。

**Q: 和 doc-drift 有什么不同？——不都是「过期检测」吗？**
doc-drift 检测**仓库内文档之间的引用失效**（文档 A 引用的事实 B 不再成立），本件检测**现实世界凭证对时间的失效**（凭证 C 对日期 D 不再成立）。前者是引用完整性，后者是有效期经济学。一个的证据在 markdown 里，一个的证据在护照上。

**Q: 为什么同名多段有效期不去重？**
那不是重复，是历史。单段是凭证，多段是节奏——没有历史就没有「你惯常提前 46 天」这行字，没有节奏，「现在办是早是晚」就退化成拍脑袋。

**Q: trip 闸门为什么检查全部凭证，连域名和 TLS 证书都不放过？**
因为人在旅途中最贵。域名 12 月 1 日到期而你 12 月 3 日才回家——续费是能远程办，但 TLS 证书 + 域名 + 银行 U 盾 + 车险一起到期就不是「能远程办」能概括的了。闸门宁可多报；嫌吵的凭证从登记表里删掉，或者用日期更近的窗口——账本跟着你的边界走。

**Q: exit 4 为什么给了 trip 而不是「存在 OVERDUE 就失败」？**
和 alarm-fatigue 的门禁哲学同源：OVERDUE 是事实陈述，永远红着的门禁没人看；trip 是一个可执行的决定，「这个决定暂时不成立」才是可以被拒绝的东西。
