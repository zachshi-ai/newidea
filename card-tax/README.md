# 卡税 · Card Tax

> 预付卡是卖给「你想成为的那个人」的，被「你实际是的那个人」消费。两者的差价静默无声：没有对账单、余额从不报龄、上次到店在记忆里永远「就在前几天」。没用完的部分不是零头——是**税**：你为「常客幻想」预付的钱，按你本来想避开的散买价计价。

预付卡在办卡那一刻之后就没有对账单了。健身年卡、英语课包、理发卡、洗车卡、瑜伽次卡——办卡时你是每月去八次的自律者，三个月后账本里只剩一场心跳骤停。没有任何 App 告诉你：

- 卡里还剩几次？**按你的实际节奏**（不是办卡时拍的胸脯），到期前能核销几次？
- 每次真实成本是多少？——不是「总价÷总次数」那个假装你会用完的口径，是**已付÷已用**。
- 商家说「再充 500 送 100」，该接吗？——你上一张卡的核销率，就是这一张的最好预测。

**card-tax 把这件事变成两份手编 TSV 账本。** 一行一次到店，一条卡档案；六个命令回答上述全部问题，并给出你这笔预付的最终账单：

```
tax = paid − used × list
```

税为正，是不去的那部分你交的税；为负，是只有到场才能赚到的折扣。散买价（list）是整个体系的锚——没有它，「付了 3650」和「去了 11 次」是两个永远不必对面的数字。

## 谁在什么场景下的什么问题

| | |
|---|---|
| **角色** | 办过预付卡/课包/次卡的都市消费者（健身、教培、理发、美容、洗车、餐饮充值） |
| **场景** | 年底盘点；「今天去不去」的犹豫瞬间；商家「再充送 X」话术递到面前的那一刻；卡过期后翻钱包才发现 |
| **问题** | 预付卡只有办卡那一刻的记忆，没有核销对账单：剩余次数、按自己节奏的到期预测、每次真实成本、续充决策，全靠感觉。没用完的部分蒸发了，连一声都没有 |
| **价值** | 把模糊的「感觉亏了」变成精确的税单；把「下周就去」的自我安慰变成断崖警报；把「再充一张」的冲动对账到你自己的历史节奏上 |

## 方法速览：一本账三张表

1. **税账（report）**——每张卡：已核销/总量、核销率、已实现税（`paid − used × list`）、判级灯；合计税与逐卡税恒等（`Σtax = Σpaid − Σused×list`，9 位小数）。
2. **节奏账（pace）**——近 8 周实际到店节奏 vs 到期钟：外推到期前还能核销几次、将蒸发的余额（剩余 × 散买价）、静默天数 vs 断崖线（`max(2× 间隔中位, 45 天)`——历史间隔的 2 倍，且不短于通识下限）。
3. **回本账（cost）**——每次已核销成本 vs 散买价、回本点（`paid ÷ list`，卡从赌注变成折扣的那一次）、回本进度。

外加两把武器：

- **续充法庭（offer）**——「再充 3000 送课时」按**你自己的历史节奏**（Σ已用 ÷ Σ持有天数，可判级卡）外推：到期内实际能核销几次、预计新税多少、占实付比例是否越过 30% 红线；旧卡还有核销率 <60% 未清的，先拦下新卡。
- **沙盘（simulate）**——「每周去 N 次」的反事实：几次可行、救回多少（救回次数 + 剩余 ≡ 原剩余）。沙盘不执法，恒 exit 0。

## 判级灯（最重者优先）

| 灯 | 语义 |
|---|---|
| `EXPIRED` | 卡已过期还剩着次数——税定格（剩余价值 ≥ 100 才亮，可调 `--red-floor`） |
| `DEAD` | 核销率 < 50% 且静默已破断崖线——这张卡事实上死了，别再骗自己「下周就去」 |
| `BLEED` | 按近 8 周节奏外推，到期时剩余 > 一半——正在放血，账本先于到期日看见 |
| `ASLEEP` | 核销率还救得回来（≥50%）但人已静默越线——冬眠，该醒了 |
| `THIN` | 持卡 < 28 天——算术照出，判级以后再说（顺便挡住新办卡的 honeymoon 假警报） |
| `ON TRACK` | 以上皆无 |
| `DONE` | 核销完毕——无论税正负，账已结清 |

## 快速开始

账本是两份 TSV（`#` 注释行合法，中英列名同效）：

```text dd:ignore
cards.tsv                     visits.tsv
card  name  pay  buy  until  units  list  target    card      date        note
yuedong 悦动健身年卡 3650 2025-09-01 2026-08-31      90  1     yuedong   2025-09-02  练背
jingjing 菁菁英语课包 4000 2025-11-15        20    260        yuedong   2026-02-10  新年第一次
xingge  型格理发卡  1000 2026-01-10         10    78         ...       ...         ...
```

- **次卡**填 `units`（总次数）；**时长卡**（年卡/月卡）留空 `units` 填 `until`，总量 = 周数 × `target`（每周预期次数，缺省 1——这是先验，`--target` 翻案，你的回忆永远赢）。
- `list` 是散买单次价，税的锚，必填。

```bash dd:ignore
python3 card_tax.py report   cards.tsv visits.tsv          # 总账+税单（红灯 exit 4）
python3 card_tax.py pace     cards.tsv visits.tsv          # 节奏 vs 到期钟
python3 card_tax.py cost     cards.tsv visits.tsv          # 回本账
python3 card_tax.py offer    --pay 3000 --units 50 --list 88 --until 2027-06-30 cards.tsv visits.tsv
python3 card_tax.py simulate --weekly 3 cards.tsv visits.tsv
python3 card_tax.py validate cards.tsv visits.tsv          # 恒等式体检（恒 exit 0）
```

`--as-of YYYY-MM-DD` 把账本钉回任何一天重放（到期前它是绿的，过期后它变红——时间旅行是免审计的）；缺省锚定账本最大日期，同一本账任何机器任何一天跑出的结果逐字节一致。`report/status`、`offer/upgrade`、`simulate/sim`、`validate/check` 同效。

## 验收标准

| # | 标准 | 验证 |
|---|---|---|
| 1 | 税恒等式：`Σ逐卡税 = Σpaid − Σused×list`，报告 9 位小数内一致；`validate` 恒 exit 0（好账本） | 38 tests |
| 2 | 守恒恒等式：逐卡 `used + remaining = units`；超发（used > units）exit 2 | tests |
| 3 | 时长卡总量 = 周数 × target（52 周 × 1 = 52）；`--target` 翻案即时生效 | tests |
| 4 | 断崖线 = `max(2× 间隔中位, 45 天)`；间隔样本不足时用通识线；`--asleep-days` 可调 | tests |
| 5 | DEAD：核销率 < 50% 且静默越线；ASLEEP：≥50% 且越线；薄卡（<28 天）永不判级 | tests |
| 6 | BLEED：近 8 周节奏外推到期核销率 < 50% 且蒸发 ≥ 100（`--bleed-floor` 可调）；EXPIRED：过期剩余 ≥ 100（`--red-floor` 可调） | tests |
| 7 | as-of 剪切语义：`--as-of` 之后的核销不存在（含边界日 ≤）；缺省锚定账本最大日期；两次运行逐字节一致 | tests |
| 8 | 赛跑：到期周数 = 天数/7，外推核销向下取整；蒸发 = 预测剩余 × 散买价 | tests |
| 9 | offer：历史节奏 = Σ已用 ÷ Σ持有天数（可判级卡）；预计新税占比 > 30% exit 4；旧卡核销率 < 60% 未清先拦；缺期限参数 exit 2 | tests |
| 10 | simulate：可行次数 = floor(假设节奏 × 窗口)；救回 + 剩余 ≡ 原剩余；沙盘恒 exit 0 | tests |
| 11 | 薄账分层：全账核销 < 3 → 判级拒绝 exit 3，**算术照出**；单卡 < 28 天 → 该卡只出算术 | tests |
| 12 | 账本损坏 exit 2：坏引用、坏日期、核销早于购卡、重复卡号、缺列、次卡无 units 且无 until | tests |
| 13 | 中英别名：列名（卡/id、实付/amount、单次价/list……）与卡号归一（`GYM-01` ≡ `gym 01`） | tests |
| 14 | 报告只打印账本 basename，绝不回显调用方路径；`--format json` 机器可读 | tests |
| 15 | examples 快照由 CI `card-tax/examples/build_examples.py --check` 逐字节校验 | CI |

## 与近邻的边界

- **dusty-subs（吃灰订阅）**：那边审**持续扣费**的服务（不取消就一直扣，从银行流水重建）；本件审**一次性预付**的服务包（钱已付清，敌人是你自己的脚）。共同的敌人是「支付与消费的解耦」。
- **cost-per-wear（每穿成本）**：那边是已购衣物拥有端的每穿成本；本件是服务包核销端的回本账——公式形似，分母一个是拥有物的使用，一个是预付额度的兑现。
- **expiry-cliff（到期悬崖）**：那边管「凭证静默失效」（提前量调整的有效期）；本件里卡过期只是税的定格时刻，核心是**核销进度与节奏**——expires 不是悬崖是终场哨。
- **recoup（回血）**：那边管闲置物转卖退出；本件的卡也能转让退出，但账本的职责是先告诉你**值不值得救**（simulate 救回多少）而不是急着挂闲鱼。
- **want-ledger（种草账）**：那边记「想要→购买」的欲望生命周期；本件从「购买」之后才开始记——**买了不用**的那一半人生。

## 诚实条款

- 本件是计算器不是律师：商家跑路、转让规则、退款政策一概不建模；税单是你谈判桌上的数字，不是法律意见。
- 散买价是你填的：填得越高税越小——这是你的皮肤游戏，骗账本就是骗下个月的自己。
- 时长卡的 target 是先验不是判决：办卡时你真心相信每周去两次，账本记得这份真诚，也记得后来的事实。
- 「没有到店记录 ≠ 没有到店」不成立——本件的宇宙里，没记就是没去；想被账本温柔对待，先把每一步记进来。
- 数据纯本地，两份 TSV，不上传任何字节。
