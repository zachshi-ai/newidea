# METHODOLOGY · 欠针 · Due Dose

## 1. 一句话

接种本只记打过的,没有人替你数欠下的——本件把本子上的产品名翻译成抗原覆盖,给每剂判定欠不欠,给查验截止日排一条补种几何。

## 2. 为什么是账本

儿童免疫是中国家庭少有的「官方替你记了大半账」的领域:接种本人手一份、门诊有电子档案、短信提醒准点。但这个领域所有的系统都在回答同一个问题——**「下一次打什么」**。没有人回答另外四个问题:

1. **按月龄,我的孩子现在欠哪几剂?**(门诊只看你约的那一种,查验才对全部)
2. **本子上的「五联第 4 针」,在查验老师眼里覆盖了什么?**(产品名 → 抗原的翻译不存在)
3. **距离查验日还有 N 天,来得及补完吗?最晚哪天去第一针?**(补种几何没人算)
4. **自费的针,花了多少、哪个系列是半程?**(价签躺在发票袋里)

提醒会断链(换城市/换门诊/关短信),账不会。抄一针一行,0–6 岁 22 剂是全部数据工程——换来的是换城市不断链、不连任何系统、字节级可复现。

## 3. 核心模型

### 3.1 抗原覆盖矩阵(翻译层)

词表把产品名归一成「抗原贡献」:单苗贡献一个抗原一剂,联合疫苗贡献多个抗原各一剂(五联 → dtap+polio+hib)。覆盖计数按抗原聚合——**剂次槽位按顺序填充**,第 1 剂永远先填槽位 1,与接种时的实际月龄无关(补种的孩子 2 岁才打第一剂麻腮风,它补的是槽位 1)。这一个抽象顺带解决了三个问题:五联替代程序(四支五联 → 脊灰 4/4,4 岁口服被替代)、IPV/bOPV 混打(都计 polio)、减毒/灭活互换(都计同种抗原,程序表才区分)。

### 3.2 月龄钟(时间层)

「N 月龄」= 生日 + N 个日历月,日对齐、月末钳制(1-31 生 → 平月 2-28)。钳制**从原始 day 每次重新计算**,不链式累积——1-31 生 +1 月 = 2-28,再 +1 月 = 3-31 而不是 3-28。判定阶梯:FUTURE(未到 anchor 月龄,不欠)→ DUE(到龄,超 3 个月内)→ OVERDUE(超 3 个月,恰线不亮)。欠账的判定与查验口径统一:**欠 = (查验日月龄应种剂次) − 已覆盖**,未到龄的剂次既不是债也不进排期,只在查验后披露。

### 3.3 补种几何(排期层)

通识规则只有两条:同抗原两剂 ≥ 28 天;不同抗原可同日并种(不同部位,含活疫苗)。由此最小完成日程是闭式:每剂最早可种日 = max(前一剂 + 28 天, 该槽位应种月龄日, as-of)。**最晚启动日 = 第一针日 + 余量**——整体顺延 δ 天仍是合法日程(间隔保持、最早日约束只松不紧),所以余量就是第一针可拖延的天数。可行性、RUSH(余量 < 14 天)、GATE-BLOCKED(差几天)全部从这一个几何推出。闭式之外再走一条逐日贪心模拟,两条路径必须给出同一张日程表——不一致当场 raise。

### 3.4 二类账(钱层)

价签就是分类:price 留空 = 一类,填了 = 自费。paid 账**按产品系列归集**(五联的钱归五联,不拆进三种抗原——家长对的是发票不是抗原表);半程针只在「先验程序到龄未齐」时点名,水痘 2 岁打完第 1 剂不是半程(第 2 剂应 4 岁)。

## 4. 与直觉的三处对决

1. **「本子上没有 = 没打过」是错的,但「本子上没有 = 没法管」是对的。** NEVER-SEEN 不指控漏打(出生医院那针常写在出生证明页),它只陈述:这一格,账本管不了。工具的边界和家长的焦虑在这里分开。
2. **「超龄欠针」不制造恐慌,它制造优先级。** 该种(●)和超龄(✗)分开——刚到龄和欠了一年是两种行动;恰线不亮(宁少报)不是宽容,是把红灯的信用留给真正的欠账。
3. **「查验」不是考试,是门槛。** 考试考「多学了多少」,门槛只问「该齐的齐没齐」。所以 catchup 的口径是查验日月龄的应种剂次,而不是「能补多少补多少」——过了门槛的剂次,查验后再说。

## 5. 开发中自纠(测试价值记录)

1. **set 迭代的哈希漂移**:ants 字典最初用 `set(schedule1) | set(CLASS2_SCHEDULE)` 迭代构建,灯的顺序随 PYTHONHASHSEED 漂移——快照在不同进程校验必翻车。全部改成固定顺序迭代;CI 前用三种哈希种子各跑一遍字节校验。
2. **翻案表没有真正生效**:`owed_by_gate` 内部读内置 `CLASS1_SCHEDULE` 常量,`--schedule` 翻案在覆盖判定生效、在补种排期失效(欠 2 剂只排 1 剂)——被「同抗原间隔 via schedule override」测试当场抓住。教训:**翻案参数必须从调用方一路传到底,任何一个函数内部引用常量,翻案就有断链。**
3. **恒等式钉错了对象**:validate 把「程序剂次 == 22」写成无条件断言,乙脑灭活 4 剂替代程序(合法翻案,总剂次 24)被判账坏。守恒恒等式的对象是「已 + 欠 + 未到龄 ≡ 当前程序表剂次」——通识值 22 只在通识表下钉死。
4. **「欠的第几剂」≠「账本第几剂」**:排期初版显示「麻腮风 第1剂」——那是欠剂序号;本子上它写的是第 2 针,家长拿这页去门诊会对不上。slot 改为从已覆盖数续接的真实剂次。
5. **注记的无差别张贴**:「出生医院那针常写在出生证明页」最初贴给所有零覆盖超龄抗原——甲肝是搬家漏的,背这个注解是误导。注记收窄到出生剂次(锚点 0 月龄):它的特指含义只在乙肝/卡介苗上成立。
6. **paid 账按抗原拆钱**:五联 ¥628 ÷ 3 拆进三种抗原——家长对的是发票,不是抗原表。改按产品系列归集,hib 覆盖作披露附注。
7. **两踩稀疏账本陷阱**:场景测试只造被测抗原的账,其它抗原全部同时超龄,exit code 断言全失真。建立构造纪律:一本「22 剂全齐」的基准账本当底,每个场景定点摘除——所有判定从绿出发。
8. **手算再输一次**:守恒式手算 15+2+5,程序 9+7+6——手算忘了乙脑槽位 1 在 14 月龄也欠;paid 合计手算把两针流感当一针。独立脚本(不经 due_dose 代码)交叉验证 9 项关键数字全对——「程序三连对手算三连错」的系列再添一笔。

## 6. FAQ

- **为什么不用小豆苗/金卫信这些 App?** 它们连的是门诊系统,答的是「下一次」;本件抄的是你手里的本子,答的是「欠下的」。App 换城市会断链,本子不会;且本件做它们不做的三件事:抗原翻译、补种几何、二类钱的账。
- **要不要抄电子档案?** 抄本子。电子档案跟着户口/门诊走,本子在你手里——账本跟着本子,数据自主。
- **联合疫苗/进口针名字对不上?** 词表归一常见名(五联/四联/13 价…);归不上的 exit 2 会把名字报出来,`--map "你写的=五联疫苗"` 教一句即可。
- **我们省的程序不一样?** `--schedule` 整表翻案(如 `je\t8,9,24,72`);守恒恒等式自动跟新表走。
- **为什么恰线不亮?** 宁少报不冤枉——超龄恰好满 3 个月的孩子,明天才欠;红灯的信用要留给真正的欠账,狼来了三次账本就没人信了。

## 7. 诚实条款(与 README 第七节同源)

程序表是国家免疫规划 2021 版的通识先验,省级增补与替代程序 `--schedule` 翻案,接种门诊永远赢;不做医疗建议,欠针红灯指向门诊咨询;二类不推荐只记账;「本子上没有」≠「没打过」;查验口径是通识简化,校医清单永远赢;孩子的健康档案是最敏感的数据之一,不连任何接口不上传任何字节;零墙钟,as-of 缺省锚定账本最大日期,同账任何机器任何一天逐字节一致。
