# 加量红线 · METHODOLOGY

> 本文回答四个问题：这套指标的数学从哪来、阈值凭什么、它被谁批评过、本工具如何把批评变成规则。所有公式都与 `redline.py` 的实现一一对应，并有测试钉死。

## 1. 核心命题：伤在斜率，不在高度

训练量与伤病的关系不是「多 = 伤」。流行病学与训练研究反复指向同一个模式：**伤病风险跟着负荷的突变走，而不是绝对量**。Gabbett（2016, *BJSM*）把这一点总结为 acute:chronic workload ratio（ACWR）框架：本周负荷（急性）相对四周基线（慢性）的比值落在 0.8–1.3 时风险最低（「甜区」），超过 1.5 时风险显著抬升。这个框架的力量在于它把「加量别太猛」从教练格言变成了可计算的读数：

```
急性负荷 A  = 最近 7 天负荷总和
慢性负荷 C  = 最近 28 天负荷总和 ÷ 4   （平均周负荷，与 A 同量纲）
ACWR       = A / C                    稳定态 = 1.0
```

量纲细节值得强调：慢性负荷必须除以 4（或等价地取四个周块的平均），否则稳定训练的比率永远是 0.25，「甜区」就失去意义。这是本工具与部分开源实现的分歧点，`tests/test_loads.py::test_steady_state_acwr_is_one` 与 `test_chronic_is_mean_weekly_not_raw_sum` 把口径钉死。

## 2. 负荷口径：session-RPE（Foster 2001）

```
单次负荷 = 时长(分钟) × RPE(1–10)
```

选它而不是公里或心率，三个理由：

1. **公里不带强度**：10 km 慢跑和 10 km 测试课对身体的账单完全不同，RPE 一笔计入。
2. **零设备**：不需要心率带/功率计，手表甚至纸笔日志都能产出三列输入（日期/分钟/RPE）。
3. **跨项目可比**：跑步、骑行、力量课可以进同一本账——这对交叉训练者尤其重要，只数公里会漏掉一半负荷。

RPE 是主观量。这不是缺陷而是设计前提：工具只用它与你**自己的历史**比（比率、周表、趋势），从不跨人比较。自洽的主观量表，好过失准的客观伪精度。

## 3. EWMA 变体（Williams et al. 2017）

滚动窗口有两个怪癖：第 29 天前的一天会突然掉出慢性窗口，基线跳变；窗口内每一天权重相同，8 天前的大课和昨天的轻松跑同权。EWMA 用指数加权修掉这两点：

```
EWMA_t = λ·load_t + (1−λ)·EWMA_{t−1}     初值 = 首日负荷
λ_急性 = 2/(7+1) = 0.25      λ_慢性 = 2/(28+1) ≈ 0.069
```

EWMA 对「最近几天急踩油门」更敏感。本工具**并列展示**滚动与 EWMA 两个读数，并在 EWMA 显著高于滚动（>0.15）时提示——两者分歧本身就是信息。测试：`tests/test_ewma.py`。

## 4. 单调性与应变（Foster 1998）

```
单调性 = 周内日负荷均值 ÷ 标准差       >2.0 为警戒
应变   = 周总负荷 × 单调性             只展示，不判区
```

单调性抓的是另一种死法：总量不大，但**每天一模一样**——没有硬 day、没有真 easy day，恢复差异被抹平。σ=0（含只有一天数据的周）时数学上单调性无穷大，工具如实报 `∞` 而不是假装给个数。应变刻意不做绝对阈值判定：它的量纲因人而异，跨人比较毫无意义，工具只让你看它随周的走势。测试：`tests/test_weekly.py`。

## 5. 争议，以及本工具的三条回应

ACWR 框架在 2019 年后遭到严肃批评（Impellizzeri et al., *BJSM/Sports Med* 2019–2020），要点有三。本工具的态度不是回避，而是把每条批评变成一条产品规则：

| 批评 | 内容 | 本工具的回应 |
|---|---|---|
| **早期不可靠** | 训练历史不足时，慢性基线是幻觉，比率会给出荒谬读数 | **校准门**：首练不足 21 天，ACWR 只展示、不判区（`tests/test_zones.py::TestCalibrationGate`） |
| **伤停悖论** | 停训后慢性衰减，任何复出的比率都数学性爆表——工具把恢复期全标红，逼人要么无视工具要么不敢练 | **归零重启 + 重建冻结**：慢性为 0 → 承认「这是重启问题」；空窗 ≥14 天记伤停，归队后 28 天判据冻结，只看绝对量（`tests/test_rebuild.py`） |
| **比率冗余** | 比率丢掉了绝对量信息，同样 ACWR 下 3000 与 300 负荷的人不是一回事 | 周表始终并列展示周负荷/日均/急性/慢性绝对值，比率只是其中一列，不是唯一结论 |

一句话：**ACWR 是护栏不是预言**。它对「这周是否在猛加」给出人群统计意义上的提示，不对「你会不会受伤」做个人断言。

## 6. 归队阶梯：为什么是 40/60/80/100%

伤停 ≥14 天后，慢性基线大幅流失，此时唯一可信的是绝对量。工具以伤停前最后一次训练日的慢性周负荷为锚（`build_report` 里的 `pre_chronic_weekly`），给出四周阶梯 40% → 60% → 80% → 100%：

- 首周 40%：低于甜区上限太多，这是故意的——复出第一周的对手是组织耐受度，不是 ACWR；
- 每周 +20 个百分点（约 +33% 相对增幅）：比经典的「每周 +10%」激进，但那是在**基线稳定**时的经验；复出期四周的合理目标是让新基线快速成形，同时绝对量仍在伤前水平之内；
- 第 4 周末恰逢 28 天冻结窗结束，比率判据恢复——此后 ACWR 重新接管话语权。

阶梯是默认建议，不是处方：疼痛、专项特点、医生意见永远优先。

## 7. 甜区余额的闭式解

`plan` 的余额回答「到期末还能再加多少负荷而不越甜区上界」。设第 28 天窗口原始和为 S₂₈、急性为 A，追加负荷 X 同时进入两者：

```
(A+X) / ((S₂₈+X)/4) ≤ 1.3
⟹  X = (1.3·S₂₈ − 4A) / (4 − 1.3)      负数取 0
```

代回验证比率恰为 1.3（`tests/test_plan.py::TestHeadroom`）。注意 X 在分子分母都出现——「加的量也垫高基线」这一点被精确计入，这是线性近似给不了的性质。

## 9. FAQ

**Q：会不会让我不敢练？**
甜区上界是 1.3，不是 1.0——工具明确允许你在基线之上多练三成。它拦的不是「练得多」，是「比你的基线猛得多」。退训区（<0.8）同样举牌：基线在流失，停训也是一种风险行为。

**Q：需要每天记录吗？**
不需要。缺勤日自动按 0 负荷处理，一年 300 天有记录和一年 60 天有记录都能算——只是基线的可信度随记录密度变化。伤停检测靠空窗本身，恰恰不需要你记录「没练」。

**Q：手表/app 的数据怎么进来？**
导出 CSV/TSV（几乎所有平台都支持），保留或改出 `date/minutes/rpe` 三列即可。RPE 通常要自己填：手表的「相对努力」或训练负荷分可以作为参考换算。列序随意、CSV 逗号分隔也认、`#` 注释行可用。

**Q：每天练两个不同的项目怎么办？**
同日多行自动相加（double 是常见的），activity 列随便写。负荷口径保证了跑步和力量课可以进同一本账。

**Q：为什么不用心率、配速、功率这些「客观」数据？**
它们都好，但都要设备、都要校准、都会坏。session-RPE 的三位输入永远不会坏：你练了多久、你觉得多累。想要更精细的负荷模型，本工具的 TSV 结构留了 `notes` 列，未来扩展不破坏旧日志。

**Q：红线周亮了就一定受伤吗？**
不一定。它是一面人群统计的护栏：红线周之后受伤的概率在统计上更高，但个体差异巨大。正确的用法是把红线周当成回看线索——如果 07/06 那周之后你确实伤了，它就是你的个人证据；如果没伤，你的组织耐受度比平均值好，仅此而已。

**Q：和其他训练 app（TrainingPeaks、Runalyze 等）的 CTL/ATL/TSB 是一回事吗？**
同族不同种。CTL/ATL 本质上就是慢性/急性负荷的指数平滑版（与本工具的 EWMA 变体接近），TSB = CTL − ATL 是绝对差而不是比率。本工具的增量在于：零依赖纯本地、比率与绝对量并列、以及把「校准门/归零重启/重建冻结」这三条诚实性规则做成结构性约束——多数 app 在这三个场景下照常给数。
