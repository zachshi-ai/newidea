# 加量红线 · Redline

> 伤病不住在跑量里，住在跑量的**斜率**里：用四周慢性负荷当刻度盘、本周急性负荷当指针，给身体装一个转速表——ACWR 就是读数，1.5 就是红线。
> A zero-dependency CLI that turns a training log into a tachometer: acute load over chronic baseline (ACWR), monotony, strain, injury-layoff rebuild ladders, and a plan simulator that tells you the redline *before* you leave the door.

---

## 一句话

每个业余跑者都经历过同一种循环：训练热情上来，周量翻倍，身体报账——胫骨、膝盖、足底——然后停训一两个月，归零，再来一遍。问题从来不在「跑得多」，而在「加得猛」：运动科学对此有个量化指标 **ACWR**（本周急性负荷 ÷ 四周慢性负荷基线），甜区 0.8–1.3，超过 1.5 就是红线区。但这套指标散落在论文和付费 app 里。`redline` 把它变成一个零依赖本地工具：吃一份「日期 / 分钟 / RPE」的 TSV 日志（session-RPE 法，不需要心率带），吐出**当前转速**、**逐周负荷表**（ACWR / EWMA / 单调性 / 应变）、**伤停检测与归队阶梯**，还能在你出门之前模拟「按这个计划下周转速多少」。三条诚实性规则贯穿始终：**基线没校准就不判区、慢性归零就承认重启、重建期就冻结比率判据**——宁可说「不知道」，不给危险的数字。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 业余耐力跑者（骑行/游泳/健身房同理）：手表里有记录、心里有目标、日历里没有余量的上班族训练者。 |
| **场景** | 报名比赛后热情加量；某周状态好就顺手翻倍；伤停一个月后急着找回状态；看着别人的课表焦虑自己的进度。 |
| **问题** | **受伤的驱动因素是负荷的变化率，不是绝对量**，但没有人给变化率装仪表：① 不知道自己**此刻的转速**——本周负荷相对四周身体基线是温和还是爆表，全凭感觉；② 不知道**计划的代价**——周末想加一堂长距离，出门前没有任何办法知道它会把 ACWR 顶到哪；③ 不知道**伤停后怎么回来**——基线已经流失，任何比率判据都会数学性爆表，于是要么不敢练、要么凭勇气练。 |
| **价值与意义** | 1) **玄学变仪表**：把「我感觉最近加猛了」换成三个可计算的数——ACWR、单调性、应变，并把红线（>1.5）摆在眼前。<br>2) **出门前模拟**：`plan` 子命令把未来会话并入日志，逐课给出预计转速和**甜区余额**（还能再加多少负荷而不越线，闭式解精确）。<br>3) **伤停后给阶梯而不是给比率**：检测 ≥14 天空窗，按伤前基线的 40/60/80/100% 给四周归队阶梯，判据冻结期内诚实地说「现在只有绝对量可信」。<br>4) **零依赖 + 纯本地**：Python 3.8 标准库，一个 TSV 就是全部数据库，不联网不上传。 |

## 核心思想：慢性基线 → 转速读数 → 红线

数据模型是一张人类可直接编辑的 TSV 表，一行一次训练。负荷口径是 **session-RPE**（Foster 2001）：`负荷 = 分钟 × RPE(1–10)`——公里不带强度信息，心率带要充电，而「这堂课多费劲」你自己就是最准的传感器。

| 概念 | 定义 | 直觉 |
|---|---|---|
| **急性负荷** | 最近 7 天负荷总和 | 这周踩了多少油门 |
| **慢性负荷** | 最近 28 天负荷总和 ÷ 4（平均周负荷） | 身体已经适应的基线刻度 |
| **ACWR** | 急性 ÷ 慢性 | 转速读数：稳定态 = 1.0 |
| **分区** | <0.8 退训 ｜ 0.8–1.3 甜区 ｜ 1.3–1.5 加速 ｜ >1.5 红线 | 甜区含上界，红线是严格大于 |
| **EWMA 变体** | 指数加权（λ=2/8 与 2/29）重算急性/慢性 | 比滚动均值更早嗅到最近几天的急踩油门 |
| **单调性** | 周内日负荷均值 ÷ 标准差（Foster 1998） | 每天>2.0 一模一样 = 恢复被吃掉 |
| **应变** | 周总量 × 单调性 | 只展示不判区：量纲因人而异 |
| **校准门** | 首练不足 21 天 → ACWR 只展示不判区 | 早期基线是幻觉，不假装它能判区 |
| **伤停与冻结** | 空窗 ≥14 天记伤停；归队后 28 天内判据冻结 | 伤停后比率必然爆表，冻结是对数学的诚实 |
| **归队阶梯** | 伤前周负荷 × 40/60/80/100% | 重建期不用比率，用绝对阶梯 |
| **甜区余额** | 末日再加 X 负荷恰达 ACWR=1.3 的闭式解 | X = (1.3·S₂₈ − 4A)/(4−1.3)，负数取 0 |

三条诚实性规则是产品的灵魂：**工具的责任边界和计算边界一致**。基线没成形（<21 天）就说「校准中」；停训后慢性归零就说「这是重启问题不是比率问题」；重建期就说「比率在数学上必然爆表，四周内只看绝对量」。ACWR 最被人诟病的三种误用，在这工具里全部被结构性挡住（详见 METHODOLOGY.md 的争议一节）。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 redline.py report examples/boombust.tsv   # 完整转速报告
```

## 命令速查

```bash
python3 redline.py report examples/boombust.tsv     # 报告：当前转速/周表/伤停/建议
python3 redline.py report examples/boombust.tsv --as-of 2026-07-03   # 站在过去某天回看
python3 redline.py plan examples/boombust.tsv --session "2026-09-05,120,7,长距离" \
                   --session "2026-09-06,60,6,配速跑"   # 出门前模拟
python3 redline.py validate examples/minimal.tsv    # 日志格式体检
python3 examples/build_examples.py                  # 重建示例数据（确定性）
python3 redline.py report log.tsv --strict          # 红线周时退出码 2（自动化闸门）
```

你自己的日志：五列 TSV（表头固定、列序随意，CSV 逗号分隔也认），`#` 开头是注释，同日多练自动相加——

```text
date	activity	minutes	rpe	notes
2026-09-01	轻松跑	45	4	小腿有点紧
2026-09-03	节奏跑	40	6	状态好
2026-09-05	长距离	90	5	最后 3 km 掉速
```

## 一个真实样例

`examples/boombust.tsv`：57 条合成但真实感的日志，埋入一条完整的 boom-bust 故事线——第 1–8 周稳定打底（+2%/周）、第 9 周报名比赛上头（+8%）、**第 10 周爆缸（周负荷翻倍到 2550）**、随后疼痛减量、伤停 15 天、归队爬坡。工具的报告：

```text
【周表】（ISO 周；单调性/应变按已过天数；ACWR 在周末结算）
周                     周负荷     日均     单调性       应变    ACWR  区
05/04–05/10      885    126     0.9      831   4.00?  …
05/25–05/31      940    134     0.9      882    1.03  🟢
06/29–07/05     1085    155     0.9     1019    1.07  🟢
07/06–07/12     2550    364     1.2     3150    1.81  🔴
07/13–07/19      575     82     0.8      487    0.44  🔵
08/10–08/16      480     69     0.9      412   2.84*  ⏳
  （? = 基线校准中不判区；* = 重建期判据冻结；🔵🟢🟡🔴 = 退训/甜区/加速/红线）

【旗帜】
  07/06–07/12  🔴 ACWR 1.81 超红线（>1.5）

【伤停与归队】
  检测到伤停：2026-07-21 之后空窗 15 天，2026-08-06 归队
  伤前慢性周负荷 ≈ 1277。伤停后基线已流失，比率判据（ACWR）会数学性爆表，
  所以重建期不用比率，用绝对阶梯（占伤前周负荷）：
    第 1 周  40% → 周负荷 ≈ 511
  判据恢复日：2026-09-02（归队 + 28 天，新基线成形）
```

埋进去的爆缸周被精确挖出（ACWR 1.81 红旗）、前八周打底全绿、疼痛周跌进退训区、伤停被按日期检出、重建周全部判据冻结——**工具还原了事故链，而不是在事后感慨**。验收测试把这个「已知答案」钉死成了断言。

出门前的模拟同样直接。重建结束后想加个周末长距离+配速跑，先问转速：

```text
日期           项目             分钟  RPE       急性       慢性    ACWR  判定
2026-09-05   长距离           120  7.0      945      794    1.19  🟢
2026-09-06   配速跑            60  6.0     1200      884    1.36  🟡

🟡 计划落在加速区但没有踩线：只保留一个刺激课，其余照常。
余额：0。这份计划已经把甜区用满了，一点都别再加。
```

## 验收标准

每条标准都有对应的自动化测试（`python3 -m unittest discover -s redline/tests`，共 108 例）：

| # | 标准 | 测试 |
|---|---|---|
| A1 | 日志解析：表头校验、列序随意、TSV/CSV 双吃、注释/空行跳过、坏行汇总一次报全（真实文件行号）、RPE 0–10 与负分钟拒绝、同日多练相加 | `tests/test_parsing.py` |
| A2 | 负荷口径：load = 分钟 × RPE 精确；按日聚合支持 double | `tests/test_parsing.py` `tests/test_loads.py` |
| A3 | ACWR 数学：慢性 = 28 天和 ÷ 4（稳定态比率恰为 1.0）；7 天含端窗口；窗外慢性归零返回 None 不抛异常 | `tests/test_loads.py` |
| A4 | 分区边界：<0.8 退训、0.8–1.3 甜区（含上界）、1.3–1.5 加速、>1.5 红线（严格大于），边界值逐一钉死 | `tests/test_zones.py` |
| A5 | 校准门与归零保护：首练 <21 天拒绝判区（含爆表负荷不许亮红）、`--as-of` 回看一致；慢性归零区域为灰不崩溃 | `tests/test_zones.py` |
| A6 | EWMA 变体：λ 常量、手工级数逐项精确、衰减慢于急性、不被单日脉冲牵着走 | `tests/test_ewma.py` |
| A7 | 单调性/应变：均值/标准差公式精确、σ=0 → ∞ 诚实报告、全零周 → 0；应变只展示不判区；部分周按已过天数 | `tests/test_weekly.py` |
| A8 | 伤停与归队：空窗 13/14 天的检测边界、阶梯 40/60/80/100% 锚定**伤前**基线、冻结窗只覆盖归队后 28 天（含「不许冻结历史周」回归测试） | `tests/test_rebuild.py` |
| A9 | 计划模拟：红/绿计划判定、未校准与冻结日标记、甜区余额闭式解精确（代回验证 ACWR=1.3、越线时余额=0） | `tests/test_plan.py` |
| A10 | dogfood：示例日志埋入的爆缸周必须被唯一标红（日期精确）、打底周全绿、伤停按日期检出、阶梯与冻结完整；示例文件与生成器逐字节同步 | `tests/test_dogfood.py` |
| A11 | CLI：report/plan/validate 退出码语义（含 `--strict` 红线 → 2）、`--json` 结构、坏文件路径与坏会话格式报错、多会话按日期排序 | `tests/test_cli.py` |
| A12 | 确定性：同一输入两次运行输出逐字节一致 | `tests/test_cli.py` |

## 边界与诚实声明

ACWR 是**人群统计的护栏，不是个人伤病的预言**。运动科学界对它有严肃批评（比率信息冗余、早期不可靠、伤停悖论），本工具把这些批评直接做成了产品规则（校准门、归零重启、重建冻结）而不是回避。RPE 是主观量，你的 6 和别人的 6 不是同一个 6——但工具只用它和你自己的历史比，自洽即可。这里没有任何医疗建议：红线周亮了，该看医生看医生。完整的公式推导、文献出处（Gabbett 2016、Foster 1998/2001、Williams 2017、Impellizzeri 2019–2020 的批评）与 FAQ 见 [METHODOLOGY.md](METHODOLOGY.md)。
