# 冷暖自知 · Own Thermometer — 方法论与 FAQ

## 1. 为什么「主观体感」可以当数据

本件最大的方法论冒险是把 feel（−2..+2 的主报告）当一等公民。辩护有三：

1. **决策等价性**：你早上做穿衣决策时用的信息就两样——预报温度 + 你对自己体感的记忆。账本记录的（预报 + 穿着 + 体感）恰好是决策的完整输入与输出；用同样的口径记账，得出的规律直接作用于下一个决策。气象站实测反而引入口径错位——你按预报穿的，就该用预报对账。
2. **单受试者设计**：不需要你和别人比，只需要你和昨天的自己比。体感量表的绝对值没有意义（你的 −1 和别人的 −1 不可通约），但**同一个人的相对秩序是稳定的**：你连续三天的 −1/−1/0 排序，比任何绝对刻度都有信息。本件全部统计（win、失误率、连败）都只用序数结构，不用「温差多少算冷」的基数假设。
3. **信号当天闭环**：情绪、疲劳这类主观量的问题是漂移和长程性（阴晴表要专门处理气候漂移）；体感信号出门半小时就兑现，当天记录当天验证，几乎没有记忆重构问题——它是最容易记账的主观数据，却从没人记。

## 2. 为什么不给「你比平均人冷几度」

最早的版本有一个「个人偏差 = 舒适带中点 − 通用锚（20°C）」的读数，被自己毙了：**把全体 feel=0 的日子的温度做 P10–P90，冬天的 2 度和春天的 23 度都算「刚好」，中点是伪刻度**（示例账本会算出「舒适带 [2.0, 23.5]，偏差 −7.2 度」这种没人能用的结论）。「舒适带」这个词预设了单峰分布，而真实的体感地形是**多峰的**（深冬稳态峰 + 春秋乱流带）。

诚实的替代是**温度地形**：不压缩成一个数，把失误率按 3°C 桶摊开——舒适段（连续 ≤20%）、雷区（连续 ≥50%）让读者自己看见形状。给结论留台阶（一个「偏差系数」）很诱人，但伪精度比没有精度更糟。

## 3. 穿过 ≠ 穿对：断档为什么不做插值

第一版断档用「单品成功记录的 P10–P90」当覆盖区间，被示例账本当场证伪：长袖T 三次成功（18.0 / 23.0 / 23.5°C）插值出 [19.0, 23.4] 的「成功温区」，把 19–23 度整段盖住，断档消失——而事实是 19–23 度之间它一次都没穿对过。**三个点撑不出一条线**，插值温区是幻觉。

最终方案是**桶级实测覆盖**：1.5°C 一档，某档被覆盖当且仅当存在一件 qualified 单品（出现 ≥3 次且穿对 ≥2 次）在该档内**真实穿对 ≥2 次**。不做任何外推——18 度穿对过两次只证明 18 度有答案，不证明 20 度有。代价是断档边界对档位敏感（这是披露的参数，`--gap-line` 可调），收益是每一个被点名的断档都有实打实的失败记录背书。

## 4. 统计选择的理由

| 选择 | 理由 |
|---|---|
| 3°C 桶（地形）/ 1.5°C 档（断档） | 地形要看趋势，桶太细全是噪声；断档要定位，档太粗边缘一次成功就点亮整段（示例里风衣在 18.0 的两次成功不该豁免 20 度的真空）。两个刻度各司其职，都是参数。 |
| P10–P90（温区/舒适带） | 手编账本必有记录错误与极端天，P10–P90 对两端各 10% 的脏数据免疫；线性插值分位数与教科书定义一致，测试用手算值钉死。 |
| win = feel=0 占比 | 序数标尺下最诚实的「成功率」：不假设 −1 和 +1 等价（它们对决策不对称），只数「没出错」。 |
| 近邻带 ±1.5°C | 一件中间层的体感差大约 3–5°C，±1.5 意味着「差一件以内的天气历史」才有资格投票。窗口是参数（--window）。 |
| 连败线 = 桶内末尾连续 3 次同向 | 3 次独立同向失误在 20% 基线失误率下的概率约 0.8%——罕见到值得报警；「末尾」语义是「现在正在进行」，历史连败（已中断）不追诉。 |
| 骤变阈值 \|Δt\|≥3°C | 与近邻带同一量纲（一件衣服的体感差）；Δt 取相邻**记录日**（不是自然日）——账本里没有的日子等于你没出门，不存在插补。 |

## 5. 恒等式清单（validate V1–V6）

1. **V1 行级**：日期可解析且 ≤ --today、tmin ≤ tmax、cond 合法、outfit 非空、feel ∈ [−2, +2]。
2. **V2 日期唯一**：一天只有一个早晨。
3. **V3 桶和**：Σ(各 feel 档计数) = 记录数。
4. **V4 方向**：冷失误 + 热失误 = 失误总数。
5. **V5 覆盖**：Σ(每行单品数) ≥ 记录数（每行至少一件）。
6. **V6 包含**：舒适带（feel=0 的 P10–P90）⊆ 出现温度范围。

另有一条**解剖恒等式**贯穿 autopsy：有解 + 无解 + 不可判 ≡ 失误总数——三种裁决瓜分全部失误，一天不多一天不少。

## 6. FAQ

**Q：多少天能见效？**
20 天出第一份总账（exit 3 门槛），60 天（约一个换季）地形开始有形状，一个完整秋冬春（~110 天）能长出示例账本那样的全部结构：雷区、孤儿、断档、连败。低于门槛一律拒答——宁可沉默。

**Q：换季/换城市怎么办？**
换季不用动——账本跨季记，雷区会自己搬家。换城市建议开新账本：体感是「你 × 城市」的联合分布，搬走之后旧账还在但不再投票（近邻带是温度的，不是地理的——如果两地气候相近，旧账继续用是你的判断，工具不拦）。

**Q：为什么 outfit 是自由文本而不是结构化衣橱？**
因为记账摩擦是这类账本的生死线。结构化衣橱（每件衣服登记厚度/材质/颜色）三周就弃坑；「卫衣+风衣」四个键的自由文本可以坚持一年。代价是「卫衣+风衣」和「风衣+卫衣」算两个组合——如实接受：名字是你的约定，账本不猜。

**Q：同一个组合在不同城市/年份还准吗？**
win 是序数统计，时间越近权重越高才对——但本件刻意不做时间加权（v1）：样本本来就薄，再加权只剩噪声。诚实条款：它回答「按你的全史，这个温度什么最稳」，不做「最近你变了」的推断；近 30 天对照（report §5）是你自己看趋势的窗口。

**Q：连败线为什么只看「末尾」？**
报警的价值在「正在发生」。历史连败（中间被好日子打断）已经完成它的历史使命——那次报警如果有效，账本里会自然出现中断。追诉历史连败只会制造狼来了。

**Q：WASTELAND（账本荒地）和断档什么关系？**
同一块洞的两张照片：断档从**衣柜**看（这个温度带没有单品穿对过 ≥2 次），WASTELAND 从**决策**看（明天就是这个温度，近邻 7 天 0 次刚好）。断档是长期结构诊断（garments，一年看几次），WASTELAND 是临出门警报（plan，明早就用）。示例账本里两者都落在 20 度附近——雷区、断档、荒地在同一块地方会师，这就是「衣柜有洞」的完整证据链。

**Q：它会推荐我买什么衣服吗？**
永远不会。「断档 [20,22)」说的是「你的衣柜在这个温度带没有答案」，补一件薄夹克、或者把现有的两件重新学会搭配、或者继续硬扛——工具不shop。它反对的不是你现在的衣柜，是**你看不见的衣柜结构**。

**Q：要不要接天气 API 自动记账？**
不做。预报抄一行是 10 秒的事，换来的是：口径永远是你出门前看到的那一眼（API 的历史实况是另一本账）；账本留在你手里，这工具没有服务器、没有账号、没有上传。零依赖不是技术洁癖，是让账本活过三个月的唯一方式。

## 7. 一句话方法论
