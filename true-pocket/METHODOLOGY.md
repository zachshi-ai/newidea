# METHODOLOGY · 实掏 True Pocket

## 一、为什么「医保报了」是一句需要被审计的话

中国的基本医保覆盖 13.6 亿人，每年产生数十亿次结算。每一次结算都打印一张单据，单据上是五个数：总费用、统筹支付、个人账户支付、现金支付、自费（外加一个衍生数：自付 = 目录内个人分担）。这五个数的**加总结构**从来没有人向普通家庭解释过——不是因为难，而是因为没人需要你懂：

- 你懂了「个账支付是你自己的钱」，就会发现自己实际的医疗负担比「医保报了 90%」的体感高得多；
- 你懂了「自付 ≠ 自费」，商业保险理赔时就不会抄错位；
- 你懂了「年度自付累计」，就能拿回个税大病医疗专项附加扣除——一项 2019 年就写入个税法、全国统一、限额 80,000 元/年的**合法退税**，也是全中国放弃率最高的税优之一。

本件不发明任何政策，它只做三件事：**抄单、加总、对口径**。

## 二、核心概念词典（结算单的解剖学）

一张标准结算单上的钱，可以这样完整地切开：

```
总费用 (total)
├── 统筹支付 (pool)          ← 医保基金出的（目录内 × 报销比例）
└── 个人负担 = 个账 (acct) + 现金 (cash)
    ├── 自付 (own)           ← 目录内费用的个人分担（起付线以下 + 共付段自付比例 + 封顶线以上）
    └── 自费 (cat_out)       ← 目录外全额（进口耗材、丙类项目、种植牙……）
```

两条恒等式是单据自身的骨架，也是本件的账本体检：

1. **三支付恒等**：`total = pool + acct + cash`
2. **分担交叉**：`own + cat_out = acct + cash`——注意这条与「个账付的是目录内还是目录外」无关：个账可以刷目录外项目（多数统筹区允许），但这不影响恒等成立，因为两边都只是「从你这里拿走的钱」的两种分类法（按支付通道分 vs 按目录归属分）。

**真口袋**（True Pocket）= 个账 + 现金。立场：个账的钱是你工资里逐月扣缴的（个人缴费 2% 全部划入），它只是先被圈存在卡里——「不是现金」不等于「不是你的钱」。同时披露**严格口径**（纯现金）供两种世界观并存。

## 三、三个判级/凭证的口径

### 3.1 门诊起付线进度条（progress）

- **只累计门诊**。门诊统筹的起付线按参保人年度门诊（目录内）费用累计，住院另有起付线（通常更高、规则另算）——把两者混进一个进度条是错的，所以 progress 默认 `--category 门诊`。
- **按成员各爬各的线**：起付线是「参保人」属性不是「家庭」属性，爸爸过线救不了妈妈的门诊。
- **目录外自费不推进度条**：种植牙的 8,600 在进度条面前不存在。`--basis incatalog`（默认，= total − 自费）/ `--basis own` / `--basis total` 三口径可切——`total` 口径会高估进度，是教学性反例。
- 跨线的那一笔做**线前/线后切分**（线前 = 线 − 到上笔为止的累计），`--rate-after` 给了则对照「线后部分 × 比例」——样例账本 4/14 那笔：240.00 线前全自付 + 383.40 × 60% = 230.04 统筹，与单据上的 pool 分毫不差。

### 3.2 个税大病医疗抵扣凭证（deduce）

政策口径（全国统一，`--deduct-line`/`--deduct-cap` 可调）：**医保目录内自付**累计，超过 15,000 元的部分，在 80,000 元限额内据实扣除，可由本人或配偶申报。

三个易错点全部内建：

- **基数是「自付」不是「自费」**——目录外的 12,600 不进抵扣基数（全民最大误解）；
- **恰 15,000 不抵**，15,000.01 抵 0.01（边界钉在测试里）；
- **未拆列的行按「个账+现金」全额计入并标注 ASSUMED**——给上界不给断言：多数门诊单据没有目录外项，上界通常就是真值；但有进口耗材的住院单，抄齐两列后真实可抵会更低。

### 3.3 灾难性卫生支出（report）

WHO 通识口径：家庭自付卫生支出超过家庭支付能力（可用收入的 40%）即为**灾难性卫生支出**（catastrophic health expenditure）——这不是「很贵」的修辞，是卫生经济学里有定义的判据。实现：`实掏 ÷ --income > --cat-line(默认 0.40)` → exit 4。

门禁纪律与全仓库一致：**宁可少亮一盏灯**（恰 40% 不亮）；`--income` 不给不判（不发明钱）；账太薄（<3 笔或跨度 <30 天）统计判级 DECLINE 但算术照出——「今年到底掏了多少」是深夜也该得到回答的问题，不该被样本量拦住。

## 四、为什么手编 TSV 而不是自动抓取

医保平台的数据接口不对个人开放，而结算单/费用清单/医保 App 账单**本来就在你手里**——抄一行 30 秒，一年一个家庭通常 5–30 行。手编不是妥协：

1. **数字是你亲眼从单据上抄的**，账本的权威性来自单据本身，不来自任何第三方接口的正确性；
2. **两条恒等式当场验钞**——抄错任何一格（三支付对不上、自付+自费对不上），validate/加载层立刻 exit 2，你抄的单据自己会证明你抄错了；
3. **零接口 = 零泄漏**：家人生病是敏感信息，本件不连任何服务、不上传任何字节、报告只打印账本 basename。

## 五、FAQ

**Q：起付线/报销比例各地不一样，默认值不对怎么办？**
A：全部参数化。`progress --threshold/--basis/--rate-after`、`deduce --deduct-line/--deduct-cap`、`report --cat-line`。本件的原则（全仓库一致）：**过期规则比没有规则危险**，所以默认值只给全国统一的那两个数（15,000/80,000），其余不给就明说「不发明政策」。

**Q：我只有门诊单，没有住院单，能用吗？**
A：能。住院列只是 category 的一种；report/family/deduce 不分类型，progress 默认只看门诊。

**Q：商业保险理赔到底要单据上的哪个数？**
A：百万医疗险通常赔「医保目录内自付」段（自付），不赔目录外自费（部分中高端险除外）——`claim` 把这个数从你抄的账里拆出来并标来源（声明/反解/ASSUMED）。条款以保单为准，本件只拆数。

**Q：共济账户怎么记？**
A：家庭共济后「卡是谁的钱、账是谁的病」是两本账。本件按**结算行上的成员**记账（谁的病算谁的实掏），个账消耗单列一榜（谁的卡在被刷）。共济划扣的精确流水以医保平台为准，本件不建模。

**Q：退款/拒付怎么记？**
A：不建模（负数 exit 2）。结算单是单向的最终事实，冲销以新结算行为准。

**Q：和商业保险的保额缺口审计是什么关系？**
A：safety-floor 回答「出事那天接得住吗」（事前），本件回答「这次接住了多少」（事后）。理赔时 claim 拆出的「目录内自付」正是 safety-floor 世界里保险公司要接的那一段。

## 六、方法论边界

- 不做医疗建议，不评论治疗方案，红灯指向的是钱不是病；
- 不预测「明年会花多少」——医疗支出是事件驱动不是节奏驱动，外推在本件没有意义（这是与 leave-debt/pace-gap 等**节奏账**的本质区别：本件是**事件账**，只加总不外推）；
- 不评估「该买什么保险」——那是 safety-floor 的账；
- 不挑战医保政策，政策永远赢，参数永远可调。
