# 实掏 · True Pocket

> 医保结算单印了五个数，从没有一行加总告诉你：这一年看病，**真正从你口袋里出去的钱**是多少。

| | |
|---|---|

| **场景** | 结算单上「统筹支付 / 个人账户支付 / 现金支付 / 自费 / 自付」五个数没人加得清；个税 App 的「大病医疗」栏不知道填什么；商业百万医疗险理赔要拆「目录内自付」拆错位被拒赔 |
| **问题** | 你的钱分两批被掏走——一批当场掏（现金），一批从你自己攒的卡里掏（个账，那是你工资里逐月扣来的钱，只是先被圈存进了卡）——而单据从不加总；「自付」（目录内报销后的个人分担）与「自费」（目录外全额）是两个不同的词，全民混淆第一名词；年度自付累计（个税抵扣的依据、门诊起付线的进度、灾难性支出判级的分母）没有任何账本在记。「医保报了」是一句让所有家庭停止追问的话 |

## 问题定义

医院收费窗口递来的那张单据，是这个国家印量最大的财务文件之一，也是被读懂得最少的一张。它把一场病的钱印成五个互不加总的词：

- **统筹支付**——医保基金出的，这部分大家看得懂；
- **个人账户支付**——从你的医保卡里扣的。**这是你自己的钱**：你工资里逐月扣的那 2%，先被圈存进这张卡。但它印在单据上的样子，读起来就像「医保付了」；
- **现金支付**——当场掏的；
- **自付 / 自费**——两个不同的概念：**自付**是目录内费用报销后的个人分担部分，**自费**是目录外项目（进口耗材、种植牙、部分检查）的全额。全民混淆第一名词，商业保险理赔时把「自费 3,000」抄进「自付」栏，是拒赔纠纷的经典开场。

于是每个家庭年底都答不上三个本该脱口而出的问题：**今年看病到底自己掏了多少？个税大病抵扣那一栏该填多少？商业险理赔要的「目录内自付」是多少？**「医保报了」是一句让所有人停止追问的话——它既是真的，又掩盖了全部。

## 设计

一本可手编 TSV（`settlements.tsv`，一行一张结算单，数字全部照抄单据）：

```
date	hospital	member	category	total	pool	acct	cash	own	cat_out	note
2026-02-14	市一院	妈妈	住院	18432.60	11208.40	0	7224.20	4224.20	3000.00	胆囊切除·耗材3000目录外
```

两条恒等式是账本的骨架（validate 逐行钉死，破裂 exit 2 拒载）：

1. **三支付恒等**：`total = pool + acct + cash`（费用侧：统筹付的 + 你付的 = 总费用）
2. **分担交叉**：`own + cat_out = acct + cash`（分担侧：目录内个人分担 + 目录外自费 = 从你这里拿走的全部——与「个账付的还是现金付的」无关，恒成立）

六个命令从同一本账长出来：

| 命令 | 回答的问题 | 关键口径 |
|---|---|---|
| `report` | 今年全家实掏多少？谁在花钱？ | **真口袋 = 现金 + 个账**（两口径并列：严格口径只算现金） |
| `progress` | 门诊起付线还差多少？跨线的是哪一笔？ | 按成员各爬各的线，**只累计门诊**（住院另有起付线）；种植牙那 8,600 自费推不动进度条一分一毫 |
| `deduce` | 个税大病抵扣能抵多少？ | 目录内自付累计 **> 15,000 的部分**（限额 80,000，全国统一政策）；未达线如实说差多少，绝不倒推 |
| `claim` | 商业险理赔要的「目录内自付」是多少？ | 已拆用声明、半拆用反解（pocket − 自费）、未拆给上界并显著标注 ASSUMED |
| `family` | 全家一本账怎么合？ | 全家实掏 = Σ成员实掏（恒等）；个账消耗逐成员点名 |
| `validate` | 账本可信吗？ | 两条恒等式逐行 + 反解一致性 + 未拆列披露 |

**灾难线判级**（report）：实掏 ÷ 年收入 > 40%（WHO 灾难性卫生支出通识红线，`--cat-line` 可调）→ exit 4。`--income` 不给不判——不发明你的收入。恰 40% 不亮：宁可少亮一盏灯。

## 与近邻的边界

- **shadow-base（暗基数）**：管公司替你缴的社保有没有缩水（**缴存端稽查**），本件管你看病时缴的钱怎么被分摊（**使用端记账**）——公积金有 redemption/shadow-base 两端并存的先例，社保医保同理。
- **medicine-rollcall（药箱点名）**：管家里药的第二口钟（开封效期，**库存**），本件管看病结账的五个数（**消费**）。
- **borderline（贴线）**：管化验指标的纵向爬坡（**健康**），本件管费用的纵向加总（**钱包**）。
- **safety-floor（兜底）**：管商业保险保额够不够（**出事前**的风险转移），本件管医保结算单怎么读（**出事后**的实际分摊）——claim 命令恰好是两件之间的桥：safety-floor 问「接得住吗」，本件答「这次接住了多少」。
- **stealth-interest（暗息）**：同是「单据上的数字 vs 真实数字」母题，那边是营销费率 vs 真实利率（**融资端**），本件是结算单五数 vs 真口袋（**分摊端**）。

## 快速开始

```bash
python3 true_pocket.py examples/settlements.tsv report --income 120000
python3 true_pocket.py examples/settlements.tsv progress --threshold 1800 --rate-after 0.6
python3 true_pocket.py examples/settlements.tsv deduce
python3 true_pocket.py examples/settlements.tsv claim --date 2026-02-14
python3 true_pocket.py examples/settlements.tsv family
python3 true_pocket.py examples/settlements.tsv validate

# 验收
python3 -m unittest discover -s tests
```

## 验收标准（全部转成自动化测试）

1. 三支付恒等逐行校验，破裂（差 > 0.01）exit 2；恰 0.01 容差内放行
2. 分担交叉恒等（两列齐拆时）：own + cat_out = acct + cash，破裂 exit 2
3. 真口袋恒等：全家实掏 = Σ成员实掏，残差 0
4. 自费永不分婚配：种植牙 8,600 全目录外，起付线进度纹丝不动、抵扣基数纹丝不动（测试钉死）
5. 抵扣边界：15,000.00 恰线不抵（超线 0）、15,000.01 抵 0.01、封顶 80,000
6. 灾难线边界：恰 40% 不亮、40%+ε 亮 exit 4；`--income` 缺省不判级
7. 起付线跨线笔切分：线前 240.00 / 线后 383.40，`--rate-after 0.6` 对照 230.04；成员各爬各的线
8. 薄账分层：<3 笔或跨度 <30 天 → 灾难线判级 DECLINE exit 3，算术照出；年度无行 exit 3
9. as-of 时间剪切：`--as-of 2026-06-30` 后 7 笔 / Σtotal 29,544.00 / 抵扣基数 6,505.56；缺省 as-of = 账本最大日期；同一本账逐字节可复现
10. 中英别名归一：OP ≡ OUTPATIENT ≡ 门诊，IP ≡ INPATIENT ≡ 住院；未知类型 exit 2
11. 报告只打印 basename，绝不回显调用方路径；负数/缺列/坏行 exit 2

## 诚实条款

- 账本只记结算单上印的事实，它不读医保平台、不猜报销规则——**政策永远赢**：起付线、报销比例、抵扣线全部 `--` 参数可调，默认值只是通识口径，不是事实断言。
- 未拆目录外的行按「全目录内」估算进度与抵扣并显著披露 ASSUMED——**给的是上界，不是断言**；抄齐两列，账本更锋利。
- `claim` 只拆数，不构成理赔承诺；`report` 的灾难线是通识红线不是医学判断；本件是计算器不是医保局。
- as-of 缺省 = 账本最大日期，`--as-of` 钉回过去即时间剪切；同一本账任何机器任何一天逐字节一致；报告只打印 basename；本地计算不连任何接口。
- 看不看病、填不填报销、报不报保险，永远是人的决定——账本只拒绝让「医保报了」继续充当句号。
