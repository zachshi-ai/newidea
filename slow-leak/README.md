# 暗漏 · Slow Leak

> 账单不会说谎，但它会含糊——漏电、漏水、漏气，全是慢漏。
> Bills don't lie, they mumble. A zero-dependency detective that reads your monthly meter ledger and tells you which meter started bleeding, when, and what it costs if you keep looking away.

---

## 一句话

电/水/燃气以月为单位聚合到家门口，而直觉对「物理用量」没有任何审计能力：冬天的电费高是采暖还是坏冰箱？夏天水费低是节水还是全家出差？逐月 3% 的蠕升肉眼彻底无感——一台老化冰箱的启动器、一个没关严的马桶水箱、一组 24 小时通电的插排，每个月只多偷 5%，等年底打开总账才发现翻了倍，**冤枉钱已经交了十二个月**。现有的账单 App 只会画柱状图，从不回答唯一要紧的问题：**哪张表、从哪期开始、超出了什么基线、放任一年要多少**。`slow-leak` 的立场：**账单管理的最小可行单元不是「这个月交了多少」，是「最新一期相对它自己的历史，有没有越界」**。工具从一本可手编的月度账本（TSV：月份/表/用量，只记物理量不记金额——金额被价格变动污染，用量才是房子的心跳）确定性算出：**同比突变 SPIKE**（超去年同期 +25%，季节是共变、去年同期才是对照，所以冬采暖夏空调天然免疫）、**连涨蠕升 LEAK**（近 4 期三连涨且同比超 20%——突变是事故一次坏了，连涨是泄漏有东西在偷跑）、**待机底座 floor**（历史最低月≈你家拔不掉的那部分消耗）、以及**年化代价**（放任一年多烧 2280 度，比「贵了」两个字有用一万倍）。`detect` 连修好的历史事件都记得：去年 6 月那根 +127% 的水费突变虽然早已修复，但它留在账本里，成为下次诊断的对照。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 交家庭账单的房主与租客；管几套房子收租的房东；对「感觉又贵了」不服气、想拿证据找物业/水务/电力公司对账的人。 |
| **场景** | 收到账单那一刻（「怎么又比上月多 80？」）；季节交替时（「冬天的电是采暖还是坏了？」）；房子里添了大件之后（「新空调到底吃多少？」）；出租屋对账时（「租客说没多用，水表为什么翻倍？」）。 |
| **问题** | ① **月度聚合抹平线索**：坏掉的设备不是按月爆的，它只让数字每个月多爬一点，聚合后再叠加季节波动，肉眼没有任何分辨力；② **没有基线**：「正常月份该是多少」没人说得清，直觉拿上个月当对照，而上个月正是被季节性推高的那个；③ **慢泄漏没有体感**：漏电不响、马桶渗漏无声，唯一的信号在账本里，而没人回头看账本；④ **发现即滞后**：等账单「看起来不对」时，异常通常已经跑了 3-6 个月，此时拿不出「从哪期开始」的证据，对账、报修、退租结算全靠嘴。 |
| **价值与意义** | ① **同比对照天然免疫季节**：冬天电高、夏天水高都是气候，唯一的公平对照是「去年的这个月」——SPIKE 用它当锚，季节不再背锅也不再打掩护；② **双检测器分工明确**：SPIKE 抓突变（上个月还好好的）、LEAK 抓蠕升（四期三涨且同比超 20%），突变是事故、连涨是泄漏，两种病两种查法；③ **诚实条款**：不足 4 期标 THIN 不判灯、断月不判蠕升、无同期对照不判泄漏——宁可漏报不误报，狼来了三次账本就没人信了；④ **年化翻译**：+92.7% 没有体感，「放任一年多 2280 度」有；⑤ **底座视角**：历史最低月是你家消耗的地板，地板变厚意味着新常驻负载（新电器/新住户/坏东西），每季度看一眼就是体温计；⑥ 零依赖 + 纯本地 + `--today` 钉死逐字节可复现。 |

## 核心思想：把「交了多少」换成「相对历史有没有越界」

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **同比基线 yoy** | 去年同月与（若有）前年同月的中位数 | 「这个月对齐的还是歪的？」 |
| **突变 SPIKE** | 当期 > 同比基线 ×1.25 → SPIKE；< ×0.75 → DROP（漂移提示，不判灯） | 「有没有东西突然开始吃电？」 |
| **蠕升 LEAK** | 近 4 期 ≥3 次环比上涨，且最新 ≥1.2× 窗口首期，且 ≥1.2× 去年同期；断月不判 | 「有没有东西在慢慢偷？」 |
| **待机底座 floor** | 各表全史最低月及其占最新月的比例（下界估计，不是纯待机） | 「我家拔不掉的消耗有多厚？」 |
| **年化代价 annualized** | (当期 − 同比基线) × 12 | 「放任不管，一年多烧多少？」 |
| **样本纪律 THIN** | 表内不足 4 期不判任何灯 | 「这本账够不够格下诊断？」 |

三条诚实条款刻在实现里：**季节免疫是同比给的**——纯环比的蠕升检测在燃气账本上一年误报六次（夏 60 方到冬 260 方是采暖不是泄漏，样例账本实测 17 次误报），加上「同比 ≥1.2×」条件后误报归零，这是本件在开发中被自己的 detect 命令抓出来的 bug，也是这条规则写进验收标准的原因；**宁可漏报不误报**——无同期对照不判泄漏、断月不判蠕升、不足 4 期不判任何灯；**底座是下界不是待机**——最低月可能你不在家，工具只说「拔不掉的部分至少这么厚」。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

## 命令速查

```bash dd:ignore
python3 slow_leak.py check ledger.tsv --today 2026-09-04          # 最新账期三表体检（红 → exit 4）
python3 slow_leak.py trend ledger.tsv --utility electric          # 单表全史趋势
python3 slow_leak.py detect ledger.tsv                            # 全史异常扫描（修好的也记得）
python3 slow_leak.py floor ledger.tsv                             # 待机底座
python3 slow_leak.py validate ledger.tsv                          # 账本体检
python3 slow_leak.py utilities                                    # 三表说明与惯犯清单
```

账本是一份可手编的 TSV（Tab 分隔），只记物理用量：

```
2026-07	electric	280
2026-08	electric	395
2026-08	water	13
```

## 一个真实样例

王姐家 2024-01 至 2026-08 共 96 期账（电/水/气三表），见 [examples/ledger.tsv](examples/ledger.tsv)。2026-09-04 她做了一次体检：

```
暗漏体检 · 最新账期 2026-08（共 96 期账，3 张表）

  electric   8 月   395 度   去年同期 205 → +92.7%   ⚡ SPIKE  ✗ LEAK
  gas        8 月    70 方   去年同期 62.5 → +12.0%   · NORMAL
  water      8 月    13 吨   去年同期 12.5 → +4.0%   · NORMAL

判定  RED —— electric 在偷跑

  electric SPIKE：比去年同期多 190 度（+92.7%，容忍线 +25%），放任一年多 2280 度
  electric LEAK：2026-05→2026-08 四期 225 → 395（3 次环比上涨）——突变是事故（一次坏了），连涨是泄漏（有东西在偷跑）
```

（完整输出：[examples/sample-check-red.txt](examples/sample-check-red.txt)，exit 4）注意气表：冬天 300+ 方、夏天 70 方，摆动 5 倍却全绿——**季节不是罪，同比才是对照**。而电表 5 月起 225→230→280→395 四期三涨，6 月同比 +24.3% 时还在容忍线内（+25%），7 月 +43.6% 亮 SPIKE，8 月双灯齐亮——`trend` 让你看到蠕升的全过程（[examples/sample-trend-electric.txt](examples/sample-trend-electric.txt)）。

`detect` 全史扫描还记着去年修好的那次：water 2025-06 的 25 吨（同比 +127.3%，马桶漏水）至今仍在账（[examples/sample-detect.txt](examples/sample-detect.txt)）——它同时是下一次诊断的对照与「那次到底多贵」的存档。`floor` 给出底座（[examples/sample-floor.txt](examples/sample-floor.txt)）：电的地板 180 度（2024-06），占最新月 46%；气表的地板占了 86%——那是一个几乎不出门的家。

## 与哪些点子不混淆

- 与 **dusty-subs**（吃灰订阅）：订阅是固定费率，金额已知、问题是「值不值」；暗漏是计量消耗，金额未知、问题是「正常不正常」。一个管勾选的账，一个管跑表的账。
- 与 **repair-ledger**（续命账）：续命账管「修还是换」的退役决策，发生在设备坏**之后**；暗漏管「哪张表在偷跑」的发现，发生在设备坏**之中**——它是续命账的前置传感器。
- 与 **wilting-point**（凋萎点）：凋萎点管植物的浇水窗口（人配植物的节奏匹配）；暗漏管房子的三表异常（房子自己的心跳）。一个问「我适不适合养它」，一个问「它是不是在偷跑」。
- 与 **life-tag**（生命价签）：价签把消费换算成生命小时，消费是主动出手的钱；暗漏是没人同意就被扣走的钱——所以它只认物理用量，钱是事后的翻译。

## 验收标准（已全部转成自动化测试）

| # | 标准 | 测试 |
|---|---|---|
| A1 | 账本解析：坏行带行号 exit 2（月份/用量/列数/重复账期/未来账期/文件缺失） | `test_a1_*` |
| A2 | THIN：表内不足 4 期不判灯，不触发 exit 4 | `test_a18_thin_*`、`TestCommands` |
| A3 | SPIKE：同比 >25% 触发；恰 25% 不触发；基线 = 去年 + 前年同月中位（示例 205 = median(210, 200)） | `test_a3_*` |
| A4 | LEAK：三涨 + ≥1.2× 窗口首期 + ≥1.2× 去年同期；任一条件不满足不判；断月不判 | `test_a4_*` |
| A5 | 季节免疫：采暖爬坡（燃气 60→300 方）零误报；去年同期对照压制纯环比 | `test_a5_*`、`test_a19_*` |
