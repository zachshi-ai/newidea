# 讲台时刻 · 方法论

> 核心命题：**语速不是常数，所以字数不是时长。**
> 一切模型都在回答同一个问题：把「这份稿子念完要几分钟」变成可计算、可校准、可审计的估计。

---

## 1. 为什么「字数 ÷ 语速」必然失准

演讲计时最常用的土办法是字数除以平均语速。它错在两层：

**第一层：文本类型决定口播密度。** 同一个演讲者：

| 内容类型 | 实际发生的事 | 相对叙述的耗时 |
|---|---|---|
| 普通叙述 | 流畅念出 | 1.0× |
| 数字「2024 年」 | 逐位念「二-零-二-四」或换算「两千零二十四」 | 慢 30–100% |
| 代码 `git log --since` | 逐 token 拼 + 等听众抬头看屏幕 | 慢 60% 以上 + 演示停顿 |
| 列表 | 每项之间换气、给笔记时间 | 每项 +0.4s |
| 翻页 | 停顿、喝水、等笑声 | 每次 +1.5s |
| 客套 | 肌肉记忆，几乎不占认知 | 快于叙述（但占预算！） |

一篇技术分享里数字、代码、列表的密度可以是日常叙述的三倍——用统一的平均语速，等于用平地配速估算山地马拉松。

**第二层：语速个体差异 ±15% 起步。** 240 字/分钟是中文播音与自然演讲的中位，紧张的人 200，播过音的人 280。所以本工具的输出永远带区间（±15%），且提供校准——两个修正方向不该混在一起：**模型解决类型差异，校准解决个体差异**。

## 2. 口播单位：度量衡的定义

所有时长计算的第一步是把文本折算成「口播单位」——嘴巴实际要发的音节数量级：

| 文本元素 | 单位 | 依据 |
|---|---|---|
| 汉字 | 1 | 每字一音节（白话文罕见多音字连读损耗） |
| 数字串 | 每位 1 | 「2024」→「二零二四」四位；整念「两千零二十四」更长——逐位是**中位保守** |
| 英文词 | 1.8 | 240 字/分钟 ÷ 133 wpm ≈ 1.8，英文词均音节多于汉字 |
| 标点 | 0 | 停顿由结构模型统一计，避免双重计算 |
| 行内代码 / 代码块 | 不占单位，按 0.12s/字符 | 见 §3 |

默认语速 4.0 单位/秒（= 240 字/分钟）。中文讲稿的粗校验：4000 字 ≈ 16.7 分钟叙述 + 停顿。

## 3. 时间轴：两类时间必须分账

```
总时长 = 叙述时长 + 固定成本
         ↑随个人语速缩放   ↑物理性的慢，不随语速变
```

- **叙述时长** = 口播单位 ÷ 语速。校准时唯一被反推的部分。
- **固定成本** = 代码逐字符（0.12s/字符）+ 翻页 1.5s + 段落 0.6s + 列表项 0.4s + 引用 0.8s + 代码演示进场 2.0s。

分账的纪律性体现在校准上：假如把停顿混进叙述时间，一个爱停顿的演讲者会被反推出「语速极慢」，然后他的纯叙述部分被进一步高估——误差复利。实现里 `timeline` 与 `calibrate_ups` 共享同一个 `_segments` 归账器（测试 `test_roundtrip_recovers_rate` 锁定：任意语速校准后重放，总时长精确还原）。

**代码为什么 0.12s/字符？** 念代码不是逐音节，是逐 token + 解释：`--no-merges` 你会念「dash dash no merges」。0.12s/字符折算下来约等于等效英文散文的 1.6 倍耗时 + 每块 2s 演示停顿，与经验值（10 词命令念 8–12 秒）吻合。

## 4. 牺牲优先级：超时修复的伦理学

均匀压缩（每段删 10%）是坏策略：它把砍伤均匀撒在全篇，痛感最大化。超时修复应该**从牺牲成本最低的地方开始**：

| 优先级 | 类别 | 为什么先死 |
|---|---|---|
| P0 | 客套与元话语（感谢、废话不多说、接下来我将、as I mentioned） | 对内容零贡献，纯预算漏洞 |
| P1 | 冗长背景（历史沿革、in the past、传统上） | 听众默认已知，Q&A 可补 |
| P2 | 次要细节（举个例子、for instance、具体来说） | 论证支撑层，砍掉不伤主张 |
| 保护 | 核心内容（未命中以上任何规则） | 永不出现在建议里 |

四条工程纪律：

1. **累计到需求即停**：建议清单在 `累计节省 ≥ 超时 × 1.05` 处截断——5% 安全边际吸收临场反弹（现场总是比稿子慢一点）。
2. **覆盖不了就明说**：删光客套背景仍不够时输出 `covered=false`——这种超时不是删字问题，是结构问题（合并章节/砍整个论点），工具不假装清单能救。
3. **噪音过滤**：省 5 秒以下的块不进清单。建议必须值得读。
4. **保护是硬规则不是权重**：核心块的 priority 是「不参与排序」，不是「排序靠后」——不存在一个足够大的超时会让工具建议删你的结论。

## 5. 主张句位置：倒金字塔审计

听众注意力在开场几分钟达到峰值，随后单调衰减。核心主张（thesis）出现的位置因此是个可审计的指标：

| 位置 | 判定 |
|---|---|
| ≤ 25% | 🟢 前置到位（倒金字塔） |
| 25–50% | 🟡 尚可，还能更前 |
| > 50% | 🔴 太晚——「埋伏笔」失败模式 |
| 未检出 | ⚪ 明说未检出，不硬猜 |

检测是**信号词启发式**（我认为 / 我主张 / 关键在于 / I argue / the key idea…），取第一处强命中。它的诚实条款：宁可漏报也不误报——检出的句子一定是作者亲口宣告的主张，位置百分比只是把「你把结论藏在了第 64%」从直觉变成数字。

「未检出」本身就是有价值的诊断：说明稿子里没有一句敢负责任的主张——这比位置太晚更该修。

## 6. 校准：一次真实计时，终身受益

```
真实时长 → 反推语速 = 叙述单位总数 ÷ (真实秒数 − 固定成本)
        → 写入 ~/.stage-time.json
        → estimate / cuts / thesis 自动复用
```

推荐流程：第一次演讲用默认语速 + ±15% 区间；讲完记下真实时长，`calibrate --actual`；之后所有估算收窄到你的真实曲线上。两次校准后区间基本可以当点估计用。

注意事项：

- **校准用的必须是「讲完同一份稿子」的时长**，不含 Q&A（否则反推出的是「演讲+答疑混合语速」）。
- **换语种要重新校准**：中文 240 字/分 ≠ 英文 240 wpm 等效，双语演讲建议分开校准两份档案（`--profile`）。
- **风格变了重新校准**：从读稿改为脱稿即兴，停顿结构会变。

## 7. FAQ

**Q: 有它还需要彩排吗？**
A: 需要，但它替代的是彩排中「计时」的那一次。省下的彩排次数可以用来练内容与衔接。它也不与彩排冲突：彩排完的真实时长正好喂给 `calibrate`。

**Q: 我讲稿里有演示视频/现场 demo，怎么算？**
A: 工具不知道你视频多长——把它写进稿子（一个代码块或明确段落注明时长），或直接在预算上减掉。未建模的时间要显式留给它。

**Q: 数字逐位念会不会高估？**
A: 「2024」可能被念成「twenty twenty-four」（英文 6 音节）或「二零二四」（4 单位）。逐位是中位保守估计；系统性偏差（你习惯整念大数）会被校准吸收。

**Q: 语速区间 ±15% 会不会太宽？15 分钟的稿子差出 4 分钟？**
A: 未校准时就该这么宽——这是对个体差异的诚实。校准后区间名义上不变，但中心移到你的真实曲线，实用精度远高于字数÷语速的土办法。

**Q: 压缩清单会建议删掉我的幽默/故事吗？**
A: 不会主动——故事和幽默通常不命中 P0–P2 规则，属于受保护的核心内容。但若你的幽默写在「举个例子」段里，它会被归类为 P2：判断权在你，工具只给优先级和秒数。

**Q: 为什么不支持 PowerPoint (.pptx) 直接读？**
A: 零依赖原则。markdown 讲稿是纯文本、可 diff、可版本控制，导出 pptx 的备注区即可双用。解析二进制格式会把「零依赖」变成「依赖 python-pptx」。

**Q: 它和 Word 的字数统计 + 网上语速表有什么本质区别？**
A: 三点：类型感知（同一份稿子里数字/代码/列表按不同速率计）、结构停顿（翻页与换气是真实时间）、可校准（你的语速是可测参数不是查表常数）。字数统计回答「多少字」，本工具回答「多少分钟」。

**Q: 英文讲稿支持吗？**
A: 支持，英文词 1.8 单位/词折算；中英混排各自计。但英文语速研究建议单独 `--profile` 校准。

## 8. 局限

- **停顿参数是人群经验值**，不是你的实测值；校准只反推语速，不反推停顿（停顿样本太少，逐项反推会过拟合）。
- **信号词检测不了「隐式主张」**——通篇讲故事、主张藏在结尾的稿子会报「未检出」。这是提醒不是误报。
- **markdown 之外**（Word、pptx、纸质稿）需要先转成 markdown。
- **无情绪模型**：笑声、掌声、忘词、翻车的时间不可预测，这正是 ±15% 区间与 5% 安全边际存在的原因。
