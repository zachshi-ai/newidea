# METHODOLOGY · 凑单线

本文写清楚每个数字的口径、每条判据的推导，以及这套账本「不做什么」。

## 1. 为什么「凑单」值得一本账

促销设计的全部智慧在于把一个复杂函数（实付 = 小计 + 凑单 − 优惠）伪装成一句口号（「再买 32 就能减 50」）。行为经济学的三件套在这里同时上岗：**门槛锚定**（99 和 300 这样的整数线把注意力从「要不要买」转移到「差多少」）；**损失厌恶**（「只差 32 就能减 50」被大脑读成「不凑就亏 50」，尽管不凑什么都不会少——你只是没拿到打折资格）；**心理账户**（凑单品被记进「省钱」的账户而不是「消费」的账户，于是它绕过了所有为正常消费设置的审视）。

三件套的合力有一个精确的财务表达：平台战报的口径是 `discount`（优惠额合计），真实口径是 `net = discount − filler`（优惠减凑单）。这两个数的差不是统计误差，是代数上恒等于凑单总额的确定值——**平台不是算错了，是只印了对它有利的那一行**，而省略的那一行恰好等于你多花的钱。一本只有单行本的账，不是账。

fridge-void 说「浪费是一个家里唯一不被记账的经济活动」；凑单是它的结算页版本：**促销诱发的那部分购买，是消费里唯一被记成「省钱」的支出**。

## 2. 口径精确定义

### 2.1 四个金额列与一个动机列

```
planned   没有满减也本来要买的商品原价合计
filler    为凑单加购的原价合计
discount  门槛优惠实得合计（只记满减，红包券一律不进）
paid      实付
```

每行过两道闸门，破即 exit 2 拒载：

```
I1  discount == rule(planned + filler)        （优惠必须能被规则复算）
I2  planned + filler − discount == paid       （残差容 1 分钱）
```

I1 是本账本最硬的纪律：它意味着 discount 列**只能装门槛数学**。现实中一张订单的优惠往往是「满减 + 红包 + 店铺券」的混合体，混着记就复算不平——账本宁可让你把红包另记他处，也不收一张算不清的单。这保证了后面所有恒等式都有干净的输入。

**filler 是动机不是商品属性。** 同一件抽纸，在回购清单上是 planned，收银台顺手拿的是 filler；同一杯挂耳咖啡，为了喝买的是 planned，为了过线买的是 filler。工具无法也不该替你判断——它只提供一列让你申报。这是全套账本唯一的主观列，也是唯一的皮肤游戏：你在这里说谎，骗过的不是工具，是下个月的自己。

### 2.2 两种规则，一条判据

现实中的门槛优惠基本只有两种形状：

```
full:M:D   满减一次   total ≥ M → 减 D，至多一次
every:M:D  每满可叠   每满 M → 减 D，discount = ⌊total/M⌋ × D
```

两种形状共用同一个决策量——**缺口 g**（购物车小计到下一档优惠还差多少钱）：

| 情形 | g | 判决 |
|---|---|---|
| full 且已过线 | — | NO_NEED（优惠已是你的，加购纯亏 C） |
| every 且余数恰为 0 | — | NO_NEED（同上——压线状态是最优状态） |
| g ≤ D | [g, D] | FILLABLE：白赚区，凑单额落区内实付必降，卡线 g 净赚最大 D−g |
| g > D | g | NOT_WORTH：任何凑单要么不触发（实付 +C）、要么触发但 C ≥ g > D（实付 +C−D > 0）——**放弃满减是数学最优**，exit 4 |

NOT_WORTH 的判词里始终写着倒贴下限 g−D：这不是威胁，是让你在货架前省掉全部纠结的那一行字。每满制下「凑到更高档」的诱惑（差 250 时干脆凑 550 上两个档）也被同一条判据覆盖：多跨一档多付 M−D > 0，永远不如卡在当前缺口——数学上不存在「凑得更远更划算」。

浮点纪律：`⌊total/M⌋` 处加 `1e-9` 防护，299.999999 的尘埃不吞掉你那一档（有测试钉死）。

### 2.3 卡线命题：为什么最优永远是恰好凑到线

给定档位（discount 不再变化），实付 = 小计 + C − discount 随凑单额 C **严格递增**。所以档内最优在 C 最小处，即恰好卡线 C\* = g。推论：

- 白赚区内，C 越小净赚越大——「多凑一件反正有优惠」永远不如「只凑到线」；
- 恰好卡线的那单（示例账本的 O-101、O-104）是这门手艺的满分卷，`simulate` 会点名它们是 optimal；
- `judge --fill` 的最优组合 = 子集和落入 [g, D] 的**最小**合计（子集枚举上限 15 件，防爆炸）。

### 2.4 幻觉差恒等式

每单净收益 `net = discount − filler`。于是账期总计：

```
Σdiscount − Σnet = Σfiller        （恒等式，测试钉到 9 位小数）
```

左边是平台战报口径与真实口径的差，右边是凑单总额。**这个差不依赖任何数据分布**——它对每一笔订单、每一个账期、每一个人恒成立，因为 filler ≥ 0，平台口径永远 ≥ 真实口径，永不低估。这就是「省略即差额」的代数含义：战报省略了多少凑单支出，幻觉就恰好有多大。示例账本：460 − 228 = 232，一分不差。

### 2.5 优惠分层：哪些优惠本来就属于你

把每单优惠拆成两层：

```
free_i   = rule(planned_i)          planned 自己就能拿到的优惠
earned_i = discount_i − free_i      靠凑单品换来的优惠
```

三个推论恒等式（全部有测试钉死）：

```
free + earned = discount
现金差 = Σpaid − Σ(planned − free) = filler − earned
net = free − 现金差
```

示例账本：¥460 优惠里 free 层 ¥300（O-104/105/107 三单 planned 本来就过线），earned 只有 ¥160；为 ¥160 付出 ¥232 凑单品，现金口径**多付 ¥72**——即便净收益是正的 ¥228，你的现金也比「全部裸买」多了 ¥72，因为那 ¥228 里有一大半本来就是你的 free 层。这是战报最深的魔术：它把「你本来就能省的」和「你花钱买来的折扣」印在同一行加粗里。

### 2.6 凑单税率：30% 红线

```
filler ratio = Σfiller / Σdiscount
```

含义：平台喊的每 1 元优惠里，被你自己的凑单吃掉的的比例。30% 红线的依据：ratio = 30% 意味着 earned 层的「折扣率」实际是 7 折（花 0.3 元凑单换 1 元优惠）——这还算一笔交易；50%（示例账本）意味着你花 5 毛买 1 元，而其中一部分凑单品注定吃灰（fate 的证据：凑单品垃圾率 69.5%），实际折扣率远低于账面。红线不是审判是触发讨论的阈值，`--red-line` 可调，exit 4 让它能进脚本、进年度购物复盘的议程。

## 3. 决策回放：四种病，四种药

`simulate` 把每一单对着理论最优重放。最优 = min(裸买实付, 恰好卡线实付)（NOT_WORTH 单没有卡线选项）；best 的最小性不靠相信，靠测试用分厘网格暴力扫 0–400 元凑单额对拍。多付的部分按病根分型：

| 分型 | 病根 | 药 |
|---|---|---|
| FORCED | 缺口 > 优惠的注定凑不平单，硬凑了 | 认出 NOT_WORTH 判词，裸买走人 |
| GRATUITY | 优惠已到手（过线/压线），手贱又加购 | 结算页问一句「这单还缺什么吗」 |
| OVERFILLED | 有白赚区但凑超了线（多付 C−g） | 记住卡线命题：多凑的部分纯花钱 |
| UNDERSHOT | 想凑但没够到线，优惠没触发 | 用 judge 的白赚区挑组合，或干脆不凑 |

示例账本的 ¥117 多付 = FORCED ¥68（O-106）+ GRATUITY ¥25（O-107）+ OVERFILLED ¥24（O-102 的 +23 与 O-108 的 +1）。O-108 那 ¥1 值得单独看：线是 7 元，你拿了 8 元的牙刷——**现实中永远找不到恰好 7 元的凑单品**，这就是「线」与「生活」的最后一元距离，账本把它定价、但不把它算成罪。

回放恒 exit 0：它是镜子不是法官，红线在 audit。对拍三层（最优 2364 < 全裸买 2409 < 实付 2481）也顺带回答了「凑单是不是一定亏」——不是：最优决策比全裸买还省 ¥45，白赚单（O-101/O-104）是真的。**工具反对的从来不是凑单，是看不见的凑单。**

## 4. fate：凑单品的行为证据

`fate` 给两类购买分别算垃圾率：

```
垃圾率 = (idle + trashed) ÷ settled      （open 未表决，不进分母——fridge-void 同一血统）
```

三条纪律：

- **覆盖率门槛 50%**：凑单侧要求 items 账覆盖 ≥ 50% 的凑单金额才判灯，否则横幅声明样本不完整、判决 withheld——两件吃灰凑单品凑不出一个结论。
- **样本门槛 5 件**：settled 凑单品不足 5 件 exit 3——3 件里 2 件吃灰（67%）和 6 件里 4 件吃灰（67%）不是同一个证据强度。
- **对照组**：计划商品就是天然的对照组。示例账本凑单品 69.5% vs 计划商品 14.1%，4.9 倍——同一双手、同一个家、同一个月，唯一的差别是放进购物车的动机。这不是行为经济学教科书的引文，是你自己的数据。

## 5. 红线、门槛与拒绝的权利

- **凑单税率 30%**（`--red-line` 可调）：超过它，这场大促的主要产出是凑单品本身——exit 4。
- **账期 5 单**：不足 5 单的账期结论纯属抽签，exit 3 拒绝下结论。
- **命运 5 件 / 覆盖 50%**：凑单品结论的双门槛，任何一项不足就退出判决席。
- **数据错误 exit 2**：双自洽闸门（I1/I2）+ rule 语法 + fate 外键，全部前置拒载。账本的第一美德不是聪明，是不会把坏数据悄悄算进结论。

## 6. 确定性原则

- 账本自锚定：年化用账本内最大最小日期折算（下限 1 周），不用系统时钟——同一本账在任何机器任何时间跑出的报告逐字节一致，才配得上 `examples/build_examples.py --check` 的字节级 CI。
- 大促年化挂横幅：「promo pace is not the year's pace」——用 3 周的大促节奏外推 52 周必然高估，账本把这个数字印出来但强制穿上同口径比较的外衣。
- 全部恒等式（I1–I6）在 `validate` 里逐一复算打印，残差 9 位小数；分解不是修辞，是会计。

## 7. FAQ

**Q:电商 App 都有「已省 ¥X」的年度账单了，为什么还要手编账本？**
A:战报的单行本正是问题本身：它只印 discount，不印 filler，而这两列的差在代数上恒等于你多花的钱。手编的原因和 fridge-void 一样——planned/filler 的划分是动机，只有你自己知道；结局（used/idle）只有看见结局的人能记。这 30 秒的手工就是账本全部的边际成本，也是它全部的可信度来源。

**Q:我在 filler 列上作弊怎么办（把冲动购买都记成 planned）？**
A:账本立刻变得毫无用处，但受害的只有你：净收益会虚高，fate 对照会失效（planned 的垃圾率被污染上升），决策回放的 optimal 单会变成自欺的单。工具不设防——它假设打开账本的人想要的是答案，不是表扬。

**Q:红包、店铺券、预售定金膨胀为什么不算？**
A:它们破坏 I1（优惠必须被门槛规则复算）。混着记的账本什么恒等式都保不住。账本只研究门槛数学这一种促销，其余优惠请在别处记账——口径的窄是为了结论的硬。

**Q:为什么只有 full 和 every 两种规则？阶梯满减（满 100−10 且满 1000−150）呢？**
A:多档并行时优惠函数不再单调，判据矩阵爆炸，而现实大促（天猫双 11 的每满 300−50、京东的满 99−109）以这两种为主。等价替换：把并行两档拆成两本账分别记，每本账各自过线——口径变窄，判断不变糊。

**Q:judge 说 NOT_WORTH，但我真的很想要那件凑单品怎么办？**
A:买——把它记成 planned。判据说的是「为了 ¥20 的优惠加购 ¥54 的东西不是一笔交易」，不是说那件东西不值得买。值得买的商品不欠一次满减：它随时可以买，包括没有促销的那天。

**Q:凑单线能不能接购物车 API 自动算？**
A:不连任何商城接口是底线：接口给的只有价格，没有动机——而本件的全部结论（净收益、分层、命运对照）都长在动机那列上。手工抄四个数（planned/filler/discount/paid），换来一本完全属于你、任何平台都拿不走的账。
