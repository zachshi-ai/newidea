# 包场 · Full House

> 一场会就是一次包场：你包下的是每个人的那一小时，而散场时永远没有账单。
> A meeting rents everyone's hour in bulk — the bill just never shows up.

## 一句话

日历只显示时间，不显示价格：一场 8 人 1 小时的会，按人均时薪 150 元就是一次 ¥1,200 的采购，而且每周都买、一年买 52 次，从没有一张账单；「顺便拉齐一下」的 4 人 30 分钟看起来免费，其实每个人都在被包场。会议是职场里最大的一笔隐形开支，它隐形的原因很简单——日历的单位是分钟，工资的单位是钱，两本账从来没有人对过时。`full-house` 从一本可手编的会议账（日期/开始/时长/人数/主题/类型/产出）确定性算出八本账：**总账单**——人时是硬通货、钱只是翻译，没给时薪照样出全部人时账（诚实条款：你不报价，它就不谈钱）；**单场排行**——谁在包最大的场（两场 32 人的全员会，一场 ¥7,213.87，合计吃掉全部人时的 35.8%）；**周期会年化**——同名系列按实证节奏（观测频次 ÷ 覆盖周数 × 52）外推成年度账单，那场看着免费的每日站会（5 人 × 15 分钟）一年 208 场 260 人时 ¥39,075，全员会年化 ¥93,780，一场周例会一年 ¥62,520；**日历形状**——会议三明治（两场之间 <15 分钟的假空档，既开不了新事也做不了深事）、连轴链、重叠撞会，以及那个最疼的数字：40 个工作日里只有 5 天没有会（12.5%）；**产出账**——决策/行动项的自报记录折成决策成本：每做出一个决定平均烧 46.1 人时 ¥6,932，而 60.2% 的人时（¥33,364）去了没有任何产出记录的会；**反事实**——砍掉那场周例会，周均从 46.1 人时跌到 38.1，红线由红转绿，一年省 416 人时 ¥62,520（17.3% 的总账单）；**排期门禁**——已经订进日历的会逐场过人时红线（单场 16 人时、每周 40 人时——「你的团队的会，每周烧掉一个全职员工」），击穿 exit 4；**账本体检**——恒等式 Σ人时逐场钉死，历史与排期分段披露。工具不连日历 API、不建模缺席迟到、不判定一场会该不该开——它只把价格挂出来：**缩屋、缩时、还是砍系列，仍是人的决定**。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 在日历里上班的知识工作者与带团队的人——周历 20+ 场会的产品经理、被评审会填满的技术负责人、想给团队「减会」却拿不出数据的管理者；也是每一个觉得「好像什么都没干一周就过去了」却说不清时间去哪了的上班族。 |
| **场景** | 周五晚上打开下周日历，整页全灰；季度复盘被问「研发效率去哪了」答不上来；想把某场周会砍掉，但「也就一个小时」这句话让所有人都觉得不至于；年底盘点才发现全年 1,000+ 小时在会上，而真正做出决定的那几个瞬间根本记不得是在哪场会里。 |
| **问题** | **会议成本在所有账本之外**：① 单场成本不可见——8 人 × 1 小时从来不是「一小时」，是 8 小时，日历从不相乘；② 周期会年化不可见——「每周一次」听着很轻，乘以 52 再乘以人数就是一辆车，没人做过这个乘法；③ 空档不可见——两场会之间 10 分钟的三明治既开不了新会也进不了深度工作，却把一整天切成碎片；④ 产出无从对账——会议的产出（决策、行动项）散落在聊天记录里，于是「这会开得值不值」永远停留在感觉。 |
| **价值与意义** | 1) **第一次有账单**：把「时间语言」翻译成「预算语言」，减会从口号变成财务决策——样例团队 8 周 369 人时、年化 ¥360,468，「我们会的太多了」从此有分母。<br>2) **砍会有优先级**：`recurring` 按年化账单排行（全员会 ¥93,780 > 评审会 ¥70,335 > 周例会 ¥62,520 > 站会 ¥39,075），`simulate cancel` 让你在推别人之前先看见收益——砍掉周例会一年 ¥62,520，红线直接回绿。<br>3) **排期有门禁**：`gate` 对日历上已订的会逐场过闸——那场 9-14 的全员会（32 人 × 90 分钟 = 48 人时）在开之前就亮灯，而不是散会之后才心疼。<br>4) **诚实条款**：人时是硬通货、钱是翻译，不报价就不谈钱；产出是自报的，工具不裁判会议该不该开；缺席、迟到、走神不建模——账本只记日历上的事实。 |

## 核心思想：人时是硬通货，钱是翻译

会议账本的第一性单位不是钱而是**人时**（person-hours = 时长 × 人数 ÷ 60）：它不需要时薪就能成立，跨团队可比，且无法被「我们工资低」 argument 消解。钱只是在人时上乘一个你自己的单价。

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **包场账单 bill** | 单场成本 = 时长 × 人数 × 时薪；总账单、周均（按覆盖周数均摊，周一到周日为一周）、年化（×52）；周均人时超过红线（默认 40 人时/周 = 一个全职员工的整周）exit 4 | 「我们的会，一个月烧多少？」 |
| **单场排行 top** | 按人时降序，top-N 场合计占比——「最贵的 5 场会吃掉三分之一人时」是常态不是巧合 | 「谁在包最大的场？」 |
| **周期会年化 recurring** | 同名系列按实证节奏外推：年化 = 场次 ÷ 覆盖周数 × 52 × 场均人时——假期与跳过的周自动摊薄，间隔中位数只作节奏参考；只出现一次的会不年化，同日同名重复场次拒绝年化 | 「这场周会一年多少钱？」 |
| **日历形状 density** | 三明治：同日相邻两场 gap < 15 分钟；连轴链：gap ≤ 5 分钟才延伸（重叠是排期事故，不算链）；干净工作日：周一到周五中零会议的天；周末会单列披露 | 「日历是怎么碎掉的？」 |
| **产出账 outcome** | 每场会自报 decision / action / none（缺省 none 且披露）；决策成本 = 总人时 ÷ 决策数；无产出的人时与账单单列；按类型交叉（全员会 100% 无产出） | 「每做出一个决定，花多少人时？」 |
| **反事实 simulate** | `cancel --match 主题` 砍掉匹配系列（`--every K` 改为每 K 场开一场），输出周均变化与年化节省——它不说被砍的会没价值，它只给「不办」这个选项标价 | 「少开这些会，一年省多少？」 |
| **排期门禁 gate** | 历史周均过周线（40 人时），排期中的会逐场过单场线（16 人时 ≈ 2 个人天）；击穿 exit 4——灯亮在开会之前 | 「下周日历已经超载了吗？」 |
| **账本体检 validate** | 恒等式 Σ场人时 == 总人时钉死；钱恒等式 Σ(场成本) == 总人时 × 时薪，漂移 < 1e-6；历史/排期分段、缺省披露、主题盘点 | 「这本账配不配得上结论？」 |

三条边界刻在实现里：

- **人时优先于钱**——不给 `--rate`（或 `--salary/--hours`）时全部命令照常出账，只是没有钱的行；unpriced 模式明示。统一时薪是刻意简化：账本不采集个人身份与个人时薪，它算的是包场的批发行情。
- **过去与排期分段**——`--today` 是显式参数而不是墙上的钟：排期中的会不进任何历史统计（逐场披露跳过数量），只接受 `gate` 的审查。同一本账任何机器任何一天跑出的结果逐字节一致（examples 快照有 CI 字节级校验）。
- **工具不裁判**——产出字段是自报的，账本不验证一场会是否真的产生了决策；它拒绝的是「免费」这个词继续在日历上流通。砍不砍、缩不缩，仍是人的决定。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 full_house.py --today 2026-08-31 bill meetings.tsv --rate 150
```

## 命令速查

```bash
python3 full_house.py bill      meetings.tsv --rate 150            # 总账单：人时/钱/周均/年化，周红线 exit 4
python3 full_house.py bill      meetings.tsv --salary 26000 --hours 173   # 时薪 = 月薪 ÷ 月工时
python3 full_house.py top       meetings.tsv -n 5                  # 最贵的 5 场会
python3 full_house.py recurring meetings.tsv --rate 150            # 周期会年化：这场周会一年多少钱
python3 full_house.py density   meetings.tsv                       # 日历形状：三明治/连轴链/干净工作日
python3 full_house.py outcome   meetings.tsv --rate 150            # 产出账：每决策成本、无产出账单
python3 full_house.py simulate  meetings.tsv cancel --match 周例会   # 反事实：砍掉一年省 62,520
python3 full_house.py simulate  meetings.tsv cancel --match 评审会 --every 2   # 改为隔周一次
python3 full_house.py gate      meetings.tsv --rate 150            # 排期门禁：击穿 exit 4
python3 full_house.py validate  meetings.tsv                       # 账本体检：恒等式/分段/披露
```

全局参数 `--today YYYY-MM-DD` 钉死「今天」，保证过去/排期分段与快照可复现。

## 账本格式（可手编 TSV，一行一场会）

```text
date	start	duration_min	attendees	subject	kind	outcome
2026-08-03	10:00	60	8	周例会	sync	action
2026-08-17	16:00	90	32	全员会	all-hands	none
```

- `start` 为 24 小时制 HH:MM；`duration_min` 分钟数；`attendees` 为正整数。
- `kind` 自由文本（sync / review / all-hands / interview / …），只用于分组展示。
- `outcome` 为 `decision | action | none`，留空或缺列默认 `none` 并在报告中披露。
- 排期中的会正常记入（日期在未来）：历史报告跳过并披露，`gate` 逐场审查。
- 从日历肉眼抄写即可，一行 30 秒；重复行（同日期同时同主题）是账目腐败，exit 2。

## 验收标准（全部转为自动化测试，62 个）

1. **解析守卫**：表头校验、列数（6–7）、日期/时间格式、时长与人数必须为正、空主题、非法 outcome、同日同时同主题重复行——全部 exit 2；注释行与空行跳过；outcome 缺省 none 且报告披露；乱序输入按日期时间排序。
2. **人时与账单**：人时 = 分钟 × 人数 ÷ 60 精确；周均按「首场周一 → 末场周日」覆盖周数均摊（口径钉死）；年化 = 周均 × 52；**钱恒等式 Σ成本 == 总人时 × 时薪** 打印并钉到分；`--rate` 与 `--salary/--hours` 互斥、`--salary` 缺 `--hours` 报错。
3. **诚实条款**：unpriced 模式全部命令可用、无任何钱的输出、明示 NOTE；红线按人时判定与单价无关。
4. **周期会年化**：同名聚类；年化 = 场次 ÷ 覆盖周数 × 52 × 场均人时（4 场每周 × 8 人 × 60 分 → 52 场/年 416.0 人时，实证口径钉死）；单次会不年化；同日同名 median gap = 0 拒绝年化。
5. **日历形状**：三明治 gap < 15（恰好 15 不算）；连轴链 gap ≤ 5、重叠不延伸链；最贵日排行；干净工作日分母为覆盖区间内全部周一至周五；周末会披露。
6. **产出账**：决策成本 = 总人时 ÷ 决策数；零决策输出 n/a 而非除零；无产出账单与人时占比；按类型交叉表。
7. **反事实**：子串匹配系列；`--every K` 保留 1/K；年化节省 = 周均节省 × 52；匹配不到 exit 2。
8. **门禁**：单场线只审排期（历史大会不触发）；周线审历史周均；默认线 40/16 人时可调；击穿列明场次 exit 4，全绿 exit 0。
9. **exit 语义**：0 正常 / 2 账目或用法错误 / 3 样本不足（<5 场历史、空账本、unpriced 想谈钱）/ 4 红线或门禁击穿。
10. **可复现**：`--today` 钉死分段；同一账本跨机器跨日期输出字节一致（examples 快照 CI 校验）。
