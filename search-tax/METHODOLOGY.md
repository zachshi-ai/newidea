# METHODOLOGY · 寻物税

## 1. 为什么是事件流，不是物品台账

「家里有什么、放在哪」的静态台账会腐烂：世界变了，台账不会自己变。寻物税只认**事件**——翻找、重购、设位，各自带日期，append-only，永不改写。静态事实（它现在在哪儿）从不需要记录：它就体现在最近一次 `search` 的 `place` 里。事件流的副作用是账本自带时间结构，窗口、回访、反事实都只是对同一行流的切片，没有第二本账要对。

## 2. 账本周与年化口径

覆盖率分母用**账本周**：首事件所在周的周一 → 末事件所在周的周日，含两端。样例 2026-06-30 → 2026-08-21 恰为 8.0 周。年化 = 总分钟 ÷ 账本周数 × 52。

为什么用周均而不是日均 ×365：翻找有强烈的周节律（周末大扫除翻出东西、工作日出门前翻钥匙），日均会把「宅家周」错误外推成低税负；周口径天然吸收这种节律。为什么乘 52 而不是 365÷7：两者相同，52 是「一年」在人话里的单位。

## 3. 惯犯判据：90 天 3 次

REPEAT OFFENDER 的默认线是 90 天窗口内 ≥3 次翻找。直觉：一件**真有固定位置、且位置稳定**的东西，在 90 天里失踪三次是不可能的——每次用完它都回到同一个地方。三次意味着「用完随手一放」已经是它的默认状态，这正是「设固定位置」干预的适应症。差一次（2 次）进 WATCH：还没到线的嫌疑犯，先观察，不冤枉。

窗口锚在**账本末日**而不是今天：账本停更三天，窗口跟着后退三天，税额与惯犯判定不因你没记账而漂移。这也是全工具没有 `--today` 的原因——所有时间参数都锚在账本内部，可复现性是构造出来的，不是纪律约束出来的。

## 4. 重购确认：证据分级，不是因果判定

`buy` 行 confront 寻物史后只给两级：

- **CONFIRMED**（有寻史）：账上这个物品任何时点翻找过——买前找不到所以买，或买后还是找不到。它不能证明因果（可能你只是顺手又想要一个），它是**证据**：找不到与重购在同一件物品上共现。
- **UNEXPLAINED**（无寻史）：账本无法解释这笔重购。它不判你有罪，它把问题原样还给你：「为什么买了第二把卷尺？」——账本的职责是让这个问题存在。

确认率 = CONFIRMED 物品数 ÷ 有 buy 的物品数。它度量的是「你的重购里有多少能被找不到解释」，分母故意用物品数而不是金额：三根便宜数据线的痛感不该被一根贵的压平。

## 5. 处方 = 寻获地众数

「它总在哪儿被找回」是「家该安在哪儿」的最好估计——你不缺收纳理论，你缺的是注意到它已经在沙发缝里被找回两次。处方纪律：众数地点出现 ≥2 次才开（一次是巧合）；两个地点打平判**游荡型**，不开处方先观察——给游荡的东西安家只是把迷路换成藏匿。

## 6. 回访口径：每观察日比率，TOO EARLY 不是「没再丢」

fix 回访最容易犯的错是把「账本在 fix 后没几天就停了」当成「fix 后没再丢」。因此 post 窗口钳到账本末日，按**每观察日**算比率：

- **TOO EARLY**：post 可观察天数 <7——证据还没机会发生，不是证据不存在（样例里指甲刀 fix 后账本只剩 1 天可观察）。
- **WORKING**：post 比率 ≤ pre 比率 ÷2——频次真的掉了。
- **NO-CURE**：比率没掉——要么家安错了地方，要么「有家」没变成「回家」的习惯。
- **QUIET**：两侧都零事件——它本来就不找上门，这次设位什么也没改变。

pre 窗口同样钳到账本起点，两侧对称，不做任何插补。

## 7. 治愈率不发明

`simulate fix` 需要一个「设位能避免多少翻找」的比率。外部常识值（「收纳后 80% 不再乱放」之类）是发明，账本拒绝。它只接受两个来源：

1. **账本内部实测**：可判 fix 案的 (1 − post/pre) 中位数。样例里门禁卡案 0.190 → 0.033 次/天，实测缩减 82%。
2. **显式 `--cure`**：你自带假设，工具照算，但输出永久挂着「assumed（外部假设，保持怀疑）」横幅。

没有可判案例且没给 `--cure`，工具的答案是 exit 3：先去给一件东西安家、观察满 7 天，让账本长出证据。

## 8. 与仓库其他点子的边界

- **left-behind 漏带时刻**：那边是出门前**漏带**（该带没带，错题在打包清单）；这边是在家里**找不到**（东西在，位置不在）。同一个「丢三落四」象限的两条轴。
- **digital-attic 数字阁楼**：那边盘数字媒体库的**结构治理**（垃圾占比、存储房租）；这边记物理物品的**检索成本**。一个管「库有多乱」，一个管「找有多久」。
- **expiry-cliff 到期悬崖**：那边是外部授予的到期日（证件、票券）；这边的东西不过期，只是失联。
- **repair-ledger 续命账**：那边决定「修还是换」（物品坏了）；这边决定「安家还是再买」（物品没坏，只是找不到）。
- **recoup 回血**：那边是处置端变现（卖掉回血）；这边是持有端检索税。一个管出手，一个管找回来。
- **cart-line 凑单线**：那边的钱花在结算页上、当场可见；这边的钱花在「以为自己没有」上、混在正常消费里。
- **contribution-gap 贡献错觉**：那边对账「人与人的贡献感知」（记忆偏差）；这边对账「人与物品的位置关系」（没有记忆问题，只有收纳问题）。

## 9. FAQ

**Q：翻找时长是回忆值，掐秒表吗？**
不。±2 分钟的回忆值足够定税与排行；秒表级精确是幻觉（翻找时的你是不会记账的）。账本按「事后想起来补一行」设计。

**Q：漏记了很多次怎么办？**
税额被低估，排行不变（惯犯是相对排名）。工具的立场：宁可低估，不虚报。这也是为什么没有「补记系数」——为遗漏发明乘数才是虚报。

**Q：家人的东西也翻找，记成一条吗？**
记。物品名不记人——家是一本账。惯犯清单问的是「哪件东西在偷全家的时间」，不是「谁在偷谁的时间」（那是 contribution-gap 的问题）。

**Q：多久记一次？多久出一次报告？**
发生了才记（不是日盘点）；≥8 次翻找且覆盖 ≥14 天后，随时可以出第一份报告。惯犯线是 90 天窗口，所以记账满三个月后判定最可靠。

**Q：为什么金额不进 report 的排行？**
排行按分钟——时间是硬通货，钱是翻译。金额进 dup（重购对账）和 wage 翻译，各归各位。
