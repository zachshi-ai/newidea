# 暗基数 · Shadow Base

> 工资条说你挣 15,000，社保系统里那个从没露过面的数字说你只有 5,500——你从没见过它，它却在给你的养老金、公积金和医保定价。
> Your payslip says ¥15,000. The number that prices your future says ¥5,500. You've never seen it.

## 一句话

在职打工人和五险一金之间隔着一本从没人翻开过的账：**缴费基数**决定你的养老金个人账户、公积金和医保，但它从不出现在工资条上，官方 App 只给你看流水和余额——零计算：不预警断月、不对账基数、不倒计时资格、不模拟离职。`shadow-base` 把两本手编 TSV（社保/公积金逐月缴纳流水 + 工资参照）放上对账台，开出五本账：**基数对账 audit**——实缴基数 ÷ 工资 = **缴费水位**（样例 5,500 ÷ 15,000 = **0.3667**，公司在按 36.7% 的你交社保；基数恰好等于当地下限 = **按下限交法的指纹**，39 个月在册）；**暗折账 compare**——低报暗折 58,520（公积金 43,320 ＋ 养老个人账户 15,200）＋ 断缴缺席 3,600 = **62,120 ≈ 4.14 个月工资**，逐月有主，统筹是共济不定价；**连续账 streak**——fund 断月 2026-05、当前连续 3、`--require 12` 还差 9 个月预计 2027-05 达成；社保补缴行在月历口径下愈合连续、在 strict 口径下断链——**两种口径同时亮出，政策永远赢**；**反事实 simulate**——`quit 1` 让 fund 的达成从 2027-05 推迟到 2027-09（**推迟 4 个月 = 空档 1 + 现有连续 3**），`bridge` 架桥不推迟但自缴月算不算连续取决于城市。账本自锚定：缺省 as-of = 账本末月，`--as-of` 钉死，同一本账任何机器任何一天跑出的结果逐字节一致。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 在职打工人——尤其是三类：正打算跳槽、在算「空档一个月会不会断」的人；正在攒购房/落户/公积金贷款资格、盯着「连续 N 个月」的人；打开公积金 App 看到缴存额、隐约觉得「和我工资对不上」的人。 |
| **场景** | ① 提离职前的那个周末：原公司交到几月、新公司从几月开始、中间那个月谁管——HR 各说各的，没人替你看那本账；② 公积金 App 里的缴存明细：月薪 15,000，每月怎么只进 1,320——「公司是不是按最低基数交的」这个怀疑从没有工具帮你证实，更没人替你算过损失；③ 购房资格窗口：需要连续 60 个月，已经连续 47 个月——「下个月裸辞会怎样」没有任何 App 回答得了；④ 每年 7 月的基数调整季。 |
| **问题** | ① **基数是影子数字**：它决定你的养老金个人账户、公积金和医保，但工资条上没有它，App 里埋在流水深处，从没人和你的工资对过——你连自己在按哪个收入的你交社保都不知道；② **低报是普遍操作**：公司按当地下限交基数省下的钱，公积金那一半本来就是你自己的钱——发现的唯一途径是自己逐月对账，而没人对；③ **断缴是资格的清零键**：购房、落户、公积金贷款、医保报销都挂在「连续缴纳」上，换工作的衔接空档全凭运气；④ **所有官方工具只展示不计算**：流水和余额看得见，水位、暗折、倒计时、推演——一个都没有。 |
| **价值与意义** | ① **第一次对账**：水位 0.3667 不是感觉，是比值——「公司在按另一个收入的你交社保」从阴谋论变成一行算术；② **暗折有了价格**：少缴的公积金（两半都是你的钱）和养老个人账户逐月加总，62,120 = 4.14 个月工资——「福利被打了折」第一次有了可以拿去和公司谈的数字；③ **断缴从恐惧变成日历**：断月在哪、当前连续多少、还差几个月、断了推迟几个月——推演代替焦虑；④ **两种口径同时亮出**：月历口径（有缴就算）与 strict 口径（补缴断链）并排呈现，因为不同城市认不同口径——工具不替政策做主；⑤ **诚实条款**：比例、下限、资格月数全是参数，它是计算器不是律师。 |

## 核心思想：工资条和社保系统是两本账，中间的差价没人替你算

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **缴费水位** | 水位 = 实缴基数 ÷ 工资参照。SHAVED < 0.60（红灯）≤ LAG < 0.90（合法滞后带，不亮灯）≤ FULL | 「公司在按哪个收入的我交社保？」——水位 0.3667 = 按 36.7% 的你交 |
| **按下限交法指纹 FLOOR-PAY** | 给 `--floor-value`（当地基数下限）后：实缴基数 == 下限 而工资高于下限 → 指纹坐实 | 「怎么证明它是故意的？」——基数恰好等于下限不是巧合，是交法的签名 |
| **暗折账** | 暗折 = Σ (工资 − 实缴基数)⁺ × 划入你名下的费率：公积金 (个人+公司)%、养老个人账户 8%。**只定价划入你名下的钱，统筹是共济不定价**；断缴月整月按 0 计入缺席账 | 「缩水的基数一年偷我多少钱？」——62,120 = 4.14 个月工资，逐月有主 |
| **确凿与存疑** | SHAVED 月与缺席月是确凿暗折；LAG 带（0.60–0.90）可能是上年月均口径的合法滞后——计入总额、单列披露、不当灯 | 「涨薪年基数没调上来，是不是被坑了？」——不一定，账本分得清算得少和算得晚 |
| **连续账** | 断月 = 账本跨度内缺行的月份；月历口径：有行（含补缴行）就算连续；strict 口径：补缴月也断链。两种口径并排亮出 | 「我的资格还安全吗？」——断月在哪、当前连续多少、还差几个月，两种口径各报各的 |
| **资格倒计时** | `--require N`：当前连续 ≥ N 已达成（断缴即可能清零）；< N → 还差 N−s 个月，按月历连续缴预计某月达成 | 「还要攒多久？」——2027-05，前提是不再断 |
| **反事实 simulate** | `quit K`：空档 K 月后资格清零重计——推迟月数 = K + 现有连续 s（旧连续不再垫底）；`bridge K`：空档自缴架桥，月历口径不推迟，自缴月算不算连续以当地口径为准 | 「下个月裸辞会怎样？自己交着呢？」——推迟 4 个月 / 不推迟但口径存疑 |
| **账本体检 validate** | Σ 复算、断月双算法（月历游走 == 行集合差）、连续双算法（向后游走 == 正向扫描）、公司缴额口径披露、暗折分解恒等（低报 + 缺席 == 总额） | 「这本账配不配得上结论？」 |

三条边界刻在实现里：

- **它是计算器不是律师**——比例（社保个人 10.5%、公积金 12%+12%、养老个人账户 8%）、基数下限、资格月数全是参数；各城市口径不同且常变，**政策永远赢**；报告不给法律结论，只给算术事实。
- **薄账分层**——跨度 < 6 个月：算术照常出账（Σ、断月、连续、月历），统计判级 DECLINED exit 3；无工资参照（`--salary`/payroll.tsv 都没给）：基数表照出，水位与暗折 DECLINED——**没有参照就没有水位**。
- **账本自锚定**——缺省 as-of = 账本末月，`--as-of YYYY-MM` 钉死；报告只打印账本 basename，绝不回显调用方路径；同一本账在任何机器、任何日期跑出的结果逐字节一致（CI 快照校验）。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 shadow_base.py report examples/ledger.tsv --wages examples/wages.tsv --require 12
```

## 命令速查

```bash
python3 shadow_base.py report   examples/ledger.tsv --wages examples/wages.tsv --require 12 --floor-value 5500  # 总账 + 灯汇总
python3 shadow_base.py audit    examples/ledger.tsv --wages examples/wages.tsv                                    # 基数逐段对账 + 水位判级
python3 shadow_base.py streak   examples/ledger.tsv --require 12                                                  # 月历 + 断月 + 资格倒计时
python3 shadow_base.py compare  examples/ledger.tsv --wages examples/wages.tsv                                    # 暗折账：两世界对照
python3 shadow_base.py simulate examples/ledger.tsv quit 1 --require 12                                           # 离职空档推演
python3 shadow_base.py simulate examples/ledger.tsv bridge 1 --require 12                                         # 自缴架桥推演
python3 shadow_base.py validate examples/ledger.tsv                                                               # 恒等式与口径披露
python3 shadow_base.py report   examples/ledger.tsv --wages examples/wages.tsv --as-of 2025-12                     # 钉死到去年底重放
python3 shadow_base.py streak   examples/ledger.tsv --require 23 --strict                                          # 补缴断链口径
```

Exit codes：**0** 绿 · **2** 账本损坏（坏行/重复月份/出界值/坏表头）· **3** 样本太薄或缺工资参照拒绝判级 · **4** 红灯（SHAVED / FLOOR-PAY / SHADOW MONTHS）。

## 账本格式（可手编 TSV）

**ledger.tsv —— 缴纳账（一月一账两行）**

```text
month	scheme	base	personal	company	note
2024-10	social	5500	577.50		入职 A 公司
2024-10	fund	5500	660.00	660.00	入职 A 公司
2026-05	social	5500	577.50		2026-07 补缴 5 月
2026-06	fund	15000	1800.00	1800.00	入职 B 公司，足额基数
```

- `month`（YYYY-MM）+ `scheme`（social/社保 或 fund/公积金，中英别名归一）全账唯一（重复 = 手抄事故 exit 2）。
- `base` 可留空——留空时按 `personal ÷ 个人比例` 反解（validate 披露反解行数）。
- `personal` 必填（个人缴纳额，工资条/社保 App 都查得到）；`company` 可选（公积金 App 两半都显示，填了 validate 会做口径披露）。
- `note` 里出现「补缴」→ 该月计入 strict 口径断点；fund 缺行 = 真断月。
- **wages.tsv —— 工资账（可选，逐月工资参照）**：`month<TAB>gross<TAB>note`；不给时用 `--salary`（全期常数）；都不给 → 只有基数表，没有水位与暗折。

## 验收标准（全部转成自动化测试，64 个）

- **暗折恒等式**：合成账本（构造已知低报 19 个月 + 足额 3 个月）必须被精确复原——fund 低报 43,320.00、养老 14,440.00、合计 57,760.00；validate 钉死分解恒等「低报 + 缺席 == 总额」。
- **两世界对照**：足额世界 = Σ工资×费率，账本世界 = Σ实缴×费率，差 == 暗折（样例 79,200 − 35,880 = 43,320）。
- **判级阶梯**：水位恰 0.60 → LAG 不亮灯、0.59 → SHAVED exit 4、恰 0.90 → FULL；LAG 月的少缴计入总额但**不当灯**（确凿暗折不含它）——专门的测试钉死这条语义。
- **FLOOR-PAY 指纹**：基数 == `--floor-value` 且工资高于下限才亮；工资本来就低于下限不亮（合法下限交）；不给 `--floor-value` 不启用。
- **断月与连续**：样例 fund 断 2026-05、连续 3/最长 19；social 补缴行月历口径连续 23、strict 口径断链后当前 3——两种口径同时亮出；断月双算法（月历游走 == 行集合差）与连续双算法（向后游走 == 正向扫描）恒等。
- **资格倒计时**：`--require 12` → fund 还差 9 个月预计 2027-05；`--strict` 切换口径后还差 20 个月；已达成分支各有一测。
- **反事实**：`quit 1` 推迟 4 个月（2027-05 → 2027-09）；`quit 0` 推迟 0（gap 0 = 无断档）；`quit 2 --require 60 --strict` 推迟 5（2031-05 → 2031-10）；`bridge` 月历口径不推迟且明示「自缴月算不算连续政策永远赢」。
- **薄账分层**：< 6 个月 → report/audit/compare exit 3 算术照出（灯照印）；streak/validate 恒 exit 0；无工资参照 → audit/compare exit 3、report 出账但审计 skipped。
- **账本纪律**：重复月份/坏月份/坏表头/负数/未知险种/缺文件/as-of 早于首行 exit 2；中英险种别名归一（社保→social、GJJ→fund）。
- **参数化**：`--fund-personal 0.05` 后反解基数随比例变（275÷0.05 = 5,500）；`--lag-line ≤ --base-floor` 拒绝；公司缴额与基数×比例口径不符 > 5% 逐行披露。
- **可复现**：全部命令同账本两次运行逐字节一致；报告只含 basename 不含调用方路径；`--as-of 2025-12` 截断后暗折重算 45,600（15×3,040）。

## 诚实条款

- **它不下法律结论**：低报基数违法是劳动法问题，本件只把「两本账的差」摆上台面——拿不拿去和公司谈、谈成什么样，是人的决定；追缴时效、仲裁口径，它一概不建模。
- **政策永远赢**：购房/落户/公积金贷款的连续月数要求、补缴是否认账、医保断缴次月是否停报——各城市不同且常变；`--require` 是**你的**参数不是本件的断言，strict 口径的存在就是为了提醒「同一本账有两种读法」。
- **统筹不定价**：医保统筹和养老统筹是共济不是你的存款，暗折只算划入你名下的钱（公积金两半 + 养老个人账户 8%）——少缴对社会统筹的影响是真的，但那不是「被偷走的你的钱」。
- **LAG 带的克制**：基数按上年月均是合法的——涨薪年的低水位可能只是没到调整季；所以 0.60–0.90 的月份计入暗折总额、单列披露、**不当灯**。宁可少亮一盏灯，不制造一场冤案。
- **失业月不发明暗折**：空档月没有工资，也就没有「应缴多少」的参照——simulate quit 只推演资格与空窗，不给空档月编造损失。
- **基数反解是兜底不是真理**：base 列留空时按默认比例反解，validate 会披露反解行数与公司缴额口径偏差——比例因城市/年份而异，参数覆盖永远优先。

## 与近邻的边界

- **safety-floor（兜底）**：那边审**商业保险**的保额够不够（买没买对），本件审**法定福利**的缴够没够（交没交足）——保险缺口是「出事接不住」，暗折是「没出事也在漏」。
- **redemption（赎契）**：那边管公积金贷款的**还贷端**（提前还款的等效收益率），本件管**缴存端**（基数水位与贷款资格的连续月数）——一个对着银行算，一个对着公司算。
- **smooth-sailing（旱涝保收）**：那边管自由职业者的收入波动（没有雇主的人怎么做月度预算），本件管受雇者的法定福利（有雇主的人被代缴了什么）——雇主缺席 vs 雇主缩水。
- **border-budget（窗期）**：那边给签证停留算滚动窗口余额（90/180），本件给资格算连续月数倒计时（require N）——同为「资格是会清零的窗口」，一个每天回血，一个月月累计。
- **felt-inflation（体感通胀）**：那边对账「官方 CPI vs 你家小票」，本件对账「工资条 vs 社保系统」——都把声称与记录的差值命名，一个叫让步，本件叫暗折。
- **life-tag（生命价签）**：那边用工资算**真实时薪**（工资条那本账的下游），本件审**工资条背后**的社保账（上游）——工资 15,000 的人时薪被隐形税啃过之后，还要被影子基数再啃一口福利。
