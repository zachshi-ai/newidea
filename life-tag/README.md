# 生命价签 · Life Tag

> 标签上印的是价格，你付的是生命小时：名义时薪是个系统性幻觉——它假装通勤、下班恢复、工作开销不存在。`life-tag` 把这三重「隐形税」拆开算出**真实时薪**，再把每一笔消费换算成「你要白上几天班」。
> A zero-dependency CLI that strips the three hidden taxes (commute, recovery, work costs) from your nominal hourly rate, converts every price tag into life-hours, and answers "relocate vs raise — which one actually buys back your time?"

---

## 一句话

你以为自己时薪 91，其实 56——差的 35 块被三笔从不出现在工资条上的「隐形税」吃掉了：下班瘫掉的恢复税、路上的通勤税、因上班而起的工作开销税。`life-tag` 用一张画像（税前月薪、税负、通勤、恢复系数、工作开销）算出你的**真实时薪**，然后把任何标价换算成**生命小时**和**白上的班次**：iPhone ¥6999 = 125.7 小时 = 10.3 个班次；奶茶 ¥20 = 22 分钟。它还回答两个经典决策——「搬近公司 vs 涨薪 10%，哪个更提时薪」（杠杆排行），以及「这班值不值得加」（加班边际时薪）。核心反直觉洞见有两个：**加班即使 1 倍率也比你的平均时薪"划算"，因为隐形税在白天已经征过了**；以及**对多数通勤族，搬家比加薪更能买回你的时间**。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 拿固定月薪的上班族，尤其在大城市通勤、下班后「累但说不清干了什么」的人；消费决策频繁，常在深夜购物车前犹豫。 |
| **场景** | 结算前纠结一件 ¥3000 的东西值不值；被「你时薪才 50 就别喝奶茶了」的言论刺痛却无从反驳；纠结要不要为省 40 分钟通勤多付房租；纠结要不要接一份 1.5 倍的加班。 |
| **问题** | **单位不统一**：价格以「元」计，你的劳动以「月」计，比较只能靠感觉。而唯一直觉可比的单位——名义时薪（月薪 ÷ 21 ÷ 8）——是**系统性高估**：① 它假装你只为工时本身付出时间，忽略通勤与下班恢复；② 它假装上班不花钱，忽略通勤费、工作餐差价；③ 它还会反向算错加班——用被摊薄的平均时薪去评估一个不再摊销任何固定成本的边际班次。高估时薪让万物显得便宜，你买贵了；错用均价让加班显得亏，你又算错了另一边。 |
| **价值与意义** | 1) **把幻觉拆成三笔账**：恢复税、通勤税、开销税逐项量化，瀑布分解精确相抵（可加和验证），你知道自己的时间到底被谁吃了。<br>2) **统一决策单位**：所有标价换算成生命小时与班次，「¥6999」变成「10.3 天白上班」，数字自己会说话。<br>3) **心跳线对抗冲动**：超过一次完整自由日（默认 8 生命小时）的购买，睡一觉再决定——给即时欲望装一个 12 小时的延迟阀门。<br>4) **杠杆排行**：涨薪 / 搬近 / 远程 / 降恢复 / 砍开销各能提多少真实时薪，排序告诉你下一份努力投在哪。<br>5) **零依赖 + 纯本地**：Python 3.8 标准库，一份 JSON 就是全部数据，不联网不上传——收入画像是最敏感的私人数据。 |

## 核心思想：三重隐形税 → 真实时薪 → 生命价签

数据模型是一份人类可直接编辑的 JSON 画像。所有推导只有一个骨架：

```
真实时薪 = (税后月入 − 工作开销) ÷ (工时 + 通勤 + 恢复)
```

| 概念 | 定义 | 直觉 |
|---|---|---|
| **名义时薪** | 税后月入 ÷ (工作日 × 日工时) | 工资条想让你相信的价格 |
| **恢复税** | 每工作 1 时报废 r 时（r=恢复系数），按名义时薪摊薄 | 下班瘫着刷手机、缓神、做不了任何正经事的时间 |
| **通勤税** | 单程分钟 × 2 × 工作日摊进分母 | 公司在「免费」占用你每天额外的两小时 |
| **开销税** | 通勤费 + 工作餐差价 + 工作着装等，摊进分子 | 上班这份工作的「耗材费」 |
| **瀑布分解** | 顺序：恢复 → 通勤 → 开销，每步侵蚀额精确可加 | 名义 − 真实 = 三税之和，分毫不差（测试钉死） |
| **生命价签** | 标价 ÷ 真实时薪 = 生命小时；÷ 每班净收入 = 班次 | 「这件东西值我几个班次」 |
| **心跳线** | 默认 8 生命小时 = 一次完整的自由日 | 超线的购买睡一觉再决定 |
| **加班边际时薪** | 名义净时薪 × 倍率 | 加班不新增通勤与开销，固定税已摊完——所以 1 倍率也高于平均真实时薪 |
| **杠杆排行** | 每个候选动作独立重算真实时薪，按 Δ 排序 | 搬家、涨薪、远程……哪一味药最对症 |

两个设计决策值得说明。**瀑布顺序固定**（恢复 → 通勤 → 开销）：三个税项交叉项的归属需要约定，本件约定「先时间后金钱」，交换顺序只影响单税项数值、不影响总量与结论。**杠杆各动作独立测算、不叠加**：现实中你不会同时搬家又涨薪又远程，叠加测算会产生「乘法幻觉」，排序才是这个功能的全部意义。

## 与近邻的边界

本仓库已有多件消费侧与时间侧的账本，本件站在它们的**收入侧上游**——每一家都把时薪当已知参数用，没有一家审计那个参数本身：

- **[move-line](../move-line/)**（挪窝线）与 **[full-house](../full-house/)**（包场）都拿「单程分钟 × 2 × 天数 × **时薪**」把时间折成钱——但时薪从哪来、被谁吃了多少，是它们视作常数的输入，正是本件的全部主题。本件不裁决租哪套房、会该不该开。
- **[cost-per-wear](../cost-per-wear/)**（每穿成本）在持有端摊销一件已购的衣服；本件在决策端把任何标价换算成生命时间——它问「买回来穿够没有」，本件问「你拿什么换的」。
- **[want-ledger](../want-ledger/)**（种草账）记录欲望从种草到枯萎的生命周期，敌人是「为不再想要的东西付钱」；本件的敌人是「用被高估的时薪估价自己的时间」。心跳线只借用它一晚（睡一觉再决定），不记欲望账。
- **[smooth-sailing](../smooth-sailing/)**（旱涝保收）管收入到手之后的节奏（虚拟发薪、跑道、税罐）；本件管收入被名义单价**系统性标错价**这件事，发生在它到手之前。
- **[move-line](../move-line/)** 的忍价线里「搬家 vs 忍涨」用的是你的时薪；本件的杠杆排行问的是同一个家族的另一个问题——「涨薪、搬近、远程、降恢复，哪个最能修好你的时薪」。互为上下游，不共享账本。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 life_tag.py hourly --path examples/metro_worker.json
```

你自己的画像：一条命令写入 `~/.life_tag/profile.json`（或用 `--path` 指定）——

```bash
python3 life_tag.py profile set --gross 18000 --tax 0.15 \
    --commute 55 --commute-cost 300 --recovery 0.30 --extra-costs 700
```

画像字段：`gross_monthly` 税前月薪、`tax_rate` 综合税负率（个税 + 五险一金占税前比例的粗略估计）、`workdays` 月工作日、`daily_hours` 日工时、`commute_min` 单程通勤分钟、`commute_cost` 月通勤开销、`recovery_ratio` 恢复系数、`work_costs_extra` 其他月度工作开销、`pulse_line` 心跳线、`currency` 货币符号。

## 命令速查

```bash
python3 life_tag.py profile set --gross 18000 --tax 0.15 \
    --commute 55 --commute-cost 300 --recovery 0.30 --extra-costs 700
python3 life_tag.py profile show    # 不给 --path 时读写 ~/.life_tag/profile.json
python3 life_tag.py hourly --path examples/metro_worker.json            # 名义 vs 真实：三重税瀑布
python3 life_tag.py tag 6999 --path examples/metro_worker.json          # 生命价签：125.7 小时 = 10.3 班
python3 life_tag.py tag 6999 --line 200 --path examples/metro_worker.json  # 临时改心跳线
python3 life_tag.py overtime 4 --mult 1.5 --path examples/metro_worker.json  # 这班值不值得加
python3 life_tag.py leverage --commute-to 15 --raise 10 --remote 2 \
    --recovery-to 0.2 --cut-costs 200 --path examples/metro_worker.json     # 杠杆排行
```

## 一个真实样例

`examples/metro_worker.json`：合成但真实感的一线城市通勤画像——税前 ¥18,000、综合税负 15%、单程通勤 55 分钟、恢复系数 0.30、月工作开销 ¥1,000。画像里埋着可手算的已知事实，`tests/test_dogfood.py` 验证报告把它们原样恢复：

```text
【时薪】名义时薪是幻觉，看看它被谁吃掉了

  税后月入      ¥15,300.00（税前 ¥18,000.00 × 85%）
  名义时薪      ¥91.07 / 时（21 天 × 8 时 = 168.00 时）

  三重隐形税瀑布（顺序：恢复 → 通勤 → 开销）
    恢复税  −21.02 / 时   每工作 1 时报废 0.3 时，摊薄 50.40 时/月
    通勤税  −10.50 / 时   单程 55 分钟 × 2 × 21 天 = 38.50 时/月
    开销税  −3.89 / 时   通勤 ¥300.00 + 其他 ¥700.00 = ¥1,000.00/月
    ──────────────────────────────
    合计侵蚀 −35.41 / 时（−38.9%）

  名义 ¥91.07 ████████████████████████
  真实 ¥55.66 ███████████████·········  ← 只有名义的 61%
```

```text
【生命价签】¥6,999.00
  = 125.7 生命小时（7544 分钟）
  或：10.3 个班次的净收入（每班带回家 ¥680.95）

  ⚠ 超过心跳线（8 生命小时 = 一次完整的自由日）
  建议：睡一觉。明早还想要，再买——欲望过夜存活率远低于 100%。
```

```text
【杠杆排行】谁最能提高你的真实时薪（各动作独立测算，不叠加）
  当前真实时薪 ¥55.66 / 时
  1. 单程通勤 → 15 分钟                 +¥7.76（+13.9%） ← 最有效
  2. 涨薪 +10.0%                    +¥5.96（+10.7%）
  3. 每周远程 2 天                     +¥4.05（+7.3%）
  4. 恢复系数 → 0.2                   +¥3.89（+7.0%）
  5. 砍 200 元/月工作开销                +¥0.78（+1.4%）
```

最后一张表是这件产品想改变的东西：直觉以为加薪是万能药，算术说 **55 分钟单程通勤才是最大的出血点**。

| # | 验收标准 | 测试位置 |
|---|---|---|

| A4 | 瀑布恒等式：三重税之和 = 名义 − 真实，`places=9` 精确相抵；零通勤零开销零恢复时真实时薪退化为名义时薪 | `tests/test_hourly.py` |
| A5 | 生命价签：小时/分钟/班次三换算正确；展示主单位按 3 小时 / 200 小时分段；心跳线判定「恰在线上不算超」；`--line` 覆盖生效 | `tests/test_tag.py` |
