# METHODOLOGY · 生命价签的方法论

本文档回答「这个工具凭什么这么算」：三笔税的建模依据、每个参数的估法、
边界情形的约定，以及把它用歪的三种方式。

---

## 1. 唯一的骨架

一切结论来自同一个恒等式：

```
真实时薪 true = (税后月入 net − 工作开销 C) ÷ (工时 H + 通勤 K + 恢复 Q)
名义时薪 nominal = net ÷ H
```

名义时薪不是「错」的，它只是回答了另一个问题——「把你不工作的所有时间
都视为免费时，你值多少」。而消费决策（花 3 小时的产出换一件东西）和加班
决策（多卖 4 小时）都是**边际**问题，边际问题要用边际价格回答。真实时薪
就是对你「可自由支配时间」的边际价格的一次修正估计。

## 2. 为什么恰好是这三笔税

| 税项 | 建模依据 | 反方观点与回应 |
|---|---|---|
| **通勤税 K** | 通勤是雇佣关系的强制附属时间：不去就没有这份收入。它由工作引起、被工作占用，却不计价。劳动经济学的通行做法是把它折算成保留工资的补偿要求 | 「我在地铁上听播客，不算纯损耗」——很好，把恢复系数里的这一部分调低即可。模型不判断你路上干什么，参数归你 |
| **恢复税 Q** | 高强度认知劳动后存在一段低产出恢复期（决策疲劳、情绪耗竭），期间你客观上做不了高价值的事。它同样是工作的直接后果 | 「我下班生龙活虎」——把 r 调到 0.1 甚至 0。工具的默认值 0.25 是保守估计，不是断言 |
| **开销税 C** | 通勤费、工作餐与家常饭的差价、为上班置装的摊销、因通勤产生的打车外卖。这些现金流出因工作而生，是收入的「成本」而非收入本身 | 「不工作我也吃饭穿衣」——对，所以只算**差价**，模型里的 `work_costs_extra` 应填增量部分 |

三笔税的共同点：**都由这份工作强制引起，都被名义时薪假装不存在**。
娱乐开销、房租大头、兴趣班不在其列——那些是你用真实时薪去买的东西，
不是这份工作的成本。

## 3. 瀑布顺序的约定

把 nominal 拆成「恢复税 + 通勤税 + 开销税」三块时，存在交叉项归属问题
（先摊谁，谁的单价基准就高）。本件约定**先时间后金钱**：

```
p₀ = nominal
p₁ = net ÷ (H + Q)        恢复税 = p₀ − p₁
p₂ = net ÷ (H + Q + K)    通勤税 = p₁ − p₂
p₃ = p₂ − C ÷ (H + Q + K) 开销税 = p₂ − p₃  （p₃ 即 true）
```

恒等式 `p₀ − p₃ = 恢复税 + 通勤税 + 开销税` 对任何参数**精确成立**
（`tests/test_hourly.py` 以 `places=9` 钉死）。交换顺序只会微调单税项数值，
不改变总量与任何结论。测试同时钉死了另一件事：K = Q = C = 0 时
true 精确退化为 nominal——工具在不做任何假设时不得产出幻觉。

## 4. 参数怎么估

**恢复系数 r**：连问自己三个工作日晚——
① 今天到家后，从进门到能开始做「我想做的事」，瘫了多久？
② 这段时间里有多少是纯工作耗竭（不是追剧的快乐）？
③ 周末补觉补的是本周的哪几天？
把答案的平均小时数 ÷ 当日工时，就是 r。估完跑一次 `hourly`，
如果数字让你愤怒，两个可能性：你被工资条骗了很多年，或者 r 估高了。
两种都值得认真对待。

**综合税负率**：个税 app 里查上月实缴个税 + 公积金/社保个人部分，
加总 ÷ 税前月薪。嫌麻烦可以用「到手 ÷ 税前」的反数。这是粗估，
对结论的影响是线性的，不需要精确到分。

**心跳线**：默认 8 生命小时 ≈ 一次完整的自由日。这条线的心理学依据
是给冲动装延迟——结算页的兴奋感撑不过一夜。你也可以设 24（一整天）
或 3（更狠）。线内不是「应该买」，只是「不必启用冷静程序」。

## 5. 加班边际分析的数学

加班的边际时薪 = 名义净时薪 × 倍率，理由：加班时段**不新增**通勤 K、
通常不新增工作开销 C、恢复 Q 也已按全月摊完（本模型把 Q 视为与工作日
绑定的沉没成本）。于是对 1.5 倍加班：

```
marginal = nominal × 1.5
premium  = marginal − true > 0   几乎恒成立
```

**这是反直觉的**：多数人用「平均下来时薪才 56」否定加班，但那 56 里
已经被通勤和恢复税啃过；边际班的固定税已由白天的班付清，即使 1 倍率
（义务加班），marginal = nominal = 91 仍高于 56。

**误用警告**：这个结论只回答「算术上」。加班的真实成本是你下班时间的
机会价值、健康折旧与关系损耗——它们不进这个模型，也永远不该进模型
（把妻子的生日折成时薪是这本账的堕落形态）。工具输出的「底线」句式
是刻意设计的：*只要你对下班 1 小时的自我估价低于 X，这班就值得接*——
估价权在你，工具只负责把 X 算清楚。

## 6. 杠杆为什么不叠加

`leverage` 对每个动作**独立**重算真实时薪，即使现实里你可以既远程又
搬近。原因：分母里的时间税和分子里的开销税有交叉，叠加测算会把
「省下的通勤分钟」按两个动作各记一遍，产生乘法幻觉（两个 +7% 加出
+14.5%）。排序才是这个功能的意义——你下一步只会做一件事，做 Δ 最大
的那件。想要组合效果，把「远程 2 天 + 搬到近郊」当成一个新动作，
手动合并参数后用 `hourly` 对比。

## 7. FAQ

**Q：我自由职业 / 按件计酬，能用吗？**
把 `gross_monthly` 填月均收入、`tax_rate` 填综合税负即可，通勤与恢复
的建模对自由职业同样成立（去客户现场的路上依然是通勤税）。按小时
卖时间的人其实最不需要它——你的价签本来就是小时。

**Q：和「时薪计算器」网站有什么区别？**
网站算 `月薪 ÷ 22 ÷ 8`，正是本件定义为幻觉的那个数。区别是三笔税、
班次换算、心跳线、加班边际、杠杆排行——前者是一个除法，后者是一套
决策单位。

**Q：会不会让人什么都不敢买？**
价签是信息不是禁令。¥6999 = 10.3 个班次的意思不是「别买」，而是
「用 10.3 个班次换它，你觉得值吗」——对真心喜欢的东西，答案是值，
换算只是让「值」字有了分量。反过来，对冲动商品，22 分钟的奶茶和
10 个班次的手机放在同一把尺子上，砍单的手会自己动。

**Q：恢复系数算高了，岂不是自我 PUA？**
会。如果你把一切休息都记成「报废」，true 会被低估，你会觉得自己的
时间不值钱。这也是 `recovery_ratio > 1` 被硬性拒绝、工具在 METHODOLOGY
里明确「r 的上界是你自己的诚实」的原因。拿不准就填 0.15——
让它低估伤害，好过高估。

**Q：为什么不考虑年终奖、股票、晋升期权？**
它们让「这份工作值多少」变成期望值问题，而日常消费决策发生在现金流
层面。本件刻意只对**月薪现金流**建模。年度性收入适合另一个工具
（也许是「年度生命账本」），不属于这个价签。

## 8. 边界与约定速查

| 参数 | 合法域 | 越界行为 |
|---|---|---|
| `tax_rate` | [0, 1) | 拒绝：100% = 白干，属填错 |
| `recovery_ratio` | [0, 1] | 拒绝：每工作 1 时要 >1 时恢复，模型不再适用 |
| `commute_min` | [0, 480] | 拒绝：单程 8 小时不是通勤是出差 |
| `price` | (0, ∞) | 拒绝：≤0 的价签无意义 |
| 加班 `mult` | (0, ∞) | 拒绝：0 倍率无意义 |
| `remote_days` | [0, 5] | 拒绝：一周没有第 6 天 |

所有金额计算用浮点，展示保留两位；测试全部用 `assertAlmostEqual`
钉在手算基准上，不以「大概」结案。
