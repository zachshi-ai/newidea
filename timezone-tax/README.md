# 时区税 · Timezone Tax

> 重叠最大的一格 ≠ 代价为零的一格；而代价不为零时，总是同一批人在付。
> A zero-dependency CLI that puts a price tag on every meeting slot: who pays the 23:00 tax, how much each timezone has paid all year, and whether rotation can even fix it.

---

## 一句话

跨时区团队的例会时间由日历工具决定，但那些工具只优化「重叠最大」，从不回答「代价由谁承担」。`timezone-tax` 把每场会议按成员本地挂钟折算成**税单**（黄金时段 0 / 傍晚 1 / 清晨 1.5 / 深夜 3 税点），按周累积成**税负账本**，算出**缴税基尼**回答「分摊公平吗」，在可行槽里做**补偿式轮换**回答「下周换到哪格」，并在轮换无法改变缴税人时诚实判定**结构性失衡**——这不是排会问题，是组织分布问题。核心反直觉洞见：**有些团队形状下，任何一格都有人缴税，且换格子换不掉缴税人——「找重叠时间」工具永远不会告诉你这件事**。

---

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 跨时区分布式团队的例会组织者：管着一支横跨 3 个以上时区的团队，每周要定一次 sync/站会/评审的时间。 |
| **场景** | 打开 World Time Buddy 找「大家都在线」的一格，永远定在总部舒服的那格；某地成员长期 22:30 甚至 23:30 开会。每个人都在忍耐区里，没人抱怨，也没有任何工具给出「不公平」的信号。 |
| **问题** | **会议代价是隐形的、累积的、无人记账的**：① 没有「谁的本地时间被打扰、打多重」的量化——重叠工具只显示颜色块，不显示代价；② 不公平按周复利——一次 23:00 不算什么，52 周就是同一个时区缴了一整年的税，但没有账本，就没人看见；③ 没有中立算法，轮换讨论要么吵起来要么不了了之；④ 最关键的：**有些团队形状下根本不存在无人缴税的格子，轮换也换不掉**——这一点没有任何工具会告诉你。 |
| **价值与意义** | 1) **把情绪变成数据**：「凭什么总是我半夜开会」从抱怨变成一张可引用的税单和账本。<br>2) **公平可以被讨论的前提是公平可以被测量**：缴税基尼、最惨比率、52 周累计税负，三个数字让轮换成为制度而不是人情。<br>3) **诚实优先**：轮换能解决就给出轮换计划；轮换不能解决（结构性失衡）或干脆无解时，直说「出路不在排会，在组织：拆会/降频/异步化」——拒绝假装调格子能 fix 组织分布。<br>4) **零依赖 + 纯本地**：Python 3.8 标准库，两个 JSON 文件就是全部数据库，不联网不上传，不含任何会议内容。 |

## 核心思想：税带 → 税单 → 税负账本 → 结构性失衡判定

数据模型是两个人类可直接编辑的 JSON：`team`（成员、时区偏移、夏令时规则、醒来时段、工作日）和 `ledger`（每场会议的税单）。

| 概念 | 定义 | 直觉 |
|---|---|---|
| **税带** | 成员本地挂钟落在哪一段：黄金 [09:00,18:00)=0、傍晚 [18:00,22:00)=1、清晨 [07:00,09:00)=1.5、深夜其余=3 | 深夜重罚：睡眠剥夺不可妥协；清晨次之；傍晚只是打扰 |
| **税单** | 一场会议 Σ 每人税点；最惨成员 = 税点最高者 | 「这次会议的真实价格」，重叠工具不显示的那个数 |
| **可行槽** | 全员本地时间都醒着（默认 [07:00,24:00)）且都是工作日的 UTC 时刻 | 排会搜索空间；很多团队根本没有它 |
| **税负账本** | 每场会议税单的累积（append-only） | 「本季度谁在缴税」的证据 |
| **缴税基尼** | 累计税负的基尼系数：0=平摊，1=一人全缴 | 分摊公平度的一个数：>0.3 预警，≥0.5 警报 |
| **最惨比率** | max/min 累计税负；min=0 视为 ∞ | 「有人从未缴税，有人周周在付」直接警报 |
| **补偿式轮换** | 每周在可行槽里选「选完之后累计税负的最大值最小」的一格，并列比总税、再并列取更早 | 完全确定性：同输入必同输出，谁也不用背锅 |
| **结构性失衡** | 整个计划期内缴税人集合完全不变 | 轮换无效的诊断书：候选槽里不存在能改变缴税人的格子 |

流程是三步：`inspect`/`simulate` 先**看见**（这场会谁缴税、这格 UTC 定死一年谁遭殃），`plan` 再**求解**（能轮换给轮换计划，夏令时自动挪槽），`record`/`report` 最后**记账**（真实会议入账，失衡亮红灯，退出码 3 可直接接 CI/巡检）。

**与近邻的边界**：[包场 · Full House](../full-house/) 算一场会值多少钱——人时×时薪的**总量成本账**，回答「该不该开、多贵」；本件算这个时刻惩罚谁——税点×基尼的**分配公平账**，回答「定几点、谁吃亏、能否轮换」。前者把会议当采购，后者把排会当分配；两本账可以记同一场会，互不替代。[社交时差 · Social Jetlag](../social-jetlag/) 管一个人的睡眠钟面（睡在钟面哪里），本件管一群人的会议钟面（把谁钉在钟面哪里）——一个是生理账，一个是排期账。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 timezone_tax.py inspect examples/team-global.json --utc 2026-09-10T15:00
```

## 命令速查

```bash
python3 timezone_tax.py inspect examples/team-global.json --utc 2026-09-10T15:00   # 这场会谁在缴税
python3 timezone_tax.py plan examples/team-global.json --start 2026-09-07 --weeks 12   # 未来 N 周轮换计划（可 --save 存账本）
python3 timezone_tax.py simulate examples/team-global.json --utc 15:00 --start 2026-09-07 --weeks 52  # 固定槽一年推演
python3 timezone_tax.py record examples/ledger-halfyear.json examples/team-global.json --utc 2026-09-14T15:00 --note "周会"  # 真实会议入账
python3 timezone_tax.py report examples/ledger-halfyear.json --team examples/team-global.json  # 账本汇总+告警（警报退出码 3）
python3 timezone_tax.py validate examples/team-global.json examples/ledger-halfyear.json   # 文件体检
python3 examples/build_examples.py    # 重建示例数据（确定性，逐字节一致）
```

团队配置长这样（夏令时由配置驱动，`MM-DD` 年度循环或 `YYYY-MM-DD` 绝对区间，不读系统时区表——换谁跑结果都一样）：

```json
{
  "members": [
    {"name": "Alice · 旧金山", "offset_min": -480,
     "dst": [{"from": "03-08", "to": "11-01", "offset_min": -420}]},
    {"name": "Dawei · 上海", "offset_min": 480}
  ],
  "waking": {"start": "07:00", "end": "24:00"},
  "workdays": [0, 1, 2, 3, 4],
  "grid_min": 30
}
```

## 一个真实样例

`examples/team-global.json`：旧金山/柏林/班加罗尔/上海四地团队。`inspect` 一场周四 15:00 UTC 的会：

```text
【税单】2026-09-10 15:00 UTC · Global Pod
  成员                本地时刻      税带    税点
  Alice · 旧金山     周四 08:00    清晨    1.5
  Bruno · 柏林       周四 17:00    黄金    0
  Chitra · 班加罗尔  周四 20:30    傍晚    1
  Dawei · 上海       周四 23:00    深夜    3
  合计 5.5 税点 · 最惨成员：Dawei · 上海
```

`simulate` 把 15:00 UTC 定死 52 周：上海缴 156、旧金山 78、班加罗尔 52、柏林 **0**——缴税基尼 0.43，最惨比率 ∞，警报。**这就是「没人抱怨却人人知道不对劲」的定量版**：柏林的 0 和上海的 156 躺在同一张表里。

`plan` 12 周给出更狠的真相：可行带里只有 14:00–15:30 UTC 四个格子，每个格子税单都是 5.5、缴税人都是同三人——

```text
【判定】警报
  · 结构性失衡：Alice · 旧金山、Chitra · 班加罗尔、Dawei · 上海 周周缴税，
    且候选槽里不存在能改变缴税人的格子——轮换无效，这是结构性税负。
  · 出路不在排会，在组织：拆会 / 降频 / 异步化。
```

唯一会动的是夏令时：第 9 周美国进冬令时，会议自动从 14:00 UTC 挪到 15:00 UTC——**税单分毫未动**。而旧金山+班加罗尔二人组则相反：冬令时让黄金时段回到旧金山，缴税人集合随季节变化，轮换判定变成「生效」。两种结局都由工具判定，不由感觉判定。`examples/team-impossible.json`（旧金山/柏林/奥克兰 + 09:00–18:00 核心时段）则直接判「无解」。这些埋进示例的已知答案全部钉死在验收测试里。

## 验收标准

每条标准都有对应的自动化测试（`python3 -m unittest discover -s timezone-tax/tests`，共 90 例）：

| # | 标准 | 测试 |
|---|---|---|
| A1 | 时间原语：偏移/跨日翻转（本地星期随之翻转）、美/欧夏令时、南半球跨年环绕区间、规则半开区间 [from, to)、`MM-DD` 年度与 `YYYY-MM-DD` 绝对两种写法、2/29 端点在平年收敛不崩 | `tests/test_time.py` |
| A2 | 税带：五处边界半开（07:00/09:00/18:00/22:00）精确落带；税率可配置且未覆盖键回退默认 | `tests/test_bands.py` |
| A3 | 税单：四地团队已知样例逐行精确；睡眠时段（含 24:00 翻转成次日 00:00）与非工作日标记原因且照常计税；全员零税时无最惨成员；自定义税率生效 | `tests/test_bill.py` |
| A4 | 公平度量：基尼在手算样例上精确到 1e-9（含全零/单人退化）；最惨比率 min=0 返回 None（渲染为 ∞）；判定阈值分级正确且可配置 | `tests/test_fairness.py` |
| A5 | 候选槽枚举：四地团队可行带恰为 UTC 14:00–15:30；grid 步长生效；无解团队返回空 | `tests/test_plan.py` |
| A6 | 补偿式轮换：注入候选槽钉死「最大累计→总税→更早」字典序与账本翻转行为；四地团队 12 周确定性、第 9 周随冬令时挪槽且税单不变；二人组季节性缴税人变化→轮换生效；单周不算结构性；无解周如实报告 | `tests/test_plan.py` |
| A7 | 账本：追加/汇总/团队补零成员；坏形状（非列表、缺 bills、税点非数字、坏 utc）校验**一次报全**；团队配置坏项聚合报错 | `tests/test_ledger.py` |
| A8 | CLI 端到端：六子命令输出节齐全；警报退出码 3、错误退出码 1；坏 UTC/缺文件/无 init 记账优雅失败；`plan --save` 产物可直接喂给 `report` | `tests/test_cli.py` |
| A9 | Dogfood：示例埋入的答案（周四税单、52 周累计 156/78/52/0、基尼 0.43、结构性失衡、无解判定）必须被工具原样挖出；示例生成器重跑与提交文件逐字节一致 | `tests/test_dogfood.py` |
