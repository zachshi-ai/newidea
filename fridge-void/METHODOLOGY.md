# METHODOLOGY · 冰箱黑洞

本文写清楚每个数字的口径、每个设计决定背后的取舍，以及这套账本「不做什么」。

## 1. 为什么是「结局」而不是「库存」

冷链管理类的产品都从库存切入：拍照记库存、识别食材、倒推保质期。这条路有两个致命伤：库存录入成本高到没有人坚持得过一个季度；保质期是印刷在包装上的**群体统计**，不是你家的冰箱——同样的菠菜， YOUR 冰箱的保鲜层和别人的不是同一个宇宙。

fridge-void 反着来：**不维护库存，只记录结局**。一次采购记一行，结局发生的那一秒记下它（扔的时候顺手记，反正你正拿着手机站在垃圾桶前）。这样账本的边际成本趋近于零，而它积累的恰好是最稀缺的数据：**你家自己的食物死亡记录**。保质期从不参与任何计算——死因由你标注，账本只负责让这五个字不至于白填。

## 2. 口径精确定义

### 2.1 结局状态机

```
            ┌──> ate      (吃掉,使命完成)
bought ─────┼──> gave     (送出,使命完成)
(open)      └──> tossed   (浪费,须注明死因)
```

- **open** 是唯一不参与浪费率的状态：它还没有表决。把它提前算成浪费是对一份还有救的食材的冤枉；把它算成「吃了」是自欺。账本让它继续待在 `pantry` 里排队。
- **gave 不是浪费**：食物的使命是被吃掉，不是被「你」吃掉。送人是转移，不是损失——这一条刻在口径里，是防止账本变成道德刑具：它审计的是黑洞，不是你的慷慨。

### 2.2 浪费率

```
waste_rate = Σ tossed.cost / Σ settled.cost      (settled = ate + gave + tossed)
```

金额是主口径（你关心的是钱）；重量是副口径（只对 `g`/`kg` 行计算，覆盖率披露在报告里——`ml`、`个`、`盒` 不做克数假设，不诚实换算不如诚实披露）。

样例：金额口径 23.8%、重量口径 25.7%（覆盖率 92.9%）——两个口径的差告诉你「便宜的东西死得更多还是更贵的东西死得更多」。

### 2.3 贡献分解恒等式

```
share_k = tossed_k / Σ settled            (k = 品类)
Σ share_k = waste_rate          (恒等式,测试钉到 9 位小数)
```

每个品类的贡献份额加总**恒等于**总浪费率——这不是近似，是分解的代数性质。它保证红黑榜是一个会计恒等式而不是排名表演：你看到的 66.4% 的绿叶菜 + 76.5% 的主食 + 100% 的乳品，加起来就是你 23.8% 的总黑洞。

死因结构同构：`Σ share_cause = 1`（分母是全部 tossed）。

### 2.4 浪费税

浪费率 r 的账本里，你花 N 元买进，吃到嘴的只值 N×(1−r)。于是：

```
real_price = 1 / (1 − r)
```

- 全账本 r = 23.8% → 每 1 元吃到嘴的食物实际花了 ¥1.313：**+31.3% 的个人通胀**。它不进 CPI，官方永远不会替你统计，但它精确地从你的钱包里流走。
- 品类级同理：绿叶菜 r = 66.4% → 标价 6 块的菠菜到你嘴边是 ¥2.97/元。**浪费税把「少扔点」从美德翻译成折扣**：把绿叶菜浪费率打到 30%,你的菠菜自动打 5.7 折。
- r = 100%（买过的每一克都扔了）→ INFINITE,不除零、不显示一个大数装精确——这个品类对你的真实单价就是无穷大,唯一诚实的读法是「别买了」。

### 2.5 年化

```
weeks = (max(bought) − min(bought)) / 7,下限 1 周
yearly_void = Σ tossed.cost / weeks × 52
```

用账本自己的跨度折算,不用真实时钟——同一本账在任何一天跑,年化数字逐字节一致。跨度不足一周按一周计,防止刚开账的账本算出天文数字吓人。

## 3. 死因学：五种死因,五种药

浪费不是一个问题,是五个问题。对策错配是「自律失败」的真正原因——你不是不努力,是你用减量的药治可见性的病。

| 死因 | 语义 | 它是什么问题 | 对药 |
|---|---|---|---|
| `spoiled` | 还没来得及吃就坏了 | **量的问题**:买进速率 > 消耗速率 | 减量、少囤、读懂自己的周均 |
| `expired` | 过了保质期,基本没动 | **动能问题**:买了就忘了它的存在 | 冷藏区「先进先出」,别让新买的挡住旧的 |
| `rejected` | 试过,不爱吃 | **黑名单问题**:口味不会因为价格改变 | `plan` 的硬闸,精确品名,一票否决 |
| `leftover` | 做多了,剩菜倒掉 | **手的问题**:烹饪量和饭量不匹配 | 煮饭减一手,或者学会吃隔夜饭 |
| `forgot` | 在冰箱深处发现,已坏 | **可见性问题**:冰箱是黑箱 | 整理冰箱、浅收纳、透明盒 |

样例账本的死因结构:spoiled 41.8% + rejected 34.3% = 76.1%——**减量和黑名单两件事覆盖四分之三的浪费**。注意 rejected 是唯一「重复发生且完全可预防」的死因:燕麦奶买了两次扔了两次,第二次 28 元是纯粹的信息费——你早就知道结局,只是没有人把证据摆到你下单的那一秒。`plan` 就是干这个的。

## 4. 红线、门槛与拒绝的权利

- **红线 15%**(可调 `--red-line`):中国城市家庭食物浪费率的研究估计多在 10–15% 区间,15% 意味着「每买 7 块钱扔 1 块」,超过它值得动用对策而不是自责。红线不是审判,是**触发讨论的阈值**——exit 4 让它可以进脚本、进 CI、进家庭会议的议程。
- **样本门槛 20 条**:10 条以内的浪费率纯属抽签(3 条 tossed / 10 条 = 30% 和 3 条 tossed / 20 条 = 15% 是同一个账本的两种运气)。不足 20 条,账本 exit 3 拒绝下结论——**宁可沉默,不出没有证据的报告**(与 slow-leak 的「宁可漏报不误报」同一血统:狼来了三次,账本就没人信了)。
- **重灾区的双门槛**:品类浪费率 ≥ 30% **且** settled ≥ 5 条才判 disaster——3 条里扔 2 条(66%)不配当重灾区,样本够了再说。
- **数据错误 exit 2**:坏日期、负金额、结局早于买进,一律拒绝装载。账本的第一美德不是聪明,是不会把坏数据悄悄算进结论。

## 5. 采购过闸的三档强度

`plan` 对购物车的三条检查,强度故意不等:

1. **黑名单 = 硬闸(exit 4)**:rejected 是你自己用真金白银投过票的结论,精确品名匹配(归一大小写与空白)。它拦的不是菠菜,是「再给它一次机会」的幻想——样例里那盒 2026-06-03 的燕麦奶已经付过一次 28 元学费,07-22 又付了一次,第三盒的学费应该是零。
2. **重灾区 = 横幅(不拦)**:品类级结论有统计噪音,且绿叶菜该不该买是你的饮食决定,账本只负责在你把第 15 把菠菜放进购物车时把 66.4% 这个数字举到你面前。
3. **总量 = 横幅(不拦)**:cart 总额 > 1.5 × 历史周均买进,提醒「冰箱是 shelf 不是 vault」——大宗采购是 spoiled 死因的头号来源。

**账本永远只拒绝一件事:让同样的浪费继续沉默。** 买不买、扔不扔、改不改,全是人的决定。

## 6. 确定性原则

- `pantry` 的「今天」= 账本内最大日期,不是系统时钟——账本是历史文档,不是实时仪表盘;同一本账在任何机器、任何时区跑出的报告逐字节一致,才配得上 `examples/build_examples.py --check` 的逐字节 CI。
- 全部浮点显示前不做隐藏舍入,金额统一两位小数、比率一位百分数——你在报告里看到的每个数字都能用账本原始数据手工复算出来。
- 贡献恒等式与死因恒等式有测试钉到 9 位小数:分解不是修辞,是会计。

## 7. FAQ

**Q:已有保质期提醒类 App,为什么还要手记账本?**
A:提醒产品回答「什么时候过期」,fridge-void 回答「你的黑洞在哪个品类、死于什么原因、每年值多少钱、下一单该拦下什么」。前者是闹钟,后者是决算。闹钟不解释为什么响了十次你还是扔——因为答案(死因结构)从来不在它的数据里。

**Q:忘记记结局怎么办?**
A:账本的诚实模型里,没记结局 = open = 还在架上。所以漏记的代价只是 pantry 里多一个躺着的老条目(DUE 灯会提醒你把它结算掉),**永远不会污染浪费率**——这是 open 不进分母的另一个理由。

**Q:和家人合账怎么记?**
A:一把账记全家:结局不分是谁扔的。责任归属是另一个问题,账本先回答「这个家一年扔掉多少钱」;如果家庭会议需要归因,那已经超出冰箱的范畴——contribution-gap(家务贡献)是更合适的工具。

**Q:浪费率多少算好?**
A:宏观研究的城市家庭食物浪费估计多在 10–15%;账本的默认红线 15%。但真正的基线是**你自己的上一季**——`ledger` 的趋势读法:红线是及格线,上一季是进步的刻度。

**Q:为什么不从银行流水/小票 OCR 自动建账?**
A:流水和小票只有买进,没有结局——而本件的全部价值都在结局那一列。结局只能由看见结局的人记录:这 0.5 秒的手工,就是账本全部的边际成本,也是它全部的可信度来源。
