# 超役 · Past Prime

> 家电是家里唯一「买下来就在倒计时」的资产：判废年限官方早就写好了——燃气
> 热水器 8 年、燃气灶 8 年（GB 17905-2008《家用燃气燃烧器具安全管理规则》
> 判废年限），洗衣机/电热水器/吸油烟机 8 年、电冰箱/空调 10 年（中国家用
> 电器协会《家用电器安全使用年限》）——但从没有任何账单把这个年限挂到每一
> 台电器头上。超役的燃气具挂在离洗澡水一米的地方；2017 年装修那批同批进门
> 的电器，正在同一年集体到站；而「坏了再说」的人，每一次都在为突发的大额
> 支出刷卡。记忆管不了十年后的事，账本可以。

## 一句话

把全屋电器抄成一本**一行一台的服役账**（品类/购入日/换新参考价/退役日），
对每台电器判出它在**判废年限**上的位置（OK / WATCH / DUE-SOON / OVERDUE，
涉燃气涉水涉电加热的**涉险台**超役单列红区），开庭四笔从没人替你算过的账：
**退休潮**（到站日在 730 天内聚簇的电器，会像波浪一样相继到站）、
**购入批次**（同年 ≥2 台——同批购入，同批到站）、
**家电退休金**（把 N 次财务事故变成一条月度预算线）、
**突击回放**（退役史里单年集中支出占全史的比例——「坏了再说」的价格）。

## 角色 / 场景 / 问题 / 价值

| | |
|---|---|
| **角色** | 2017 年前后装修过一次的城市家庭：那一年冰箱洗衣机热水器灶具油烟机同批进门，说明书早就扔了，电商订单要翻三层；每年冬天看到热水器事故新闻会心里一紧，然后想「我家那台才八年，应该没事吧」，继续洗 |
| **场景** | ① 洗澡时热水器点三次才着，你想「修还是换」，却连它买了几年都说不清；② 同一个月里洗衣机罢工、油烟机吸力归零，一年内第三次刷卡买家电——这不是运气，是十年前的购入批次集体到期；③ 翻到「燃气具判废年限 8 年」的新闻，想确认自家那台超没超，发现家里没有任何一个地方记着它的购入日期；④ 理财 App 能算基金定投，没有任何工具能回答「为了家电退休，我每月该存多少钱」 |
| **问题** | 1. **判废年限从没人挂到台上**：官方规则写好了年限（gb17905 是强制性的安全管理规则，协会线是行业共识），但铭牌贴在机器背面、说明书进了垃圾桶、订单藏在电商平台——年限与台子之间隔着三层考古<br>2. **同批老化不可见**：装修年的采购潮意味着十年后有一波集中的「退休潮」，逐台的直觉（「这台才用七年」）永远看不见波浪，每一次到站都被当成独立的坏运气<br>3. **支出是散点不是预算**：家电更换的财务冲击随机到站，突击换新的那一年现金流被打穿；退休金（sinking fund）是财务常识，却从来没有工具把「哪台哪年到站、换新多少钱」接成一条月度线<br>4. **涉险台没有红区**：燃气热水器/燃气灶超役不是「旧了费电」，是一氧化碳与泄漏问题；在一般的「家电老化」叙事里，涉险台和微波炉排同一个队 |
| **价值** | report 出全屋老龄化地图（四档判级 + 涉险红区 + 退休潮 + 购入批次 + 退役史反哺的个人节奏）；queue 出退休时刻表（每年谁到站、年预算多少）；fund 出未来 12 个月的每月退休金（超役台走快速通道，分摊 fen 级恒等）；simulate 钉死守恒（今天全换 == 按到站排队——退休金不创造钱，只搬移钱在时间上的位置）；energy 把实测 kWh 折成电费与超龄能效惩罚（assumed 先验口径，无实测 DECLINE）；validate 做判级完备/池构成/守恒/单调性/双算法体检。判废年限三级来源逐台标注（gb17905 / assoc2020 / folk），`--life` 一句话翻案——说明书与铭牌永远赢，本地价格永远赢；全部本地计算、不连任何接口；as-of 缺省 = 账本最大日期，`--as-of` 钉死后同一本账任何机器任何一天逐字节一致 |

## 验收标准

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 判级边界 | 剩余 **731/730/366/365/1/0/-1 天 → OK/WATCH/WATCH/DUE-SOON/DUE-SOON/OVERDUE/OVERDUE**，边界全部钉死（测试字面量） |
| 2 | 到站日日历口径 | 购入日 + N 年 = 第 N 个周年（2017-06-10 + 8 年 = 2025-06-10，不是 2922 天的近似）；2/29 购入平年落 2/28 |
| 3 | 示例账本钉值 | as-of 2026-09-05：14 在役 + 3 退役 + 1 无日期；判级 **OVERDUE 4 · DUE-SOON 3 · WATCH 5 · OK 2**；剩余天数逐台钉死（热水器 -452、洗衣机 -430、电热毯 61、净水机 220、冰箱 318、电视 432、空调 664、扫地机 715、加湿器 1593、微波炉 1718） |
| 4 | 涉险红区 | 燃气热水器 + 燃气灶超役 → **OVERDUE-SAFE ×2** 红区顶置、灯文指向燃气公司安检与品牌售后、明示「换与不换是人的决定」；电热毯（贴身电加热）DUE-SOON 也进涉险名单 |
| 5 | 来源三级标注 | 热水器/灶 `gb17905`、冰箱/空调/洗衣机/油烟机 `assoc2020`、微波炉/电视等 `folk`，逐台显示在「寿命·源」列；`--life 电热水器=12` 翻案后 source 变 `user`；行内 life_years 列为 `manual` 且赢过一切 |
| 6 | 先验垫底与翻案 | 未抄换新价的台用品类先验中位并标 `*`（微波炉 ¥500*、电热毯 ¥250*）；`--price 微波炉=666` 后翻成 666 且不再标 `*`；`--priors` 文件可整表覆盖并为表外新品类补先验（空气炸锅 4 年） |
| 7 | 退休潮聚簇 | 到站日 **恰 730 天同波、731 天裂开**；示例账本三波：**潮① 2025-06-10 ~ 2027-04-13（672 天）6 台（涉险 3）、潮② 2027-07-20 ~ 2028-08-20（397 天）6 台、潮③ 2031-01-15 ~ 2031-05-20（125 天）2 台**，聚簇构成对全部在役台的划分（3 潮 + 0 单飞 = 14） |
| 8 | 购入批次 | **2017 批次 5 台：4 台已超役、1 台 DUE-SOON**——同批购入，同批到站，report 原文钉死 |
| 9 | 退休金恒等式 | 未来 12 个月池 **¥13,950（7 台，超役快速入池 4 台）→ 每月 ¥1,162.50**；月摊按 fen 级最大余数法，Σ逐月 == 池**一分不差**（含 ¥100.01/¥0.03 等无理池的测试） |
| 10 | 守恒 | queue：已到站 ¥7,900 + 2026 ¥250 + 2027 ¥9,300 + 2028 ¥8,550 + 2031 ¥800 = **¥26,800 == 全池 == simulate replace-all 一次性总额**——A == B，退休金不创造钱 |
| 11 | 突击回放 | 退役史：旧冰箱 10.9 年、旧微波炉 10.0 年、旧洗衣机 8.3 年，中位 **10.0 年**（≥3 台才出统计）；**2017 年退役支出 ¥7,898（2 台）占全史 92.9%** → 突击点名；只有单年支出历史时不判突击（单年就是全史） |
| 12 | 双算法 | 剩余天数 timedelta 差 == 儒略日序数差（50 组随机日期对）；到站日重放一致；池构成两条独立循环一致；validate 全绿 |
| 13 | 单调性 | as-of + 1 天，任何台的判级指数不降（时间只往前走，判级永不回绿） |
| 14 | 别名归一 | 燃气热水器≡gas_water_heater≡燃气式热水器；冰箱≡fridge≡refrigerator≡电冰箱；洗衣机≡washer≡滚筒洗衣机；先验表外品类（空气炸锅）不猜寿命 → NEVER-PRIOR 点名，不进判级 |
| 15 | 无日期点名 | buy_date 留空 → NEVER-DATED，不入判级；涉险品类附「优先考古这张」提示 |
| 16 | 薄账分层 | 在役 0 台 → exit 3 且退役史/点名**照出**（算术不因薄账沉默）；在役 1 台超役照样亮灯 exit 4；退役史 <3 台时个人节奏 THIN、先验照用 |
| 17 | 账本合法性 | 未来购入日 / 退役早于购入 / 台名重复 / 日期非法 / life_years 出 1..50 带 → 全部 exit 2 |
| 18 | 零锚定可复现 | as-of 缺省 = 账本最大日期（示例 2026-01-15，热水器超役 219 天）；`--as-of` 钉死后同日两次运行**逐字节一致**；报告只打印 basename，不回显绝对路径 |
| 19 | energy 诚实 | 冰箱实测 52 kWh/月 × 0.55 元 = ¥28.60/月，对新机对照先验 24 kWh（assumed）年化惩罚 **¥184.80（五年 ¥924）**；账本无任何实测行 → DECLINE「不发明你的用电量」 |
| 20 | exit codes | report 有超役 → 4；全部在役期内 → 0；在役 0 台 → 3；账本/参数损坏 → 2；queue/fund/simulate/energy/validate 为视图命令恒 0（账本错误仍 2） |

## 快速开始

```bash
# 全屋老龄化地图：四档判级 + 涉险红区 + 退休潮 + 购入批次 + 退役史
python3 past_prime.py report examples/fleet.tsv --as-of 2026-09-05

# 退休时刻表：每年谁到站、年预算多少（--years 调视野）
python3 past_prime.py queue examples/fleet.tsv --as-of 2026-09-05

# 家电退休金：未来 12 个月每月存多少（超役台快速入池）
python3 past_prime.py fund examples/fleet.tsv --as-of 2026-09-05

# 反事实：今天全换 vs 按到站排队（守恒）；或单台再撑几年
python3 past_prime.py simulate examples/fleet.tsv replace-all --as-of 2026-09-05
python3 past_prime.py simulate examples/fleet.tsv keep 厨房燃气热水器 --years 3 --as-of 2026-09-05

# 实测 kWh 折电费与超龄能效惩罚（assumed 口径，无实测 DECLINE）
python3 past_prime.py energy examples/fleet.tsv --as-of 2026-09-05

# 账本体检：判级完备 / 池构成 / 守恒 / 单调性 / 双算法
python3 past_prime.py validate examples/fleet.tsv --as-of 2026-09-05

# 测试
python3 -m unittest discover -s tests
```

## 账本格式

TSV，一行一台，表头固定；`#` 开头的行忽略。

| 列 | 必填 | 说明 |
|---|---|---|
| `item` | ✓ | 台名（唯一键，重复 exit 2） |
| `category` | ✓ | 品类（中英别名归一；先验表外不猜寿命，进 NEVER-PRIOR） |
| `buy_date` |  | 购入日 YYYY-MM-DD（留空进 NEVER-DATED；晚于 as-of exit 2） |
| `price` |  | 当年购入价（元，仅展示） |
| `replace_cost` |  | 今日换新参考价（元；留空用品类先验中位并标 `*`；退役台上语义为**当年换新支出**，进突击回放） |
| `retired_date` |  | 退役日（留空 = 在役；早于 buy_date exit 2） |
| `kwh_month` |  | 实测月均用电（energy 用；无实测 DECLINE，不发明） |
| `life_years` |  | 行内寿命覆盖——说明书/铭牌口径，**赢过先验与 `--life`** |
| `note` |  | 备注 |

参数：`--as-of` 锚定日期（缺省=账本最大日期）· `--life CAT=年` 覆盖品类寿命 ·
`--safe CAT` 追加涉险品类 · `--price CAT=元` 覆盖换新参考中位 ·
`--priors FILE` 整表覆盖先验 · `--years N` 排队视野 · `--price-elec` 电价。

## 判级与门禁

- 四档：**OK**（剩余 >730 天）→ **WATCH**（≤730）→ **DUE-SOON**（≤365）→ **OVERDUE**（≤0，即超役；到站当天即超役，边界钉死）。
- **涉险台**（燃气热水器/电热水器/燃气灶/电热毯，`--safe` 可追加）：超役顶置红区 OVERDUE-SAFE，灯文指向燃气公司安检与品牌售后——**账本不下检修结论，换与不换是人的决定**。
- 门禁只看 `report`：任一台 OVERDUE → exit 4；其余命令是视图，恒 exit 0（账本错误 exit 2、在役 0 台 exit 3）。

## 与近邻的边界

- **odometer-illusion**（双钟）：那边管**保养周期**（机油每 5000 km/6 个月——为延缓衰老做的维护，车还在服役期内），本件管**整机判废年限**（衰老本身的终点）；那边的机器坏了进 repair-ledger 裁决，本件的机器到站进 queue 排队。
- **repair-ledger**（续命账）：那边是**故障当下**的单台修/换裁决（边际每服务年成本），本件是**故障之前**的全屋队列管理（谁快到站、退休金每月存多少）；本件不碰维修报价，那边不问批次波浪。
- **expiry-cliff**（到期悬崖）：那边管**凭证的失效**（护照/保单/域名——纸会过期，答案办一张新的），本件管**实物的判废**（机器会老，答案是预算一条线）；那边有提前量（提前 46 天去办），本件有快速通道（超役台不等你攒满）。
- **dusty-subs**（吃灰订阅）：那边是持续付费（每月扣款，敌人是惯性），本件是一次购入（十年一换，敌人是遗忘）；共同点是「支付与使用的解耦」。
- **slow-leak**（暗漏）：那边用量蠕升是连续信号（逐月 3% 肉眼无感），本件年龄到站是离散跳变（周年那天它就超役了）；一个查「用得多」，一个查「活得久」。
- **safety-floor**（兜底）：那边审保单的保额够不够（出事那天接不接得住），本件审家电的年限超没超（洗澡那分钟安不安全）——都是「存在 ≠ 够」。

## 诚实条款

- **判废年限是先验不是预言**：gb17905 是强制性安全管理规则（燃气具 8 年），协会线是行业共识（2020），folk 是通识先验——三级来源逐台标注；说明书与铭牌永远赢（行内 `life_years`），`--life` 一句话翻案，`--priors` 整表翻案。
- **换新参考价是先验中位**：标 `*` 的行不是你买到的价；本地价格永远赢（`replace_cost` 列、`--price`）。账本不联网、不促销、不预测涨价。
- **没有日期就不装知道**：NEVER-DATED 不入判级，只点名——发票、电商订单、铭牌 serial 都记得它的生日，考古是你的事。
- **先验表外不猜寿命**：NEVER-PRIOR 只点名不判级，给出翻案参数。
- **energy 只认实测**：kwh_month 是电表读数不是估算；新机对照是 assumed 先验，「换新省多少」账本不承诺。
- **它不下检修结论**：超役燃气具的灯指向燃气公司安检与品牌售后；何时换、换什么、花多少钱，永远是人的决定。账本只拒绝让「判废年限」继续沉默。
