# 窗期 · Border Budget

> 滚动窗口里的每一天都在花同一笔 90 天的预算，而窗口从不显示余额——海关数的是章，从来不是你的账。
> Every day inside the zone spends the same rolling 90-day budget, and the border counts stamps, never balances.

## 一句话

短期签证的停留规则是一条滚动窗口——**任意回看的 180 天里累计停留不得超过 90 天，入境日和离境日都算**——这是一笔每天都在花费、每天都在缓慢回血的预算，但护照上只有章：没有余额、没有恢复日程、没有「最晚离境日」。凭感觉订票的人（「上次才去两周，这次一个月应该没事」）就是在掷骰子，掷输的代价是落地当场拒入境。`border-budget` 把「窗期」补进账本：每次停留记一行（TSV 手编：入境/离境/区域/备注），确定性算出七本账——**余额账**（`balance`：今天窗口已用 83/90、剩 7 天；但今天就走可以连住 15 天，因为 3 月的那段停留正从窗口尾部每天滑出——**余额和可住天数是两个数字，回血就住在它们的差里**）；**释放日程**（额度哪天回血、回几天：「09-11 到 09-18 每天回 1 天，spare 回到 15」）；**行程过闸**（`check`：那趟订好的 10-02..10-15 秋游贴线通过——峰值 89/90，**只剩 1 天的余量**；而贪心版本 10-02..11-13 峰值 104/90 超 14 天，最晚离境日 10-30，一个 29 天的行程仍装得下——它不给一句「不行」，给的是能落地的最晚出口）；**反解**（`when --days 30`：想要 30 天完整额度，最早 11-30 出发——从今天起要等 85 天，**等的就是窗口本身**；真无解时诚实说「730 天内没有这样的日子」而不是硬造一个日期）；**排期门禁**（`gate`：全部已订行程逐段过闸 + 未来 365 天窗口峰值预演，票已买就占额度，窗口不赊账）；**停留档案**（`history`：每次行程天数、离境那天的窗口占用、全史峰值——你离超限最近的是哪一天）；**反事实**（`simulate cancel`：取消秋游后，今天的余额不变（历史无法取消），但未来一年的窗口峰值从 89 掉回 83——取消不动过去，松动的是未来）。口径钉死：双算法恒等式（逐日累计 == 逐段裁剪）在 validate 里对账；`--today` 显式参数让同一本账任何机器任何一天跑出逐字节一致的结果；离境留空的未闭合行程只计到今天并在 validate 披露。工具是计算器不是律师：逾期后果不建模，窗口参数（`--window/--quota`）可调成其他地区的口径——**它只回答「还能待几天」，不回答「该不该超」**。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 在滚动停留规则下出行的人——一年去几次欧洲的旅行者、跑多国客户的商务人士、在申根区里长住短住交替的数字游民；以及每一个订票前对着护照上的章发呆、试图在脑子里模拟 180 天滑动窗口的人。 |
| **场景** | 订机票前想知道「10 月去三周、12 月再跨年还行吗」；在值机柜台被问「你过去 180 天在区内待了多少天」而答不出来；看着官网计算器一页一页手输出入境日期，算完这一趟，下一趟又得重来；行程想改长一周，不知道到底能不能改。 |
| **问题** | **额度没有余额显示**：① 滚动窗口不能心算——任意一天的占用 = 过去 180 天里每次行程的重叠拼接，人脑做不了这个滑动求和；② 「余额」和「可住天数」是两个数字——窗口尾部的旧行程正在滑出，今天出发能住的天数大于剩余额度，这个差从来没人告诉你；③ 最晚离境日不存在——改签延住时，没人告诉你这趟到底能延到几号；④ 已订的票也在吃额度——凭据上没写，窗口里已经扣了。 |
| **价值与意义** | 1) **余额第一次有读数**：`balance` 每天一句话——用了多少、剩多少、今天就走能住几天、额度哪天回血；「凭感觉」变成「看余额」。<br>2) **订票前过闸**：`check` 把行程对窗口逐日核对，SAFE 给余量、OVER 给最晚离境日和能装下的天数——改签谈判桌上有数字。<br>3) **贪心的代价可量化**：同一趟秋游，14 天贴线 89/90，43 天超限 14 天——「多住 29 天」的代价不是罚款金额，是「根本进不来」，提前 43 天就知道。<br>4) **等待期有解释**：`when` 把「现在去不了」翻译成「11-30 就能去」——等的是哪段旧行程滑出、哪天释放多少，窗口第一次有了恢复日程。 |

## 核心思想：额度是一笔滚动预算，账本负责显示余额

90/180 的全部数学是一条规则：对任意一天 D，窗口 [D−179, D] 内的停留总天数 ≤ 90（入境日与离境日均计）。`border-budget` 在这条规则上盖了七本账：

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **占用 used(D)** | 窗口 [D−179, D] 内的停留天数；行程重叠按并集计（同一个人不能被算两次在区内） | 「此刻窗口里有多少天是我的历史？」 |
| **余额与可住** | spare = quota − used(today)；walk = 从今天贪心可连住的天数——两者差 = 窗口尾部正在回血的旧行程 | 「今天还能不能走、能走多久？」 |
| **释放日程** | 未来逐日 used 的下降点聚合成区间：「XX 起每天回 N 天」——旧行程滑出窗口的那一天，额度回来 | 「额度什么时候回血？」 |
| **行程过闸** | 行程每一天的窗口峰值（行程自身计入）；SAFE 给余量；OVER 给第一破线日 + 最晚合法离境日 + 能装下的行程长度 | 「这趟票能不能订？」 |
| **反解 when** | 最早的出发日 s 使得连住 N 天的每一天都 ≤ quota；730 天内找不到就如实说无解 | 「想要 N 天，最早哪天走？」 |
| **排期门禁 gate** | 已订（entry 在未来）的行程逐段过闸；未闭合行程按占用到今天审；未来 365 天逐日峰值预演 | 「订好的票会不会自己爆掉？」 |
| **双算法恒等式** | 逐日累计（occupied 集合计数）== 逐段裁剪（每段与窗口求交再求和）——validate 钉死两者相等 | 「这本账配不配得上结论？」 |

三条边界刻在实现里：

- **票已买就占额度**——账本里的未来行程同样进入 used 的计算，窗口不赊账也不透支；`gate` 审的就是这些已经扣款的占位。
- **未闭合行程是唯一的猜测**——离境留空表示人还在区内，占用只计到 `--today` 为止，`validate` 单独披露；账本其余每一行都是章上的事实。
- **计算器不是律师**——入境离境双计日、180/90 的口径可调（`--window/--quota`），但逾期后果、移民官自由裁量、各国特殊规则一概不建模；它回答「还能待几天」，不回答「该不该超」。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 border_budget.py --today 2026-09-06 balance trips.tsv
```

## 命令速查

```bash
python3 border_budget.py balance  trips.tsv                        # 余额：83/90，今天就走能住 15 天 + 释放日程
python3 border_budget.py check    trips.tsv --entry 2026-10-02 --exit 2026-10-15   # 贴线通过：峰值 89/90
python3 border_budget.py check    trips.tsv --entry 2026-10-02 --exit 2026-11-13   # 超限：exit 4，最晚离境 10-30
python3 border_budget.py when     trips.tsv --days 30              # 反解：最早 11-30 出发，等 85 天
python3 border_budget.py gate     trips.tsv                        # 全部已订行程过闸 + 365 天峰值预演
python3 border_budget.py history  trips.tsv                        # 停留档案 + 全史峰值
python3 border_budget.py simulate trips.tsv cancel --match autumn  # 反事实：取消秋游，峰值 89 -> 83
python3 border_budget.py validate trips.tsv                        # 账本体检：双算法恒等式 + 未闭合披露
```

全局参数：`--today YYYY-MM-DD` 钉死「今天」（快照可复现）；`--region`（默认 schengen，各区域各记一本账互不污染）；`--window/--quota`（默认 180/90，可调成其他地区的口径）。

## 账本格式（可手编 TSV，一次停留一行）

```text
entry	exit	region	note
2026-07-02	2026-07-22	schengen	july long stay
2026-09-01	2026-09-05	schengen	top-up
2026-10-02	2026-10-15	schengen	booked autumn
```

- 日期 `YYYY-MM-DD`；入境日与离境日**都算停留日**（申根口径）。
- `exit` 留空 = 未闭合（人还在区内），只计到 `--today`，`validate` 披露。
- 未来行程正常记入（票已买就占额度）：`balance`/`gate` 计入，`history` 只看已闭合的。
- 从护照章或入境记录抄写即可；离境早于入境、同一区域两段重叠（一个人不能同时两次入境）都是账目腐败，exit 2。

## 验收标准（全部转为自动化测试，46 个）

1. **解析守卫**：表头校验、坏日期、离境早于入境、空 region 默认 schengen、注释行跳过、文件缺失——exit 2；乱序输入按入境日排序。
2. **窗口口径**：入境离境双计日（1 天行程 = 1 天占用钉死）；窗口 = [D−179, D] 闭区间；90 天连续停留的窗口峰值恰好 90。
3. **双算法恒等式**：逐日累计 == 逐段裁剪，样例账本 83 == 83 钉死。
4. **余额账**：used/spare 精确（83/7）；**回血可住 > 余额**（spare 7 天但今天就走能住 15 天——窗口尾部滑出的旧行程计入贪心）；释放日程按「连续同速」聚合成区间；空账本 0/90 全额度。
5. **行程过闸**：SAFE 给峰值与余量（89/90 贴线）；OVER 给第一破线日（10-31）、超限天数（14）、最晚合法离境日（10-30）与可装下行程（29 天）；与已订行程重叠按并集计并披露 NOTE；一年前的入境拒绝审计（归 history）。
6. **反解 when**：`--days` > quota exit 2；最早出发日钉死（30 天 → 11-30，等 85 天）；周期性行程让 90 天永不可行时 exit 3 诚实拒答（候选行程吞并重叠段按并集计，构造需绕开该语义——测试注释里写明）。
7. **排期门禁**：无已订行程 exit 0；贴线 SAFE exit 0；超限 BREACH 列明最晚离境 exit 4；`--window/--quota` 自定义口径生效。
8. **档案与反事实**：history 列出每次行程天数与离境时占用、全史峰值；simulate cancel 精确给出「今天余额不变、未来峰值 89→83、今天可住天数不变」三种影响并注明原因；按备注或日期匹配，无匹配 exit 2。
9. **区域隔离**：混合账本各区域各记各的窗口（uk 15 天 ≠ schengen 83 天），互不污染；无该区域 exit 2。
10. **exit 语义与可复现**：0 正常 / 2 账目或用法错误 / 3 无诚实答案（无解、参数荒谬）/ 4 超限；`--today` 钉死分段，同一账本跨机器跨日期输出字节一致（examples 快照 CI 校验）。
