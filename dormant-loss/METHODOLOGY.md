# METHODOLOGY · 躺亏 · Dormant Loss

## 1. 一句话

定期存款的合同利率只在期限内兑现,到期之后银行的默认动作接管价格——本件把存单抄成账本,把利率画成时间线,把「沉默=活期」的每一次翻译折成躺亏,让你在银行推送「已到期」的那一刻就知道自己每年少拿多少。

## 2. 为什么是账本

存款是中国家庭最大的单一资产,也是唯一**所有人都以为自己在管、实际上没有人管**的资产:余额有 App,到期有推送,但「这笔钱现在按什么利率在跑」没有一页给出答案。银行是唯一知道你利率掉档的人,而它不通知——**通知到期是合规,翻译掉档不是义务**。更根本的一层:贷款有人替你算(等额本息、提前还款都有现成工具),存款端是空的,因为存款的损失不是一笔支出,而是「没拿到的利息」——它不出现在任何流水里,只出现在两条利率的差里。

抄一笔存单一行(银行/本金/利率/期限/存入日),到期后的故事只记「发生了什么」(转存/取走)——这是全部数据工程。换来的是:爸妈五家银行的纸质存单有一本总账、利率六连降的每一步都留痕、不连任何系统、字节级可复现。

## 3. 核心模型

### 3.1 利率时间线(翻译层)

一笔存款的利率是**阶梯函数**:[存入日, 到期日) 兑现合同价;之后由事件流重放——renew 段兑现转存价(它有自己的期限,到期后同样进入下一轮),withdraw 截断一切,而**两段之间的空白自动按活期补齐**。「沉默就是活期」是这个模型的核心断言:到期不办,银行按最低价续算,这不是惩罚条款,是默认语义——所以账本只需要记主动发生的事,空白本身就是信息。到期日几何与月龄钟同源:对月对日、月末钳制、从原始 day 每次重算不链式累积(1-31 存 +1 月到期 2-28,再 +1 月是 3-31 不是 3-28;闰日 2-29 存 60 月到期钳到平年 2-28,存 96 月保留 2-29)。

### 3.2 躺亏的锚(算术层)

躺亏 = Σ 各段 本金 × (原合同利率 − 段利率) × 段天数 / 365。**锚定原合同利率**是方法论上最关键的决定:它让账本零外部先验——不预测市场、不引入「现在能存多少」的行情,只回答「这笔钱比它曾经值的少拿了多少」(the ledger is the manual)。机会成本是另一个问题:decide 用你抄来的真实报价(--rate)做两世界对拍,不给报价就不判。两种计息基如实分开:定期段利息按月基(银行整期算法),活期段按天基,躺亏统一天基——月基与天基的差如实披露,由容差与诚实条款兜底,不假装精确。

### 3.3 状态桶与灯(判级层)

五桶:在保(合同期内)→ 躺活期 → 转存存续 → 已取走 → 提前支取。四盏灯各管一种病:🔴 SLEEPING-DEMAND(躺活期的钱,双闸:本金超线**或**年化超线)、🟡 RESET-DOWN(转存降档超 0.25pp——「转存了」不等于「安全了」)、🟡 EARLY-TAX(提前支取税)、🔵 PRIME-HOLD(老合同稀缺,锁住它)。全部恰线不亮:双闸用严格大于,RESET/PRIME 用严格大于——红灯的信用留给真正的躺亏。PRIME 的前提是「在保」:一笔 3.575% 的存单如果已经躺进活期,它不是稀缺资产,是已经凉了的资产——稀缺性属于合同,不属于钱。

### 3.4 时间机器(取证层)

as-of 截断语义:未来存单与未来事件是「还没写下的未来」,排除并披露,不是账坏。提前支取在 as-of 之前未发生时,合同就还在保——支取的后果是事件日之后才展开的历史。样例钉回 2024-05-09(工行到期前一天),躺亏只剩 ¥585.62:大额躺亏全是之后两年半的沉默,**欠的利息不会自己消失,但它是可以不再继续的**。

## 4. 与直觉的三处对决

1. **「转存了 = 安全了」是错的。** 自动转存进的是转存日的挂牌价——利率下行通道里,这一转就是腰斩(2.60% → 1.35%)。转存解决的是「别躺活期」,解决不了「价格是你定的还是银行定的」。RESET-DOWN 灯把转存过的存单继续点名。
2. **「钱没少 = 没损失」是错的。** 存款到期一分不少,少的全部走在两条利率的差里——它不进流水、不弹通知、不影响余额,所以没有任何「对账单」会显示它。躺亏是只存在于对照里的损失,这正是需要一本账的原因。
3. **「提前支取差几天无所谓」是错的。** 提前支取按活期重算的是**全部存期**的利息,不是「提前的那几天」。EARLY-TAX 灯把这笔税立在历史里;PRIME-HOLD 灯则提醒:在利率下行的年代,「别动那笔老存单」比「多抢 0.1% 新利率」更值钱。

## 5. 开发中自纠(测试价值记录)

1. **as-of 恰等于存入日的存单崩了**:build_segments 用 `as_of <= start` 返回空段,state_of 查 FUTURE 灯名 KeyError。边界是:存入当天它在保(0 天合同段),不是未来。边界语义要按「钱的状态」定,不按「程序方便」定。
2. **手算连输,程序全对**:邮储躺亏手算 4,156.49,程序 4,156.60(2820×538/365,心算乘法错);建行 realized 手算 4,037.44,程序 4,037.40(638 天活期利息);decide 翻案年化手算 10,300,程序 10,335(邮储利差 2.575pp 写成 2.525)。「程序三连对、手算三连错」系列再添一笔——关键数字一律独立手算对拍后钉进测试。
3. **as-of 截断与事件校验打架**:初版在 build 层边走边校验,未来 renew 事件会产生负天数段。重写为两层:载入层做全史一致性校验(存续期转存/取走后再动/同日二义,与 as-of 无关的账坏当场拦),build 层只做 as-of 截断(未来排除并披露)。校验是账的体检,截断是视角的选择,两件事不能混在一个循环里。
4. **GHOST 容差测试先打脸了自己**:造的「抄错」差 100,落在 0.5% 容差(21527.95×0.5% = 107.64)内,validate 绿灯通过——容差是有意设计(银行闰年/结息细节),不是 bug。要造 GHOST 得差 300。测试造数据必须先过容差这一关,否则验的是容差不是验钞。
5. **PRIME 灯一开始想给「利率高」的所有存单**——被自己的翻案测试抓住:邮储 3.575% 但已躺活期,不进 PRIME。「稀缺资产」的前提是「还在合同期内」;躺平的老合同只剩躺亏,没有稀缺性。
6. **恰线语义统一钉死**:红双闸、RESET、PRIME 全部「严格大于才亮」。恰线不亮不是宽容,是让每一盏红灯都可辩护——宁少报,不冤枉。

## 6. FAQ

- **银行 App 有到期提醒,为什么要手抄?** 它通知「到期了」,不翻译「少了多少」;自动转存的推送从不附对账。提醒是银行的义务,翻译掉档不是——本件做的正是翻译。
- **爸妈的存单是纸质的,连 App 都没有?** 那正是第一用户:替爸妈管存单的人。纸质单据上本金/利率/期限/存入日齐全,抄一笔一行;到期后发生了什么,问一句爸妈或打个电话,记进 renewals。
- **利率一直在降,转存了也会再降,记账有什么用?** 账本不预测利率,它只陈述两件事:已经发生的掉档(躺亏在册),和正在发生的速率(每天 ¥42)。锁不锁、什么时候锁,decide 摆出两世界的差,决定是你的。
- **大额存单可以转让,靠档计息怎么办?** 不建模。转让价差、靠档规则写进 note,realized 容差兜底——账本宁可留白,不编算术。
- **躺亏锚为什么不是「现在的新存利率」?** 零外部先验:账本内部只有「这笔钱曾经值的价格」是硬的。要算机会成本,decide --rate 把你抄来的报价请进来——先验是参数,不是断言。

## 7. 诚实条款(与 README 第七节同源)

活期利率与各灯线是通识先验,全参数翻案,银行挂牌永远赢;定期月基/活期天基如实分开,不建模滚存/靠档/部分提前支取,realized 容差兜底;不预测利率,decide 只对拍你抄来的报价;不构成投资建议,红灯指向银行柜台,这是利率账不是风险账;沉默=活期是通识默认,约定转存以存单为准;抄错当场 GHOST;存款是家庭最敏感的数字之一,不连任何接口不上传任何字节;零墙钟,as-of 缺省锚定账本最大日期,同账任何机器任何一天逐字节一致。
