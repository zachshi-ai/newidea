# 漏带时刻 · Left Behind

> 漏带不是在机场发生的，是装箱那一刻就注定的——而通用清单是「平均人」的清单，它不记得你上次忘了什么。
> A zero-dependency CLI that turns your trips into a calibration loop for your packing list: it remembers every left-behind and every ghost you hauled for nothing, flags what you systematically forget, and packs the next bag from evidence instead of memory.

---

## 一句话

每次出发前夜，你对着空箱子和手机里搜来的「出差必备清单」——那张清单是写给**平均人**的，它不知道你上个月刚把充电头忘在北京，也不知道那把伞陪你去过三个城市、淋过零场雨。漏带的懊恼和悔带的重量从没被结构化记录过，于是同一个错误以稳定的概率反复发生：**清单从不学习，全靠你的大脑硬扛**。`left-behind` 把每一次行程变成一次清单校准实验：回家后花一分钟，把这次**漏带的**（到了现场才补救的）和**白扛的**（原样往返一次没用的）记成一行账。账本随后算出四样东西：你的**盲区**（同一物品漏带 ≥2 次——漏一次是意外，漏两次是模式）、你的**幽灵货物**（反复白扛的重量）、你的**补救账单**（漏带现场采购花了多少冤枉钱），以及最要紧的——**收敛趋势**：前半程 vs 后半程的漏带率，回答「你的清单到底有没有在从错误里学习」。最后用 `pack` 命令生成下一张装箱清单：基线模板按天数缩放，你的盲区置顶警示，惯犯幽灵被降级到「想清楚再带」。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 每月出差 2 次以上的商务差旅者（「我又忘带充电头了」）；包揽全家行李的「行李总管」；两地往返的双城族。共同点：装箱频次高、清单靠回忆、错误在重演。 |
| **场景** | 出发前夜对着空箱发呆，不知道从哪收拾起；到达后发现漏带，在机场/酒店以恐慌价补救；回家开箱，一半东西原封不动——但下次装箱时，这些教训全都想不起来。 |
| **问题** | **清单没有反馈回路**：① 通用清单模板是「平均人」的清单，你的系统性盲区（总漏的那几样）它一无所知；② 上次漏了什么、多带了什么，反馈散落在懊恼里，从未落账——错误没有沉没成本，就会重演；③ 没有任何指标回答「我的装箱水平在变好吗」——漏带率十年如一，却从没人量过。 |
| **价值与意义** | 1) **错误变账本**：漏带（left）与白扛（ghost）从此有了结构化记录，和补救成本、白扛克数——懊恼第一次变成了可分析的资产。<br>2) **盲区现形**：同一物品漏带 ≥2 次自动标记为盲区并置顶到下次清单——漏一次是意外，漏两次是模式，而模式是可以修的。<br>3) **清单从证据生成**：`pack` 输出 = 基线模板（按天数缩放）+ 你的盲区警示 + 你的常备物品 + 幽灵降级区——「平均人的清单」被你的数据逐条修正。<br>4) **收敛可测量**：前半程 vs 后半程漏带率给出唯一重要的元指标——清单有没有在迭代。不降反升时账本会直说。<br>5) **零依赖 + 纯本地**：Python 3.8+ 标准库，一个 TSV 就是全部数据库，不联网不上传，手机备忘录/表格软件都能直接编辑。 |

## 核心思想：错题本 → 盲区/幽灵/收敛 → 下一张清单

数据模型是一张人类可直接编辑的 TSV 表，**一行 = 一个「物品 × 行程」事件**——只记值得记的：漏带的、白扛的，以及作为画像对照的「带了且用了」。

| 概念 | 定义 | 回答的问题 |
|---|---|---|
| **漏带事件（left）** | 到了现场才需要采购/借用/将就的物品，记补救成本 | 我的清单哪里有洞？ |
| **幽灵货物（ghost）** | 装了箱、原样往返、一次未用的物品，记重量 | 我为哪些「万一」付着运费？ |
| **盲区（blind spot）** | 同一物品漏带 ≥2 次（`BLIND_SPOT_AT`） | 哪个洞是模式性的，不是意外？ |
| **惯性悔带** | 白扛 ≥2 次的物品（`GHOST_DEMOTE_AT`） | 清单里哪些是仪式感部门？ |
| **补救账单** | Σ 漏带现场采购成本（未记价的单列计数） | 我的恐慌价一共交了多少？ |
| **收敛（convergence）** | 前 n/2 次 vs 后 n/2 次行程的漏带率 | 清单到底在不在学习？<4 次行程拒绝评估 |
| **行程画像（profile）** | 按行程类型聚合的事件分布 | 出差清单和度假清单不该长一样 |

`pack` 生成的下一张清单有四个区：**【先摸口袋】**盲区置顶警示（带行程号与日期）；**【基线】**内置通用模板、消耗品按天数缩放（内裤袜子 = 天数+1，封顶 10）；**【你的常备】**该类型行程中出现 ≥2 次（`PACK_USED_MIN`）的「带了且用了」物品；**【想清楚再带】**惯性悔带降级区（`--all` 可强制恢复，但账本会把白扛史写在你脸上）。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 left_behind.py analyze examples/realistic.tsv   # 完整错题本报告
```

## 命令速查

```bash
python3 left_behind.py analyze examples/realistic.tsv              # 报告：总览/盲区/品类/幽灵/补救账单/收敛
python3 left_behind.py analyze examples/realistic.tsv --type leisure  # 只看度假行程的账
python3 left_behind.py pack examples/realistic.tsv --type business --days 3  # 生成下次装箱清单
python3 left_behind.py pack examples/realistic.tsv --all           # --all：不降级幽灵物品
python3 left_behind.py validate examples/minimal.tsv               # 账本格式体检
python3 examples/build_examples.py                                 # 重建示例数据（确定性剧本）
```

你自己的账本：十列 TSV（表头固定、列序随意），`#` 开头是注释，一行一个「物品 × 行程」事件——

```text
date	trip_id	trip_type	days	item	category	event	cost	weight_g	notes
2026-04-08	T003	business	4	手机充电头	electronics	left	89	酒店前台借了一夜，第二天机场买的
2026-03-18	T002	business	2	雨伞	misc	ghost		350	深圳没下雨
```

`event` 三态：`left`（漏带，cost 记现场补救花了多少钱）、`ghost`（白扛，weight_g 记它让你白扛了多少克）、`used`（带了且用了，cost/weight 留空）。cost/weight 可留空——未记价的漏带照样计数，只是不进补救账单。

## 一个真实样例

`examples/realistic.tsv`：12 次行程（business×7、leisure×5）、35 条事件，确定性生成，**埋入了已知模式**——充电头漏带 2 次（electronics 重灾区）、雨伞白扛 3 次、健身裤白扛 2 次、前半程漏 5 件/后半程漏 2 件（在改善）、名片漏带未记价。工具的报告：

```text
【总览】
行程 12 次（business×7, leisure×5），2026-03-02 ~ 2026-08-29
漏带率 0.58 件/次（7 件）；幽灵率 0.58 件/次（7 件）
幽灵货物累计白扛 2.1 kg
补救账单 ¥279（另 1 件漏带未记价，不进账单但计入漏带数）

【盲区】漏一次是意外，漏两次是模式
 1. 手机充电头（electronics）：漏带 2 次，累计 ¥158  ← 重犯
    上次：2026-07-08（T006）

【品类分布】漏带重灾区
 electronics  ████████████ 2（¥158）
 health       ████████████ 2（¥57）
 ...

【幽灵货物】原样往返的重量
· 雨伞：3 次白扛（1.1 kg）
· 健身裤：2 次白扛（800 g）
 ...

【收敛】清单在迭代吗
前 6 次行程漏带率 0.83 件/次 → 后 6 次 0.33 件/次：在改善
```

埋进去的充电头盲区登顶、雨伞三连幽灵被点名、收敛方向被正确判读为「在改善」——**账本挖出的是模式，不是情绪**。验收测试把这些「已知答案」钉死成了断言。

## 验收标准

每条标准都有对应的自动化测试（`python3 -m unittest discover -s left-behind/tests`，共 74 例）：

| # | 标准 | 测试 |
|---|---|---|
| A1 | TSV 解析：表头校验、列序随意、注释/空行跳过、坏行汇总一次报全（带行号）、event 三态枚举、days≥1、date 合法、cost/weight 非负、同 trip_id 的行程元数据冲突必须报错 | `tests/test_parsing.py` |
| A2 | 行程账本：按 trip_id 聚合为行程；漏带率/幽灵率/补救账单在已知账本上精确；未记价的漏带计入漏带数、不进账单、单独呈报 | `tests/test_ledger.py` |
| A3 | 盲区：同一物品漏带 ≥2 次触发、按（次数，累计成本）排序、给出最近一次的行程号与日期；只有 1 次的不得误报 | `tests/test_ledger.py` |
| A4 | 幽灵货物：按（次数，累计重量）排行、重量汇总 kg 换算精确、未记重的计数呈报；零幽灵时诚实输出而不是空指针 | `tests/test_ledger.py` |
| A5 | 收敛：已知构造下前半 > 后半判「改善」、反向判「不降反升」并告警、相等判「持平」；<4 次行程拒绝评估趋势；奇数行程时中位行程不参与任何半程 | `tests/test_convergence.py` |
| A6 | 清单生成：基线模板消耗品按 days 缩放（days+1、封顶 10）、耐用品恒定；盲区置顶带行程号；常备区只收该类型 used≥2 的物品；ghost≥2 降级且 `--all` 可恢复 | `tests/test_pack.py` |
| A7 | 画像与默认值：`--type` 只吃该类型历史、未知类型回退基线并声明、省略 `--type` 取行程数最多的类型、省略 `--days` 取该类型历史均值取整、空账本输出基线并声明「还没有你的数据」 | `tests/test_pack.py` |
| A8 | CLI 端到端：analyze/pack/validate 退出码与输出节齐全；坏账本、缺文件、未知行程类型优雅失败 | `tests/test_cli.py` |
| A9 | Dogfood：示例埋入的已知模式（充电头盲区、雨伞三连幽灵、收敛改善、账单 ¥279、名片未记价）全部被报告恢复；确定性生成器重跑与提交文件逐字节一致 | `tests/test_dogfood.py` |
| A10 | 诚实条款：空账本拒绝分析；事件行缺 item/category/trip_id 拒绝；ghost 行 weight 缺失计数呈报而非静默忽略 | `tests/test_parsing.py`、`tests/test_ledger.py` |
