# METHODOLOGY · 来得及的统计口径

本文回答「凭什么」：每一个判定背后的口径、它的边界、以及它**不**回答什么。

---

## 1. 为什么是分位数，不是平均

导航 App 报「40 分钟」的时候，它报的是一个分布的某个中心读数；而你拿它做的事情（8:20 出门）是一个**单边风险决策**。单边风险决策的正确读数不是中心，是尾部：

> 「我手里的时间，覆盖了这个分布的百分之几？」

工具用**经验分布**回答：`P(on time) = #{历史时长 ≤ 你手里的时间} / n`。没有正态假设、没有置信区间拟合——50 次通勤就是 50 个样本点，你的余量盖住几个，概率就是几。这带来三个推论：

- **份额即分位数**。报告说「你手里的 36 分钟是 P0」，和说「P(on time) = 0%」是同一句话。概率是分布的语言，分位数是决策的语言，`now` 同时给你两个。
- **平均值不被展示为决策依据**。均值在 `routes` 表里只以 P50 的身份出现——它是分布的一员，不是分布的代表。两条路线的均值可以几乎相同（地铁 41.6 vs 公交 40.7）而 P80 差出 6 分钟（44 vs 50）：抖动不进均值，进分位数。
- **最差日是最硬的证据**。SAFE 判定的措辞是「连你记录里最差的一天都装得下」——余量减去 `max(时长)`，不是减去任何中心读数。

## 2. 窗口条件化：8:15 这条线

同一个路线的通勤不构成同一个分布：7:50 出门和 8:25 出门面对的车流不是同一股。工具把每条路线的样本按出发时刻切成两个池（默认 08:15，`--peak-split` 可调），`now` 和 `leave` 优先读「你这个点出门」的池：

- 池样本 ≥ 5（`MIN_BUCKET_N`）：用窗口池，报告声明出处（"departures from 08:15, n=25"）；
- 池样本 < 5：退回全路线池，报告**声明这是回退**（"route overall (window bucket thin)"）。

**为什么只有两个窗口**：手编账本的样本天然堆在早晚高峰，工作日晚上 21:30 出门这种行一年记不了几条。五个时段的划分很精致，但五个 n<5 的池就是五条传闻——两个窗口才是两个样本。这条线不是理论，是数据密度的妥协；`--peak-split` 让你按自己的账本密度移动它。

**08:24 出门读晚窗的 25 次、不读全池的 55 次**，是本件和「把所有历史搅在一起算个平均」的工具的分界线。

## 3. `leave` 的不动点迭代：为什么需要它

「最晚几点出门」的朴素解法是 `目标 − Q_want(全池)`。但它自相矛盾：全池的 P90 让你在 08:15 出门，而 08:15 出门该读的是晚窗分布——晚窗的 P90 更长，真正的线应该更早。

工具因此迭代求解：**答案（出门时刻）落在哪个窗口，就用那个窗口的分位数重解一次**，直到答案的窗口生成答案自己。窗口是离散的，迭代可能振荡——陈屿的账本在 want=0.9 时就是振荡的：

```text
全池 P90 = 45m → 线 = 08:15 → 落在晚窗 → 晚窗 P90 = 47m → 线 = 08:13
08:13 落在早窗 → 早窗 P90 = 42m → 线 = 08:18 → 又落回晚窗 → ……
```

三个候选里 08:13、08:18、08:13 没有**自洽**的解，工具取**最早**的候选（08:13）。这不是随便挑：最早的候选在**任何**一个窗口自己的统计下都安全（08:13 属于早窗，早窗 P90 = 42，08:13 + 42 = 08:55 ≤ 09:00）——它可能过于保守，但永远不会「按晚窗数据出门、按早窗规律堵车」。**宁早勿险**是反解的唯一合理失败模式。

精化池太薄时的回退同理：早窗建议你 08:30 走（30m），可 08:30 属于晚窗、晚窗只有 3 条数据——用早窗的分布给晚窗的出门背书是统计冒领，工具放弃这个候选，退回全路线分位数的保守线，并在报告里写明出处。

## 4. THIN 门：8 和 5

两个阈值，两个用途：

- **`MIN_NOW_N = 8`**（路线级）：低于它，`now`/`leave` 直接 exit 3 拒绝判定。依据是粗糙但诚实的：n=8 的经验分布每个点占 12.5%，你手里的余量落在两个样本点之间的空隙里时，任何「概率」都是插值出来的装饰。报告的措辞是 "a probability over 4 trips is invention, not statistics"。
- **`MIN_BUCKET_N = 5`**（窗口池级）：低于它不构成条件化，退回全池并声明。5 保证池内至少能区分「中位」和「尾部长度」。

门槛全部可调（`--min-n`），调低时报告不会阻止你——它只是不再替你负责。

## 5. 贴线（close call）：准点率的影子账本

margin ∈ [0, 5 分钟] 的到达记 close call。它单独成账，因为**准点率和贴线率讲的是两个故事**：陈屿的地铁准点率 92.7%，但 21/55 = 38% 的通勤落在 5 分钟余量内——他不准点的日子很少，「差一点不准点」的日子接近一半。这就是「习惯性最晚出门」的统计形状：准点靠贴线而不是靠 buffer 的人，迟到率只差一个坏运气以外的东西。

5 分钟这个窗口的依据：人感知「差点迟到」的记忆强度和真迟到几乎相同，而 5 分钟也是「再早出门 5 分钟就能全部消掉」的量级——`simulate --earlier 5` 直接和它对账。

## 6. `simulate` 的口径：margin 平移与它的边界

`simulate --earlier N` 把每一次通勤的 margin 加 N 重算准点。这是**保守的反事实**：它假设「早 N 分钟出门，路上的时长分布不变」。现实里早高峰的时长分布本身会变（更早出门可能更快），所以 simulate 的读数是**下界**——早出门的真实收益只会更多，不会更少。它不假设的只有一件事：你不换路线。换路线的收益去 `routes` 里看。

年化口径：观测跨度（首末日期差 + 1 天）折算 365.25 天。67 次计时通勤摊在 180 天里，8 次迟到年化 16 次——样本外的外推，报告里明写 "annualized"。

`--earlier` 之后迟到率仍 ≥ 10% 时给 advisory exit 4（STILL LATE）：问题是路线或目标时刻，不是闹钟——改钟解决不了被低估的路线。

## 7. 边界：本件不回答什么

- **不回答「今天路上要多久」**。它不是预报：没有天气、没有事故、没有施工。它回答的是「以历史为条件，现在的决策胜率多少」。实时路况是另一个数据源，不在这个账本里。
- **不解释迟到的因果**。「地铁 × 周五」贡献 50% 的迟到是描述，不是归因——也许周五晚出门是因，也许周五车流是因；工具只负责让惯犯组合无法隐身。
- **不替你定「该几点到」**。target 是你写的（09:00 打卡、09:15 站会），工具对目标本身没有意见；`late` 只告诉你为这个目标你付了多少迟到税。
- **不处理跨午夜通勤**。账本校验 arrive > depart 且同日——这不是夜班公交的账本，强行记会被 exit 2 拒绝。
- **窗口边界两侧的样本互不共享**。08:14 和 08:16 出门被切进两个池是条件化的代价；边界样本归属哪个池对整体判定不敏感（两个池都声明了出处），较真的人应该调 `--peak-split` 而不是怀疑人生。

## 8. FAQ

**Q：为什么 `--at` 必须手填，不能自动取当前时间？**
可复现性是本仓库的宪法：报告里每个数字都必须能钉死重放。真实使用里「现在」就是你的手表；CI 和测试里「现在」是 `--at 08:24`。一个隐式读钟的工具没法逐字节复现，也就没法验收。

**Q：为什么 exit code 有四档？**
因为裁决是接口：`0` SAFE（放心走）、`4` RISKY（advisory，你可能迟到）、`5` DEAD（统计上已经死了/窗口已关）、`3` THIN（数据不足，拒绝判定）、`2` 用法或账本错误。快捷指令和 cron 用 `$?` 分流：4 振动提醒、5 直接发消息改签。

**Q：记多久才够用？**
一条路线一个季度（约 25–30 次）就脱离 THIN；两个窗口各自 ≥ 5 次后条件化才开始工作。换季、换车、城市改了施工路线——旧样本就是旧路线，建议开新的 route 名（`metro-line2-q4`）而不是污染旧分布。

**Q：target 每天不一样怎么办？**
`target` 是行级字段：那天 10:00 才上班就写 10:00。准点账按行算 margin，与固定的「公司时间」无关。不计时出行（遛弯、兜风）target 留空，它们进时长分布、不进准点账。

**Q：为什么迟到的定义是 margin < 0 而不是「超过 1 分钟」？**
margin = target − arrive，9:00:00 之后到达就是负 margin。要不要给「迟到」加宽限是公司文化问题；账本记录事实，宽限请自行在 target 里减掉。
