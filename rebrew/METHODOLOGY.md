# 方法论 · 复现那杯（Rebrew）

> 这份文档回答「为什么这样设计」：为什么先测噪声再调参、σ̂ 怎么估、MDE 从哪来、Pearson r 的边界在哪里、以及那些注定会被问的问题。

---

## 1. 第一性原理：先测噪声，再谈效应

任何实验科学的第一步都不是「找效应」，而是**估计噪声**。原因很朴素：

> 如果同一配方冲两次的评分能差 1.5 分，那么任何小于 1.5 分的「参数发现」都无法与手抖区分。

这是信号检测的最基本约束——**分辨力受噪声下限的支配**。咖啡社区的大量「玄学争议」（94°C 还是 92°C？1:15 还是 1:16？）很可能不是观点分歧，而是**双方都在自己的噪声底噪里各自捡到过一次好运**。rebrew 的第一块输出不是参数建议，而是复现半径 σ̂：它告诉你，你的「发现」要超过多少分才有资格叫发现。

这就是建议阶梯（复现 → 降方差 → 散开探索 → 单因素实验）的依据：

1. **复现（reproduce）**：日志里没有任何同配方重复 → σ̂ 无从估计 → 一切结论都不可检验。先复冲当前最高分配方 2~3 次。
2. **降方差（stabilize）**：σ̂ ≥ 1.5 分（10 分制）→ 单因素实验的 MDE 会大到没有实用价值（每组 2 杯时 MDE ≈ 4 分——你根本没有那么宽的评分区间）。先练一致性：固定注水手法、固定计时。
3. **散开探索（explore）**：噪声可控，但日志里只有一种配方 → 参数空间还没打开，相关性无从算起。
4. **单因素实验（experiment）**：以上全部通过，才开实验计划。

**1.5 分这条线从哪来？** 它是经验线而非统计线：10 分制下，1.5 分大约是「明显好喝/明显难喝」的主观档位宽度。若 σ̂ 超过它，你的评分系统本身分不出「相邻两档」，更分不出参数效应。它同时编码在 `NOISE_CEILING` 常量与验收测试 A4 里——工具在噪声超标时**拒绝**给出调参建议，这是产品立场，不是 bug。

## 2. 复现半径 σ̂ 的估计

**配方指纹** = (豆, 粉量, 水量, 水温, 研磨)。`time_s`（总注水时间）是过程结果而非设定参数，刻意排除在指纹外——两次「同参数」冲煮的注水时间不同，恰恰是噪声的来源之一，不能让它豁免。

对每个 n≥2 的重复组计算组内评分的**样本标准差**（n−1 分母；n=2 时 s = |x₁−x₂|/√2），再取所有组的**均方根（RMS）**作为全局 σ̂。选 RMS 而非中位数，是为了不让「恰好很稳的一组」把整体噪声估计拉低——在厨房规模的数据量（几个组）下，RMS 对最差情况的保守偏置是特性不是缺陷。

诚实的失败模式：**没有任何重复组时返回 None**，报告明说「测不出来，不假装能算」。这条也是验收标准 A2——一个测量工具最坏的行为不是「测不准」，而是「没测也给你个数」。

## 3. MDE：多大的差异才值得相信

双样本、每组 n 杯重复、显著性 α=0.05（双尾）、功效 80% 时，最小可检测效应的近似公式：

```text
MDE ≈ (z_{α/2} + z_{β}) · σ̂ · √(2/n) ≈ 2.8 · σ̂ · √(2/n)
```

（z_{0.025}=1.96，z_{0.20}=0.84，合计 2.8。）它是经验近似：严格版应该用 t 分布并逐案算自由度，但在 n=2~5 杯的厨房场景里，近似误差远小于评分本身的主观误差，不值得为此引入任何依赖。

两个直觉读法：

- **σ̂ 减半，MDE 减半**：练一致性比多冲一杯「更便宜」——这是「先降方差」阶段的量化理由。
- **每组 2 杯 → 3 杯，MDE 降 ~18%**（√(2/3)）：重复的边际收益递减，别指望靠堆杯数弥补手抖。

## 4. 旋钮排行：Pearson r 的用法与边界

对每个旋钮（水温/研磨/粉量/水量/粉水比），计算其取值与评分的 Pearson 相关系数，按 |r| 排序。**相关不是因果**，rebrew 对 r 的定位是「排序线索 + 生成单因素假设」，判定交给实验计划。已知边界：

- **线性假设**：r 只捕捉单调线性关系。倒 U 型关系（真实的粉水比往往如此）会被低估——本仓库示例里 1:15 的最优性就主要体现在分组均值而非 r。所以报告同时给分组均值节。
- **参数共变**：如果你习惯「细研磨配高水温」，r 会把这个捆绑计入两个变量。单因素实验（锁定其余、只动一个）正是为此存在。
- **混杂因素**：豆子养排期、室温、水质、你昨晚的睡眠——都不在日志里。它们全部被折叠进 σ̂ 和残差，这正是 MDE 要求「超过 2.8σ̂√(2/n) 才下结论」的原因。
- **数据量的诚实**：报告在榜首 |r| < 0.3 时不标「最相关」，明说「效应可能被噪声淹没，或参数空间还没碰到有效区间」。

**为什么 time_s 单列一节且标注「相关≠因果」**：注水时间是手法与研磨共同的结果变量。它与评分的相关可以很有信息量（比如「时间长的杯子萃取更足」），但把它当旋钮去「设定」是范畴错误——你能设定的是手法，不是结果。

**为什么限定同豆域**：不同豆的基准分和最优参数完全不同，混算等于往 r 里注入豆间方差。多豆日志自动取记录最多的豆为主域（报告注明），`--bean` 可手动切换。

## 5. 为什么不用多元回归 / 机器学习

厨房场景的数据是**小样本、强共变、高噪声**的：几十条记录、五个参数彼此相关、σ≈0.5 分。线性回归在这个区间给出的系数置信区间宽到没有意义，任何更花哨的模型都是对噪声的过拟合。rebrew 的选择是统计上最保守的那条路：**单变量相关做排序 + 单因素实验做判定 + MDE 做门槛**。这也是它在示例数据上能恢复埋入效应、而「直觉调参」不能的原因——方法朴素，但每一步都可检验。

## 6. 评分：主观量具的校准

评分是整条链路里唯一的软量具，rebrew 不假装能替你校准，但 METHODOLOGY 给出可操作的建议：

- **锚点固定**：先写下你的 5 分（日常及格）和 8 分（愿意请朋友来喝）的书面定义，再开始记分。量具漂移会直接抬高 σ̂——这恰好会被复现半径逮住，算是免费的自检。
- **盲评最好，但别等**：能遮盖标签盲评最好；不能的话，至少在冲完 10 分钟内、漱口后评分。
- **0.5 分步进**：比整数细一点（否则 MDE 太粗），比 0.1 分粗很多（那是伪精度）。

## 7. FAQ

**Q: 我该记多少条才开始有结论？**
复现半径需要 ≥1 个重复组（2 杯同配方）就能出数，但置信很粗。实用门槛：每个想下结论的参数档位 ≥2 杯、总杯数 ≥15 之后，MDE 才开始落到「参数效应的典型幅度」（约 1 分）以内。

**Q: 相关性排行把我带偏了怎么办？**
会发生的——r 是观测性证据。但带偏的成本被 MDE 拦住了：错误的假设会在单因素实验里表现为「差异 < MDE，维持原判」，而不是变成你的信仰。这是实验循环的意义：**r 提案，实验投票**。

**Q: 研磨刻度在不同磨豆机上不可比怎么办？**
rebrew 只做你**个人日志内部**的比较，从跨机器比较这个雄心里撤退了。日志内刻度一致即可；换了磨豆机，就开一个新日志（或至少在 notes 里记一笔，并理解跨机器段的 r 会被污染）。

**Q: 为什么是 TSV 而不是 app/数据库？**
一行一次冲煮、手机备忘录/表格软件都能直接编辑、`diff` 友好、永不锁死在任何工具里。你的冲煮数据应该像你的咖啡一样：自己烘焙，自己保存。

**Q: 滤杯/滤纸/水质这些固定因素呢？**
固定因素不进指纹。它们变了就换日志，或者接受「换器材前后的 σ̂ 和 r 不可比」——工具的每个数字都只对**当前这套器材组合**负责。

**Q: 这和「控制变量法」有什么区别？**
没有区别——它就是把你在中学学过的控制变量法，变成会自动算噪声、自动排优先级、自动开实验单的一套流程。科学方法的家用版本，仅此而已，也正因如此它有效。
