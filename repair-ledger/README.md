# 续命账 · Repair Ledger

> 师傅说「修好再战三年」,你的账本说:三年打五折,一年半——报价才 ¥700,新机 ¥3500,这笔钱买到的每个服务年比新机贵 64%。
> A zero-dependency CLI that turns "repair or replace?" from a feeling into a ledger: every repair is a receipt for extra life, and the ledger learns how much of the repairman's promised life your household actually got.

---

## 一句话

家里的耐用品坏了,维修师傅报价 ¥600、拍胸脯「修好再战三年」,新机 ¥3200——修吗?多数人靠两种情绪回答:「舍不得」(修!)和「烦死了」(换!),然后各踩一次坑:舍不得的路线走到第三次修理,累计维修费悄悄爬过了购价,才发现自己在**给废品站预付工资**;烦死了的路线上周才给一台刚大修过的机器办了退休——那正是它寿命最健康的一天。`repair-ledger` 的立场:**修还是换, comparable 的既不是报价也不是新机价,是边际每使用年成本**;而「师傅说再战三年」这句话的价值,你的维修历史早就有答案——每一笔记下「宣称续命」的维修,都会在下次故障那天兑现成「实际续命」,`median(实际/宣称)` 就是**你家维修市场的画饼系数**。同一台机器修得越多,每次买到的寿命越短(**续命递减**),累计维修费一过购价,**沉没护栏**直接把「再修一次」改判成报废。维修师傅仍然修机器,这台 CLI 修的是你做决定的方式。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 家里耐用品开始进入「维修期」的家庭决策人(洗衣机第 N 次报修,报价单在手);租房拎包、大件靠二手的年轻人(购价低、维修占比涨得快,更容易撞上沉没护栏);喜欢修东西但不知道何时该停手的「舍不得党」。 |
| **场景** | 维修师傅报价电话里(「¥700,修好能用三年」——挂电话前跑一次 `verdict`);年度家底盘点(「家里 5 件老家伙,谁在偷偷吃掉最多的服务年成本?」);修完之后(把「宣称三年」记进账本,坐等现实对账);第 N 次修理冲动来临那一刻(「上次说三年,这次又信吗?」)。 |
| **问题** | ① **可比性错位**:报价(一笔钱)和新机价(另一笔钱)看起来在比,其实不可比——修买来的是残命,新机买来的是整条命,不折算成「每服务年成本」的比较全是错觉;② **宣称续命无对账**:「再战三年」是维修成交的关键话术,但从没有账本记录它兑现了几成,于是同一个饼可以画十年;③ **续命递减不可见**:同一台机器每修一次,下次故障来得更快,人的直觉却把「刚修过」当成「很健康」;④ **沉没成本无护栏**:修理费一笔一笔付的时候从不像总额,累计爬过购价的那一天没有人会主动告诉你。 |
| **价值与意义** | 1) **边际裁决**:`verdict` 把报价折算成「¥/服务年」与新机同台对比,输出 FIX / REPLACE / SCRAP 三判定与对应 exit code,可被脚本化进家庭决策流程;2) **画饼系数**:从自己的维修史算出 `median(实际续命/宣称续命)`,师傅的话第一次有了个人对账基线(样例账本:0.49——「再战三年」按 1.5 年听);3) **续命递减检测**:物品级实际续命序列严格递减即亮灯,附在每次裁决上;4) **沉没护栏**:累计维修(含本次报价)超过购价 → SCRAP,结构性挡住「给废品站预付工资」;5) **零依赖 + 纯本地**:Python 3.8 标准库,`--as-of` 钉死即逐字节可复现,家庭账目不出电脑。 |

## 核心思想:修理买的是残命,新机买的是整条命

修理经济学里全部的错误,都来自把「一笔钱」和「一笔钱」直接比较。账本引入三个量,把比较拉回同一量纲:

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **续命收据 repair trail** | 每笔维修记 `claimed_years`(师傅宣称)与实际续命(到下次故障/报废的间隔;还没坏 = 删失 `≥n`,不进统计) | 「上次修完,到底用了多久?」 |
| **画饼系数 pie factor** | 全家已结维修的 `median(实际/宣称)`;无历史默认 1.0;`failed` 维修计 0(钱照付、命没续) | 「师傅的话按几折听?」 |
| **边际每服务年成本** | 修理:`报价 / (宣称 × 画饼系数)`;新机:`新机价 / 期望寿命` | 「同样买一个服务年,哪边便宜?」 |
| **三方裁决 verdict** | 边际比值 ≤ 容忍度(默认 1.0)→ **FIX**(exit 0);不占优且维修占比 < 100% → **REPLACE**(exit 3);维修占比 ≥ 100% → **SCRAP**(exit 4) | 「现在这次,修、换、还是扔?」 |
| **续命递减 diminishing** | 该物品已结 fixed 维修的实际续命严格递减 → 裁决附警示(不改数值,只改你听报价时的表情) | 「这台机器是不是越修越短命?」 |
| **沉没账 sunk** | `购价 + 累计维修 − 报废回收`;`每服务年 = 沉没 / 服役年数` | 「这台机器至今一共吃了我多少?」 |

四条诚实条款刻在实现里:**「今天」只属于真实使用**——`--as-of` 钉死即逐字节可复现(本文档全部输出钉在 2026-09-04);**修不好的钱照记账**——`failed` 维修 actual 记 0 且进画饼样本,「修不好也收钱」是这个市场最贵的一句话;**删失如实**——修完还没再坏的维修只有下界,标 `≥`,不冒充已结进中位数;**没有历史不惩罚**——空账本画饼系数默认 1.0,先信师傅,账本记下后见分晓。

## 命令速查

```bash dd:ignore
python3 repair_ledger.py report examples/home.json --as-of 2026-09-04            # 全景:每服务年成本排行 + 续命实况
python3 repair_ledger.py report examples/home.json --as-of 2026-09-04 --format json   # 机读
python3 repair_ledger.py show examples/home.json washer --as-of 2026-09-04       # 单物品:每笔维修的宣称 vs 实际
python3 repair_ledger.py history examples/home.json --as-of 2026-09-04           # 画饼考古:全部维修的兑现率
python3 repair_ledger.py verdict examples/home.json washer \
  --quote 700 --claimed-years 3 --new-price 3500 --new-life 12 --as-of 2026-09-04   # 修/换/废裁决(exit 0/3/4)
python3 repair_ledger.py verdict examples/home.json washer --tolerance 2.0 ...   # 容忍度:修理贵到几倍仍算 FIX
python3 repair_ledger.py verdict examples/home.json microwave --scrap-ratio 1.5 ...  # 护栏松紧:维修占比几倍才判废
```

## 一个真实样例

[examples/home.json](examples/home.json) 是一份五件耐用品的账本:洗衣机(修 3 次)、冰箱(修 1 次)、笔记本(修 2 次后结案)、热水器(修 3 次后结案)、微波炉(最后一笔没修好)。全景:

```text dd:ignore
续命账 · Repair Ledger — 观察日 2026-09-04
画饼系数 0.49(9 笔已结维修的中位 实际/宣称;师傅说再战三年,按 1.5 年听)

ITEM           名称                  服务年        沉没      每服务年     维修占比  续命实况                       状态
--------------------------------------------------------------------------------------------------
laptop         笔记本                 6.8    ¥10400     ¥1525   12.24%  1.9 → 1.6 ▼递减              已结案
fridge         冰箱                  7.3     ¥4450      ¥610   14.10%  ≥4.6                       服役中
washer         洗衣机                10.1     ¥4500      ¥446   40.62%  1.7 → 0.8 → ≥1.0 ▼递减       服役中
heater         热水器                 9.3     ¥3500      ¥375   96.11%  2.1 → 1.6 → 1.5 ▼递减        已结案
microwave      微波炉                 6.4     ¥1200      ¥188   71.43%  2.0 → 0(failed)            服役中
```

同一个画饼系数 0.49 下,三台机器在同一天拿着报价单走进裁决,走出三条路:

**冰箱 FIX(exit 0)—— 修。** 压缩机再修一次 ¥480,师傅宣称续 4 年,折算后诚实续命 1.9 年:¥246/服务年,新机要 ¥371/服务年,比值 0.66——这笔钱买到的服务年更便宜,给师傅打电话。

**洗衣机 REPLACE(exit 3)—— 换。** ¥700 买「宣称 3 年 / 诚实 1.5 年」= ¥479/服务年,新机 ¥292/服务年,贵 64%;维修占比 62% 还没撞护栏,但账本附了续命递减警示:实际续命 1.7 → 0.8,一次比一次短——旧机的感情不进账本。

**微波炉 SCRAP(exit 4)—— 扔。** 边际比值 3.59 早就输了,更致命的是累计维修(含本次)¥850 已是购价 ¥700 的 121%——继续修,是在给一台该退休的机器分期付款。

## 验收标准

全部转成自动化测试,住在 [tests/test_repairledger.py](tests/test_repairledger.py)(66 例,`python3 -m unittest discover -s repair-ledger/tests` 一次跑完):

1. **坏数据必须拒收**:文件缺失、非法 JSON、顶层类型错、缺字段、id 重复、负价格、非法日期、维修早于购入/乱序、负费用、非法 outcome、非正宣称续命、报废早于末笔维修、负回收值 → 一律 exit 2 带可读信息,不许带病计算。
2. **账本数学可复算**:服务年数(服役中到观察日 / 结案到报废日冻结)、沉没 = 购价 + 维修 − 回收、每服务年 = 沉没 / 服役年数——样例账本逐件核对。
3. **续命轨迹如实**:fixed 的实际续命 = 到下次故障或报废的间隔;尚无后续 = 删失 `≥n`;failed 记 0 且计入统计——「修不好也收钱」照进画饼。
4. **画饼系数** = 全部已结维修 `median(实际/宣称)`;删失不进样本;空账本默认 1.0;师傅保守(实际 > 宣称)不惩罚性压回 1.0。
5. **续命递减**:实际续命严格递减才亮灯;单笔/持平不亮;failed 不参与该判定。
6. **三方裁决**:边际占优 → FIX(exit 0);不占优 → REPLACE(exit 3);不占优且维修占比(含本次报价)≥ 阈值 → SCRAP(exit 4);`--tolerance` 与 `--scrap-ratio` 均可调且方向正确;画饼系数为 0 时诚实续命归零、判 REPLACE;赠品(price 0)无维修占比、不触发 SCRAP。
7. **裁决护栏**:已结案物品拒绝裁决(exit 2);未知物品、非正报价/宣称续命/新机参数、非法 `--as-of` 均 exit 2。
8. **可复现性**:样例账本 `--as-of 2026-09-04` 钉死后,report 与 history 两次运行逐字节一致;三条裁决(FIX/REPLACE/SCRAP)的数值(¥246/服务年、比值 0.66、画饼 0.49、占比 62%/121%)逐项断言。

## 设计决策

- **画饼系数取全局中位数而非物品自身**:单件物品的维修样本太少(常见 1–2 笔),中位数不稳;「你家维修市场的兑现率」本来就是一个跨物品的个人基线——它同时校准了你选师傅的眼光和本地维修市场的水位。物品自己的递减趋势则单独作为 advisory 附注,不参与数值计算。
- **`failed` 维修计入画饼样本(actual = 0)**:那笔钱付出去的时候,宣称续命同样写在报价单上;把它剔出统计等于免费给「修不好也收钱」续信用。
- **递减只警示、不改判**:画饼系数已经完成了「师傅的话打几折」的全局校准,再让递减序列改数值等于双重惩罚;但它应该出现在你听报价的那一刻——所以它印在裁决输出里。
- **SCRAP 阈值默认 100%**:累计维修(含本次报价)追平购价,是「经济上已经把这台机器重买了一遍」的清晰信号;想更保守可以 `--scrap-ratio 0.8`,想更恋旧可以 1.5。
- **为什么不用折现率/通胀**:本件比较的是同一时点上的两个边际选项,通胀对两侧同向作用,引入折现只增加参数不改变排序;家庭账本的敌人从来不是精度不足,是没有账。
