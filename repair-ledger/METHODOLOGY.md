# 续命账 · Repair Ledger — 方法论与 FAQ

> 本件的方法论立场:修还是换,是一个**边际决策**;而边际决策需要的不只是今天的报价,还有你自己历史里长出来的折算率。账本不替你修机器,账本修的是你做决定的方式。

---

## 1. 为什么「报价 vs 新机价」是错的比较

维修师傅的话术结构永远是:「这笔钱(¥700)能买三年」。这句话的漏洞不在钱,在「三年」——它是**宣称续命**,不是诚实续命。同样,新机标价 ¥3500 买的是 12 年期望寿命。两笔交易真正可比的量纲是:

```
修理边际成本 = 报价 ÷ (宣称续命 × 画饼系数)     ← 每服务年
新机边际成本 = 新机价 ÷ 新机期望寿命             ← 每服务年
```

只要前者 ≤ 后者(默认容忍度 1.0),修理就是更便宜的买法;反之,你是在为「舍不得」支付溢价。样例账本里洗衣机的裁决:¥700 ÷ (3 × 0.49) = ¥479/服务年,对新机 ¥292/服务年——感情溢价 64%,每多留它一年多付一百多块。

**与沉没成本谬误的关系**:已经付掉的维修费不应影响下一次决策——所以 `judge()` 的 FIX/REPLACE 判据里只有**本次报价**的边际,历史维修费不进分子。历史维修费出现在两个别的位置:每服务年成本的分母(它是历史事实)和 SCRAP 护栏(见 §4)。这不是半吊子沉没成本,是把「过去的钱」和「下一次的钱」分账。

## 2. 画饼系数:宣称续命的个人对账基线

维修市场有一个结构性的信息不对称:师傅在成交前给出「再战 N 年」,而验证这句话要等下一次故障——那已经是下一单生意了。`repair-ledger` 把验证自动化:

- 每笔维修记下 `claimed_years`(师傅说);
- 下一次故障、或报废、或观察日,自动兑现出「实际续命」;
- `画饼系数 = median(实际/宣称)`,跨全部物品、全部已结维修。

### 2.1 统计口径

| 口径 | 规则 | 为什么 |
|---|---|---|
| **删失只标不进** | 修完还没再坏的维修,实际续命只有下界(`≥ n`),不进中位数 | 把「还没坏」当「已兑现」会系统性高估系数;右删失样本的正确处理就是只用其存在性、不用其数值 |
| **failed 记 0** | 没修好的维修,actual = 0,进样本 | 那笔钱成交时同样有宣称续命背书;剔除它等于给「修不好也收钱」免费续信用 |
| **不 clamp 上限** | 实际 > 宣称时 ratio > 1,如实保留 | 师傅保守是一种可积累的信用;把它压回 1.0 会丢失「这家师傅超预期」的信息 |
| **全局而非物品级** | 中位数跨全家物品计算 | 单件物品常见只有 1–2 笔已结维修,中位数不稳;「你家的兑现率」同时校准选师傅的眼光与本地市场水位 |
| **空账本默认 1.0** | 没有历史时不折算 | 不惩罚新人:先信师傅,账本记下,后见分晓 |

### 2.2 样本量的诚实边界

9 笔已结维修的中位数(样例账本)已经有用,但它仍是一个宽置信区间的小样本。方法论的诚实态度是:**系数是活的**——每结一笔新维修它就重算一次;当它不足以支持精细结论时,裁决输出里那个「画饼系数 0.49 → 诚实续命 1.5 年」的箭头本身就是结论的主要部分。不要用 3 笔样本的 0.49 去争论 5% 的边际差;用它去拦住比值 1.6 的明显劣质交易,这正是它设计的工作点。

### 2.3 品类混合的伪影

全屋系数把洗衣机和微波炉混在一起。若你的维修史跨「大件 / 小家电 / 电子品」且兑现率差异明显,可以分账本文件(每个文件一套系数);本件刻意不内置品类分层——在典型家庭 <20 笔维修的规模下,分层会把每层的样本压到统计无意义的水平。先有全局基线,等账本厚了再分家。

## 3. 续命递减:为什么「刚修好」不等于「很健康」

同一台机器的维修有一个普遍的物理规律:每次修理解决的是**当前故障**,而老化是全机身的——换掉的加热棒是新的,内胆还是十年前的。于是实际续命序列倾向于递减:样例里的热水器 2.1 → 1.6 → 1.5 年,洗衣机 1.7 → 0.8 年。

本件的判定规则:该物品**已结 fixed 维修**的实际续命**严格递减**才亮灯(单笔、持平、回升都不亮;failed 不参与,因为它没有「修好后的寿命」可言)。它作为 advisory 印在裁决输出里,**不修改数值判据**——理由见 §5.2。

## 4. 沉没护栏:SCRAP 的经济学

```
累计维修(含本次报价) / 购价 ≥ 1.0  →  SCRAP
```

这条护栏的直觉:当修理费总额追平购价,你在经济上已经把这台机器**重买了一遍**,却没有得到一台新机器——继续修,每一笔都是在给一台该退休的机器分期付款。

设计细节:

- **分子包含本次报价**:护栏问的是「如果今天再修一次,会到什么水位」,这是决策时点的正确视角;
- **只在边际判 REPLACE 之后才检查**:护栏不越权——如果边际账大占优(报价 50 块买 5 年),哪怕累计已超购价也应该修;沉没成本谬误的两个方向(「都修这么多了再修一次」和「已经修太多了这次不修了」)都被同一条规则挡住:看边际,再看水位;
- **赠品(price = 0)无此一说**:没有购价就没有占比,只按边际裁决——`judge()` 返回 `repair_ratio = None`,不触发 SCRAP。

## 5. 常见问题

### 5.1 这和 cost-per-wear / cost-per-use 是一回事吗?

同族不同题。「每穿成本」(cost-per-wear)是**购买决策**的事前工具:买之前预估使用率;「续命账」是**持有期**的事中工具:东西已经在手里、坏了,下一次边际怎么选。一个管入口,一个管出口;一个的未知数是「未来会用多少次」,一个的未知数是「这次修理真的能续多久」。两件工具在数据形态上甚至互为镜像:前者记使用次数,后者记故障间隔。

### 5.2 为什么递减只警示、不改判据?

因为画饼系数已经完成了「宣称 → 诚实」的全局折算,而递减信息在很大程度上**已经包含在里面**:一台越修越短命的机器,它每笔维修的 ratio 本来就低,会自然拉低全局系数并反映在下一次裁决里。再让递减序列进入数值,等于对同一信号双重惩罚。但递减有一个数值无法替代的功能——它是**这一台机器**的私有信息(全局系数是全屋的平均),所以它以警示的形式出现:不改答案,改你听「再战三年」时的表情。

### 5.3 观察日 `--as-of` 是什么?为什么要钉死?

所有「至今」的计算(服役年数、删失下界)都以 `--as-of` 为参照。默认取今天,但文档、测试、CI 里的所有输出全部钉在同一日期(2026-09-04),这让样例报告**逐字节可复现**——你今天跑和三年后跑,看到的数字一样。家庭账本和实验记录共享同一条纪律:不钉死参照日的数字,过了午夜就变成另一个数字。

### 5.4 维修师傅宣称「修不好不收钱」,怎么记?

那是一笔 `claimed_years` 存在、`cost` 可能为 0 的维修。如果真没修好,记 `outcome: "failed"`、`cost: 0`——actual = 0 照进画饼样本,但钱上不冤枉人。本件的 `failed` 语义是「寿命没续上」,不是「钱白花了」,两本账分开记。

### 5.5 我该记到什么粒度?什么不值得记?

判据:**下一次故障来临时,这笔记录能不能改变一个裁决**。¥120 换个微波炉门扣值得记(它进入画饼样本和占比);¥15 换根电源线不必(记账成本超过信息价值)。经验法则:维修费超过物品购价 3% 或超过 ¥100 的都值得记,其余随意。

### 5.6 新机期望寿命哪里来?

用同品类的经验值(滚筒洗衣机 10–12 年、冰箱 12–14 年、笔记本 5–7 年),或你对特定品牌的判断。它是**你**对另一条命的定价参数,不是客观常数;敏感的话跑两次 `verdict`,一次乐观一次悲观,看判定是否翻转——翻转本身就告诉你这个决策对新机寿命敏感,值得再查 10 分钟资料。

### 5.7 为什么不做通胀/折现?

见 README「设计决策」:比较发生在同一时点、两个选项同向受通胀作用,折现不改变排序,只增加参数。家庭账本的敌人不是精度不足,是没有账。

## 6. 局限

- **画饼系数假设宣称续命可比较**:不同故障类型的「三年」难度不同(换压缩机 vs 换门扣);在小样本下这是可接受的噪声,样本大了请按 §2.3 分账本。
- **不考虑停机成本**:冰箱坏了三天,食物损失的 ¥300 不在任何一笔维修费里——如果你的场景里停机很贵,把它自己加进报价 mentally 再跑裁决,方向不会错。
- **不处理情绪价值**:那台陪你搬过三次家的洗衣机,账本永远算不出它的溢价。但正因为如此,把经济账算清楚才更有必要——你知道自己在为什么付钱,和不知道,是两种完全不同的「舍不得」。

## 7. 数据格式

```json
{
  "items": [
    {
      "id": "washer",
      "name": "洗衣机",
      "purchased": "2016-08-01",
      "price": 3200,
      "expected_life_years": 10,
      "repairs": [
        {"date": "2023-03-12", "symptom": "不脱水", "cost": 260,
         "outcome": "fixed", "claimed_years": 3.0}
      ],
      "retired": {"date": "2024-03-02", "salvage": 30}
    }
  ]
}
```

字段:`repairs[].outcome` ∈ `fixed` / `failed`;`claimed_years` 必填(failed 也记,那是成交时的宣称);`retired` 可选,`salvage` 默认 0。校验规则(乱序、越界、负值、重复 id……)全部拒绝且 exit 2——账本的第一美德是不接受糊涂账。
