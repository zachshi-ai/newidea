# 稍后永不 · Later Never

> 稍后读的「稍后」，在统计意义上就是「永不」。
> A zero-dependency CLI that turns your read-it-later pile into an honest ledger: digestion half-life, a clearing ETA that can be ∞, and a surgery list for what to archive.

---

## 一句话

收藏按钮是注意力唯一一张**只刷不还**的信用卡：点星那一刻焦虑 −1（好像已经处理过了），代价全部延期——列表无声地涨到几百条，没有账单、没有利息提示、没有任何仪表盘回答那个要命的问题：**按我现在的节奏，这堆东西清得完吗？** 日历工具有忙碌率，稍后读工具只有那个越来越大的未读数字。`later-never` 的立场：**稍后读管理的最小可行单元不是「未读数」，是「消化半衰期」**。从一本可手编的 TSV 账本里，它量出你收藏后实际多久会读（中位 t½，示例里是 9 天——超过 2×t½ 没读的，统计上已经死了）、你的**老化曲线**、近一季的摄入/消化速度，然后给出别人从不给你的结论：当每周收藏 ≥ 每周阅读，**清空 ETA = ∞**——问题从来不是「不够努力地读」，是「还在无节制地收」。最后一份**手术单**告诉你哪些条目该归档（越老越死的 R1、类型幻觉的 R2）、哪类 tag 从此别再收（收了 ≥10 条、读率 <20% 的**幻觉类型**）——扔与不扔，仍是你的决定。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 知识工作者与自学者（信息摄入是工作的一部分，收藏是本能动作）；信息焦虑者（「好东西不能丢」的仓鼠型收藏家）；试图用稍后读工具「变好」的人——工具用了三年，未读从 40 涨到 800。 |
| **场景** | 周日晚上的例行愧疚（「这周又收了 15 篇，读了 2 篇」）；换稍后读工具 / 清点数字资产时直面那 800 条未读；决定「要不要再点这个收藏」的当下；给「我是不是该戒掉信息流」找一个证据而不是一个感觉。 |
| **问题** | **收藏是即期结算、远期违约的注意力合约**：① 点收藏的瞬间给「已处理」的错觉——开放回路被虚假闭合，大脑停止提醒你（与 Zeigarnik 效应相反的解药被滥用了）；② 堆积无账单——不像信用卡有月度对账单，「未读 +1」没有痛感，800 条和 80 条在体感上没区别；③ 收藏类型有系统性自欺——教程、工具类收藏从不读却持续收藏：收集的是「理想自我」不是信息（收集者谬误）；④ 没有工具回答结构性问题——「多老就死透了」「按当前节奏清得完吗」「哪些该批量归档」，日历和稍后读应用全都不回答。 |
| **价值与意义** | 1) **消化半衰期 t½**：已读条目「收藏→阅读」延迟的中位数（样本 <5 拒绝计算，不瞎算），把「放多久就没救」变成你自己的数字。<br>2) **清空 ETA（可为 ∞）**：`backlog ÷ (每周读 − 每周收)`，摄入 ≥ 消化时诚实判 **never**——第一次有工具说「你需要的不是更努力，是更少地收藏」。<br>3) **老化曲线**：按收藏时长分桶的读率，揭示你的阅读习惯是渐死还是断崖崩塌（示例里：老桶 100%、新桶 40%——崩塌是最近半年的事）。<br>4) **幻觉类型检测**：收了 ≥10 条且读率 <20% 的 tag 被点名——「为理想自我收藏」的实锤。<br>5) **手术单 + 配额**：R1/R2 两条确定性归档规则 + budget 反推「每周多读几篇或少收几篇」，行动建议保留人的决定权。<br>6) **零依赖 + 纯本地**：Python 3.8 标准库，`--today` 钉死即逐字节可复现；你的阅读史就是你好奇心的病历，不上传、不登录。 |

## 核心思想：注意力债务的复式账本

稍后读的所有痛苦，都来自把「收藏」记成了「获取」。工具把一笔收藏拆成两个时刻——**saved_at（收进来的那天）**与 **read_at（真正读完的那天，可能永远不来）**——两列之间的差额就是全部指标的原材料：

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **消化半衰期 t½** | 已读条目 `(read_at − saved_at)` 的中位数（天）；样本 <5 返回「不足」 | 「一篇收藏放多久，就统计上死透了？」 |
| **坟场率** | 未读且 age > 180 天的比例 | 「多大比例的收藏已经无人认领？」 |
| **老化曲线** | age 分桶（0–30 / 31–90 / 91–180 / 180+）各桶的读率 | 「我的阅读习惯是渐死，还是某个时代之后崩塌的？」 |
| **速度** | 近 90 天每周收藏数 / 每周读完数 | 「两个水龙头现在各开多大？」 |
| **清空 ETA** | `backlog ÷ (读/周 − 收/周)`；差 ≤ 0 → **∞** | 「按当前节奏，清得完吗？」 |
| **幻觉类型** | 某 tag 收藏 ≥10 条且读率 <20% | 「哪类收藏是给理想自我买的家具？」 |
| **手术单 R1** | 未读且 `age > max(4×t½, 30)` | 「哪些已经死透了，可以体面下葬？」 |
| **手术单 R2** | 未读且 `age > max(2×t½, 30)` 且**所有** tag 均为幻觉类型 | 「哪些是被类型诅咒的，再放也不会读？」 |
| **配额** | 目标 M 个月清空 → 每周需读 `收 + backlog/周数`，或每周只许收 `读 − backlog/周数` | 「两个杠杆各拧多少？」 |

三条诚实条款刻在实现里：**t½ 是中位数不是平均数**——阅读延迟是重尾分布，一个「收藏了三年才读」的异类会把均值拉到毫无意义的 30 天，中位数纹丝不动；**样本不足就拒绝计算**——已读 <5 条时显示「不配算中位数」，宁可没有数字也不给噪音起名字；**ETA = ∞ 不是失败是事实**——工具不假装「加油就能清完」，摄入 ≥ 消化时它把结构性真相直接写在报告里。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash dd:ignore
python3 later_never.py audit examples/library.tsv --today 2026-09-04
```

## 命令速查

```bash dd:ignore
python3 later_never.py audit examples/library.tsv --today 2026-09-04          # 总览：t½ / 坟场 / ETA / 幻觉类型
python3 later_never.py audit examples/library.tsv --max-graveyard 0.20        # 闸门：坟场率超 20% → exit 4
python3 later_never.py triage examples/library.tsv --today 2026-09-04         # 归档手术单（只给名单，不删东西）
python3 later_never.py budget examples/library.tsv --months 6 --today 2026-09-04  # 清空目标反推两杠杆
python3 later_never.py mark examples/library.tsv es9 --today 2026-09-04       # 读完一条：t½ 的样本就是这么来的
python3 later_never.py import-pocket pocket_export.html --out library.tsv     # 从 Pocket 导出重建账本
```

## 一个真实样例

`examples/library.tsv` 是一本 41 条的账本（18 读 / 23 未读，锚定 2026-09-04）：

```bash dd:ignore
python3 later_never.py audit examples/library.tsv --today 2026-09-04
```

```
坟场率（收藏 >180 天未读）: 24%
消化半衰期 t½      : 9.0 天 —— 收藏后 2×t½（18 天）没读，大概率永不

老化曲线（老桶的读率是封棺定论；新桶的还没写完）：
  0–30 天    n=7    读率 43%
  31–90 天   n=15   读率 40%
  91–180 天  n=5    读率 100%
  180+ 天    n=14   读率 29%

近 90 天速度：每周收 1.7 篇 / 每周读 0.7 篇（净 -1.0）
清空 ETA           : ∞ —— 摄入 ≥ 消化，backlog（23 条）统计上永不清空；你不需要更努力地读，需要更少地收藏

类型画像（幻觉 = 收了 ≥10 条且读率 <20%）：
  ai-tools       收 15  读 1  （7%）坟场 7  ← 幻觉类型
  essays         收 12  读 8  （67%）坟场 0
  career         收 8   读 2  （25%）坟场 3
  deep-work      收 7   读 7  （100%）坟场 0
```

这本账讲了一个完整的故事：`essays`/`deep-work` 是真爱（67%/100%），`ai-tools` 是幻觉（收 15 读 1）——但老化曲线揭露了更残忍的细节：91–180 天桶读率 100%、新桶只有 40%——**阅读习惯的崩塌是最近半年的事**。每周净增 1 篇，23 条 backlog 统计上永不清空；`budget` 会告诉你杠杆 B（少收）算出的配额是负数——光停止收藏都不够，必须同时加读。

## 验收标准

全部转成自动化测试（`python3 -m unittest discover -s later-never/tests`，48 个用例）：

1. **账本严谨**：5 列 TSV；坏日期 / 列数不对 / 空 id / 重复 id / read_at 早于 saved_at 一律拒绝（exit 2）；写回 roundtrip 不丢字段。
2. **t½ = 中位数**：示例账本断言 9.0 天；构造含 90 天异常值的数据，中位数纹丝不动；已读 <5 条时拒绝计算（显示「样本不足」而非数字）。
3. **坟场率**：示例断言 10/41；边界（age=187 vs 180）落桶正确；已读条目永不计入。
4. **老化曲线**：四桶 n 与读率精确断言（7/15/5/14）；桶边界 age=30/31、180/181 有专测。
5. **速度与 ETA**：90 天窗口边界（恰好在 cutoff 上的收藏不计入）；摄入 ≥ 消化 → ETA 为 ∞；消化 > 摄入 → 周数精确。
6. **幻觉类型**：需同时满足 ≥10 条与 <20% 读率，4 条全未读的小样本**不**给帽子；双标签条目计入两个 tag。
7. **手术单确定性**：R1 用 `max(4×t½, 30)` 门槛（age=36 的 ca7 不入、age=71 的 es9 入）；R2 要求所有 tag 均为幻觉；t½ 缺失时退化到绝对阈值并如实标注。
8. **配额**：drain = backlog/周数精确；示例账本的摄入配额为负（「光停收都不够」分支可触发）。
9. **Pocket 导入**：只取 Read Later 段（Read Archive 不进账本）；坏时间戳条目跳过；日期按 UTC 折算保证跨机器一致；tags 逗号分隔转分号。
10. **CLI 契约**：exit 0/2/3/4 各就各位（2 用法错 / 3 拒绝审计 / 4 坟场闸门）；`--today` 钉死则两次运行逐字节相同。
