# 回血 · Recoup

> 卖不掉不是因为行情差，是你的锚还停在原价：把闲置处置记成一本事件流账本，市场对每件在架闲置的判决——该出手、该降价、还是该白送——第一次有两条算出来的线。
> It's not a bad market; it's your anchor still living in the past. Recoup replays your second-hand listings into a ledger of market verdicts: the offer line and the white-gift line.

---

## 一句话

闲置挂上二手平台的那一刻，定价就锚死在了沉没成本上——「当年 3,588 买的，挂 2,000 已经很亏了」，而市场只认清算价值：无人问价不是「行情差」，是市场每周重申一次判决，只是这个判决从没被任何账本记录；于是物件躺在阳台吃灰、心却被每月挂在「再等等能卖更高」的幻想上，最后多半白送甚至扔掉，空间和心智的成本从不进入「卖了多少钱」的对账。本件把闲置处置记成一本可手编的事件流 TSV（`events.tsv`：list 挂出 / price 改价 / ask 询价 / sold 成交 / gave 白送 / trash 丢弃 / pull 下架自留），重放出四本账：**清算回血率**（示例账本 14 个挂单周期成交 4 件，回血 ¥1,810 ÷ 投入 ¥5,596 = **32.3%**，金额加权）、**询价漏斗**（14 挂出 → 7 被询价 50.0% → 4 成交）、**降价弹性**（5 次降价的降价前/后 14 天询价率对比，响应比 2.00x →「市场在看，是价不对」，降价无响应则是「别磨价了，市场没在看你」）、**品类校准**（先验只是垫底——你自己的成交样本 ≥ 3 时，你的账本就是你的手册）。在架闲置逐件过**四灯状态机**：GREEN（市场还在看）→ YELLOW（降温/价未对齐）→ RED（**出手线**：最高出价 ≥ 挂价 80% 还捏着不卖，钱包在敲门——示例里电饭锅挂 ¥330、有人出 ¥350 已捏 39 天；或**幻想价**：显示器有真实出价 ¥700 却按 900 挂了 102 天）→ DEAD（**白送线**：零询价超过品类白送线，市场已宣判残余价值 ≈ 0）。示例实测：平板挂了 171 天零询价，越过 84 天白送线的 2 倍——**恋物警报**（exit 4）；`simulate` 给出在架回血区间账：上界 ¥6,367（全部按品类基线回血）、下界 ¥4,428（DEAD 归零），**幻想敞口 ¥1,939**——还在做梦的钱，和已经在架上躺掉的 622 个件·日。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 整理完柜子、闲置拍照挂上闲鱼/转转的断舍离人；搬家/换城市前要清仓大件的家庭决策人；给孩子换下来一批用品、挂了三个月无人问价还舍不得降价的父母；「挂着反正不亏」的定力越强、阳台越满的人。 |
| **场景** | 挂单两周没人浏览、开始怀疑「是不是行情差」的那几天；收到「300 出不出」却想着「这价我不如留着」的时刻；每次整理都看到那件挂了三个月的平板、每次都点开「编辑·降价」又退出来的晚上；搬家前一周，发现清仓所得远低于预期的慌乱。 |
| **问题** | ① **定价锚在沉没成本**：直觉按「原价 × 对折感」定价，而二手只认清算价值——挂价隐含回血率与市场已实现回血率的差（锚税）从不被计算；② **无人问价没有分母**：市场对每件挂单的判决（多少天无人问 = 无兴趣）散落在平台 UI 里，没有任何账本累计，于是「再等等」永远成立；③ **空间占用从不入账**：挂单躺在架上的每一天都在烧空间和心智，但这笔持续成本不出现在任何「卖了多少」的对账里——白送显得像亏损，其实常常是止损；④ **降价没有弹性数据**：降 100 没人理，就更不敢降——可降价到底 summon 不 summon 询价，只有对比降价前后窗口才知道；⑤ **出价被辜负**：真实出价是钱包投票，「出 350 的我嫌低，出 300 的我没看见」——出手线（出价 ≥ 挂价 80%）被辜负的那一刻，市场已经举手。 |
| **价值与意义** | ① **两条判决线进场**：出手线（有真实出价捏着不卖 → 接受或降到出价之下）与白送线（零询价超期 → 市场宣判 ≈ 0，送人回收空间）——「该不该再等」第一次变成一个可检查的日期，而不是一种感觉；② **锚税显形**：在架挂价的隐含回血率中位 vs 自己账本已实现的品类回血率，差值超过 30pp 亮红线——整个架子按回忆定价时，工具会说话（exit 4）；③ **恋物警报**：零询价超过白送线 2 倍（示例：平板 171 天 vs 84 天线）——继续挂是负持有（shelf bills you daily, the tag pays nothing）；④ **降价弹性实证**：降价前后 14 天询价率对比分三档判级（RESPONSIVE ≥ 2x / WEAK / NO-RESPONSE），降价救不救得动，用数据说话；⑤ **幻想敞口**：simulate 给出在架回血的上界/下界区间与差额——还在做梦的钱一次说清；⑥ 先验诚实：品类默认表是常识值不是平台数据，只在你自己的成交样本 < 3 时垫底，账本长起来后你的成交史就是你的手册；⑦ 零依赖 + 纯本地 + 不连平台不爬行情，卖不卖、送不送仍是人的决定。 |

## 核心思想：把「再等等」换成两本账——市场判决账与空间占用账

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **清算回血率** | Σ 成交价 ÷ Σ 原价（金额加权，按品类可分解、可加总还原） | 「我的东西在市场上真实能回多少血？」——不是「我觉得值多少」 |
| **询价漏斗** | 挂出 → 被询价 → 成交，三级转化率 | 「问题出在曝光、价格还是品类？」 |
| **四灯状态机** | 零询价：< 0.5× 白送线 GREEN，≥ 0.5× YELLOW，≥ 白送线 DEAD；有询价：出价 ≥ 80% 挂价 RED（出手线），出价低但超白送线 RED（幻想价） | 「市场对这件东西的判决进行到哪一步了？」 |
| **出手线** | 最高出价 ≥ 当前挂价 × 0.80 未成交 | 「钱包在敲门，我还要不要端着？」 |
| **白送线** | 零询价持续超过品类白送线天数 → 残余价值 ≈ 0 | 「再挂下去，除了灰还能收获什么？」 |
| **恋物警报** | 零询价挂龄 ≥ 2× 白送线（exit 4） | 「我留着的是东西，还是沉没成本？」 |
| **锚税** | 在架隐含回血率中位 − 品类已实现回血率中位；> 30pp 红线（exit 4） | 「我的整个架子比我的成交史贵多少？」 |
| **降价弹性** | 每次降价前后 14 天询价率对比；响应比 ≥ 2x RESPONSIVE / < 1x NO-RESPONSE；样本 < 3 次降价拒判 | 「降价到底有没有用？我的东西还有救吗？」 |
| **幻想敞口** | 在架上界（全部按品类基线回血）− 下界（DEAD 归零） | 「我还在做梦的钱是多少钱？」 |

三条设计立场刻在实现里：**先验只是垫底**——品类默认表（3C 白送线 84 天、家具 112 天、服装 56 天……）是常识值不是平台数据，只在你自己该品类成交样本 < 3 时垫底并显式标注 `prior`，`--cat name:sell:dead:ratio` 可扩展新品类——账本不是数据是假设，账本长起来后你的成交史就是你的手册；**「今天」绝不取自系统时钟**——缺省 as-of = 账本最大事件日期，`--as-of` 显式钉死，同一本账任何机器任何时间跑出的结果逐字节一致；**拒答优先**——挂单周期 < 3、账龄 < 28 天、降价事件 < 3 次时如实 DECLINE（exit 3），宁可不说也不编一个判决。

**与近邻的边界**：cost-per-wear（每穿成本）量**持有端的利用率**（买了要穿够次数才不亏），本件量**处置端的变现率**（决定放手之后，怎么卖、何时认输）——一个是购买前的口子，一个是出手后的账；fridge-void（冰箱黑洞）记消耗品的结局、量浪费率，本件记耐用品的挂单周期、量清算率——冰箱里的结局以天计，架子上的判决以周计；dusty-subs（吃灰订阅）是「持续付费的闲置」，本件是「停止付费的闲置」——订阅的敌人是自动续费，闲置的敌人是幻想价；repair-ledger（续命账）裁决「修还是换」，是拥有期的维修经济学，本件裁决「卖还是送」，是处置期的清算经济学；move-line（挪窝线）算「搬家还是续租」的一次性迁移税，本件管搬家前那批东西怎么清——先算挪窝线，再跑回血账。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

## 账本格式

一本可手编的事件流 TSV（`events.tsv`，`#` 开头为注释行；结案动作不填金额）：

```
date	item	action	amount	paid	category	note
2026-03-01	电纸书	list	899	1999	electronics	吃灰两年，换新款前清仓
2026-03-20	电纸书	price	799		一周没人看，降 100
2026-03-25	电纸书	ask	700		能到地铁站自提吗
2026-04-02	电纸书	sold	700		28 天回血
2026-03-29	人类简史	gave			楼下漂流角，等不及了
```

规则：`list` 行必须带 `paid`（当年买价）与 `category`（品类别名，可用 `--cat` 扩展）；`ask` 行 `amount` 是对方出价，可空（纯咨询不进出手线，但进询价数）；`price` 提价合法（现实中会改价重挂），弹性只统计降价；`sold/gave/trash/pull` 结案，`sold` 必须带成交价；同一物品结案后可重新 `list`（下架重挂/换平台），开新挂单周期。

## 用法

```
python3 recoup.py report     events.tsv [--as-of 2026-08-20]   # 总账+漏斗+四灯+锚税
python3 recoup.py stale      events.tsv                        # 在架逐件判决（恋物警报）
python3 recoup.py elastic    events.tsv                        # 降价弹性三档判级
python3 recoup.py verdict    events.tsv 电饭锅                  # 单件判决与行动建议
python3 recoup.py simulate   events.tsv                        # 在架回血区间与幻想敞口
python3 recoup.py categories events.tsv                        # 品类校准表（先验回退标注）
python3 recoup.py validate   events.tsv                        # 账本体检
```

Exit 码：`0` 正常；`2` 账本结构损坏（未挂先卖/重复挂出/结案带金额/坏日期）；`3` 拒答（样本太薄/查无此物/账龄不足）；`4` 红线（恋物警报/锚税超线/单件出手线或白送线双倍）。

## 验收标准

| # | 验收项 | 标准 | 状态 |
|---|---|---|---|
| 1 | 事件流重放 | list/price/ask/sold/gave/trash/pull 七种动作重放出挂单周期，结案后可重新挂出开新周期 | ✅ |
| 2 | 四灯状态机 | GREEN/YELLOW/RED/DEAD 按品类白送线判定，边界钉死：恰在 0.5× = YELLOW、恰在 1× = DEAD、零询价路径对挂龄单调 | ✅ |
| 3 | 出手线 | 最高出价 ≥ 挂价 × 0.80 未成交 → RED；恰在 0.80 触发、0.79 不触发；有高出价在架永不判 DEAD | ✅ |
| 4 | 白送线与恋物 | 零询价 ≥ 白送线 DEAD；≥ 2× 白送线 exit 4（report/stale/verdict 三处一致） | ✅ |
| 5 | 锚税 | 在架隐含回血率中位 − 品类基线中位 > 30pp → exit 4，判词点名「按回忆定价」 | ✅ |
| 6 | 恒等式 | 漏斗守恒（挂出 = 成交+送出+弃+自留+在架）；回血加总一致（report 现金 = categories 加总）；回血率金额加权（9 位小数）；simulate 敞口 = Σ DEAD_paid × 基线 | ✅ |
| 7 | 先验回退 | 品类成交 < 3 笔用先验并标注 `prior`；≥ 3 笔自动切实证（your ledger is the manual） | ✅ |
| 8 | 降价弹性 | 降价前后 14 天窗口询价率（按实际覆盖天数折算）；< 3 次可观测降价拒判 exit 3；RESPONSIVE ≥ 2x / WEAK / NO-RESPONSE 三档；提价不计数 | ✅ |
| 9 | 拒答 | 挂单 < 3 周期 / 账龄 < 28 天 / verdict 查无此物 → exit 3，输出 DECLINE | ✅ |
| 10 | 账本护栏 | 未 list 先事件、开周期重复 list、结案后再事件、sold 缺金额、gave/trash/pull 带金额、坏日期、负数、未知品类 → exit 2 | ✅ |
| 11 | 可复现 | 缺省 as-of = 账本最大事件日期，无 `date.today()`；`--as-of` 截断未来事件并披露条数；同账重跑逐字节一致 | ✅ |
| 12 | 测试与快照 | 65 tests 全绿；`recoup/examples/build_examples.py --check` 对账本与全部 8 份输出做字节级校验；CI 门禁 + advisory 快照 | ✅ |
