# METHODOLOGY · 雪崩 · Avalanche

## 1. 数据契约：只抄 App 肯给你的四个数

```
date	due	done	again	new
```

- `due`：App 首页的「今日到期」。**含逾期回炉、不含新卡**——这是 Anki 与墨墨的共同口径，也是本件全部动力学的基石：App 的 due 数已经把你昨天欠的滚进今天，所以 carried 不需要你记账，它就在 due 里。
- `done`：今日复习完成的卡数（新学另计）。
- `again`：done 里答错（遗忘）的张数。
- `new`：今日新学张数。

为什么手编而不读 Anki 数据库：①跨工具通用（墨墨/Quizlet/纸质 Leitner 盒都给得出这四个数）；②数字就在首页，30 秒抄完；③手编即审计——你抄的每一天都会被迫看一眼那个数，这本身就是本方法论的一部分。数据库导入、API 同步都是可行的下游工程，不改变账本语义。

`leeches.tsv` 是可选的**完整**遗忘名册（card/lapses）。「完整」是硬约束：validate 用 Σlapses ≡ Σagain 做双账核对，破即 exit 2。只录惯犯不录散卡，恒等式就不成立了。

## 2. 存量：carried 递推与卡·日债

- 第 t 日欠账：`carried(t) = max(0, due(t) − done(t))`。done > due 合法（提前清偿未来的到期，报告披露 paid-ahead 行数）。
- 当前积压：`B = carried(最后一天)`。
- 债（存量）：`debt = Σ carried(t)`，单位**卡·日**——每张逾期卡每躺一天计一天的债。
- 断更日（账本里缺席的日子）的债**没有入账**：那些天 carried 依然在，只是没人记账。所以 debt 是下界，报告在 idle days 行明说。
- 账外核销（forgiven）：某天 due < 前日 carried，意味着有卡没经过账面就离开了牌组（删除/暂停/导出）。这不是账坏（删卡是合法操作），但要披露——核销不是还债，是债消失了。

## 3. 流量：D、C、F 与两种利差

窗口 = 尾随 `--window`（默认 28）个**记账日**（不是日历日——断更日不占窗）。统计量取窗口内的**下中位数**（sorted[(n−1)//2)）：整数进整数出，对爆发日稳健，且逐字节确定。

- 到期压力 `D` = 中位(due)：App 眼里你每天面对多少。
- 清偿能力 `C` = 中位(done)：你实际每天付得起多少。
- **表面利差** `s = D − C`：今天的流血速度。积压越高，due 越高（欠账滚入），s 越大——这就是「越欠越快」的形状。
- 新鲜进水 `F` = 中位(due(t) − carried(t−1))：把积压惯性剥掉后，**老卡与新卡管道的真实回炉流**。核销行（fresh < 0）从 F 的样本中剔除并披露。
- **结构利差** `= F − C`：假设今天起新卡归零，老卡回炉是否仍快于你的清偿。正 = 这个牌组**在结构上无法自愈**，问题不在意志力在排程。

两种利差的分工：s 告诉你今天流多少血，F−C 告诉你止血带有没有用。

## 4. 崩盘投影：一条直线和一个日期

- 崩盘线 `--doom-line`，默认 **3×C**：积压超过三个日清偿能力时，复习已经从记忆作业退化为手指运动（你的手会自动替你按「简单」）。Anki 社区的经验法则「积压超过一天能清的量就该停新卡」是 1×C，那是 freeze 线；本件的红线设在 3×C，两者不冲突。
- 投影：`B(t) = B + s·t`，与崩盘线的交点即崩盘日。线性外推在积压滚入 due 的真实动力学下是**保守偏早**的（s 本身会随积压增长），警告系统宁早勿晚。
- `--doom-window`（默认 42 天）：崩盘日落入窗口 = `AVALANCHE` exit 4；更远 = `ACCRUING` exit 0（债在涨，但还有几个月的从容）；B 已越线 = `OVERFLOW` exit 4——**崩盘不是要来，是在发生**。
- s ≤ 0：`HARVEST`（s<0，还债中）/ `TREADING`（s=0，打平）。

## 5. simulate：三种未来

从 as-of 状态出发（默认 = 账本最后一天），三情景全部**速率恒定**投影：

- `as-is`：保持现状 → report 同一款崩盘日（跨命令一致性钉死在测试里）。
- `freeze`：新卡归零，按 C/天还 F/天 → 净还 `C − F`。净还为正给出**最早清零日**；净还 ≤ 0 = `MATH-DEAD` exit 4：冻结新卡在数学上永远清不完，**砍牌组或加时间是仅有的出口**。
- `accelerate X`（默认 2.0）：能力 ×X 再算一遍。

**F 恒定假设的诚实披露**：冻结后真实进水会低于 F（近窗新卡管道会排空），所以清零日是**最早下界**（真实只会更晚），而 MATH-DEAD 可能被高估（管道排空后 F 或许降到 C 以下）。两个方向都写在输出的 assumptions 行里；`--freeze-inflow` 允许你自己给定进水做敏感性——账本给判决也给你翻案的工具。
偿还恒等式钉死：`⌊B/net⌋ × net + 末日余数 ≡ B`，任何情景不平凡即账坏。

## 6. add：新卡配额闸

`quota = max(0, C − D)`：今天的余水管径。request ≤ quota → PASS；超过 → `LEVERAGED` exit 4。同时披露近窗 `new` 合计（管道存量）——样例账本在欠着 3352 张的 12 月，近 28 天还在往里加 840 张新卡。
配额是**今天的余量，不是终身额度**：新卡的第一个到期在明天，此后是终身到期流（≈7-12 次复习/卡，取决于你能记多久）。账本不建模终身流（那需要间隔与记忆模型），它只在你按下「+30」之前把今天的账摊开。

## 7. leeches：遗忘的帕累托

- 名册按 lapses 降序；**遗忘集中度** = 前 20% 卡占 Σlapses 的比例（样例 40.5%）。
- kill list：lapses ≥ `--leech-line`（默认 **8**，Anki 的 leech 判定同款阈值）。挂起建议附**救济下界** = kill list 的 lapses 合计 ÷ 记账日数——「每天至少少几张到期」，只是下界：惯犯卡的完整回炉贡献不止于此。
- 存在 kill list → `KILL-LIST` exit 4。挂起是建议不是执行——账本不动你的牌组。
- 双账核对：Σlapses ≡ Σagain（全史）。--as-of 截断回放时跳过（名册没有日期，无法截断），明说 n/a。

## 8. 薄账与退出码

- `< 7` 个记账日：report/add/simulate 的统计判级 DECLINE exit 3——样本撑不起中位数与外推；存量算术（backlog/debt）照常输出，**算术不因薄账沉默**。validate/leeches 的表级事实（逐行检查、逐卡名册）照常开庭。
- 退出码：0 正常；2 账坏（结构非法或双账不平）；3 薄账拒统计；4 门禁红（OVERFLOW / AVALANCHE / LEVERAGED / MATH-DEAD / KILL-LIST）。

## 9. 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `--window` | 28 | 流量统计的尾随记账日窗口 |
| `--doom-line` | 3×C | 崩盘线（张） |
| `--doom-window` | 42 | 崩盘日落入此窗口（天）即 AVALANCHE |
| `--leech-line` | 8 | 惯犯卡门槛（Anki 同款） |
| `--accelerate` | 2.0 | simulate 加速倍率 |
| `--freeze-inflow` | F | freeze/accelerate 情景的进水改写 |
| `--as-of` | 账本最大日期 | 截断回放锚点 |

零锚定：源码无 date.today()，缺省 as-of = 账本最大日期；显式给同一日期与缺省逐字节一致。报告只打 basename——同一本账任何机器任何一天跑出的结果逐字节一致，examples 快照由 CI 逐字节校验。

## 10. FAQ

**Q：我已经积压 2000 张了，这账本还管用吗？**
A：最管用的时刻就是现在。`simulate` 会告诉你冻结+加倍之后的最早清零日，或者给你 MATH-DEAD 判决——很多「再扛扛」在算术上就不成立，早一天知道比多扛一个月便宜。

**Q：墨墨没有 again 这个数怎么办？**
A：again 缺了可以记 0（遗忘率列显示 0%，leeches 双账按 0 核对），流量与债的全部机制照常工作。但你会失去遗忘帕累托——惯犯卡点名靠的是 again 流。

**Q：多副牌组怎么办？**
A：一本账一副牌（或一组同节奏的牌）。不同牌组的清偿能力是同一份注意力，混记会把两个排程问题搅成一个看不懂的数。

**Q：Anki 的当日重学步为什么不算？**
A：保守口径。again 卡按次日回炉计，真实 Anki 里步进重学当日内消化，本件把债记大一点——警告系统宁重勿轻。

**Q：为什么不做 Anki 插件？**
A：会做（读 collection.anki2 的 revlog 表可以直接生成 reviews.tsv），但那是管道不是方法论。账本的价值在「每日四个数 → 利差/崩盘日/惯犯」这层语义，它对任何 SRS 成立。

## 11. 设计取舍备忘

- **下中位数**而非均值：蜜月期的爆发日（151 张那种）不配代表你的能力；下中位让 C 偏小、D 偏小——C 偏小让崩盘线（3×C）与配额更保守，警告系统方向正确。
- **表面利差做投影、结构利差做判决**：s 含积压惯性（滚入效应），适合回答「照今天这个速度何时漫堤」；F−C 剥掉惯性，适合回答「这个系统还能不能自愈」。两个数都给，混用即错。
- **B ≥ 线即 OVERFLOW，不看方向**：即便 s<0（在还债），高于 3×C 的积压意味着当下的复习质量已经劣化——还债中的红灯是「继续还」，不是「没事了」。
