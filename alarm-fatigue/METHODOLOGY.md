# METHODOLOGY · 警报信用学

> alarm-fatigue 的信用分不是修辞，是一本从 git 痕迹确定性重建的账。本文记录每一条记账规则的动机、边界与已知局限。

## 1. 立场：度量警报，不度量人

flaky test 的真正伤害不是它自己红，而是它**让所有红灯贬值**。医疗安全领域研究 *alarm fatigue* 数十年：监护仪误鸣率上去之后，护士对真警报的反应时间系统性变长——信用一旦破产，连从不误鸣的警报也一起失去听众。测试套件同理：**套件的可信度不取决于测试数量，而取决于最不可信的那个红灯**。

由此推出本工具最重要的立场分离：**信用分不是责任分**。一个连实现一起修好的负责任的 flaky 修复（`signal` -10）和一个纯调测试的糊弄（`solo` -5）都会扣分——因为信用账本服务的对象是**红灯的消费者**（那个看到红了决定要不要看的人），他不知道也不关心修复是否负责任，他只记得「这个测试哭过狼」。工程师的尽职与否属于 code review 的辖区，不属于信用局的辖区。

## 2. 五类信号：痕迹学，不是访谈学

所有信号都来自 git 历史的确定性事实，每类信号回答同一个问题的不同侧面：「这个警报有没有被证实误鸣过？」

| 信号 | 痕迹 | 为什么这个权重 |
|---|---|---|
| mute（-30） | diff **新增**行出现 skip/xfail 类标记 | 最重的罪：警报还挂在墙上，电池被抠了。未来所有真火警在此静默，且表面上「测试还在」 |
| focus（-25） | 新增 `.only`/`fit`/`fdescribe`/`focus: true` | 一次 commit 静音**所有同伴**——JS 世界经典的「全绿假象」。略轻于 mute 只因它常是误提交、通常很快被发现 |
| retry（-20） | 新增 `retries =`/`flaky(`/`@retry` 等 | 不修警报，改成自动重按。掩盖了不稳定性但承认了不稳定性——诚实的一半 |
| signal（-10） | 消息命中 flaky 词表 | 消息**亲口承认**这个警报误鸣过。最轻的痕迹：至少有人在认真对待它 |
| solo（-5） | commit 只改测试、不动实现 | 弱证据：大概率在「调测试让它过」。扣分轻因为误报存在（重构测试结构、补断言都是 solo） |

同一次 commit 命中多类时**只按最重的一类扣分**，其余作为 tag 附带（`mute + solo`）。理由：一次修补对信用的伤害是「事件」级的，信号类型只是这次伤害的定性，叠加扣分等于把一个事件记两笔账。

**burst（-10）** 是唯一的窗口级信号：14 天内 ≥3 次修补说明「修了三次还飘」——这不是运气差，是结构性的不可信。它加扣而不是乘扣，保持账本的可解释性：每一分都能指着一笔具体的 commit 说清楚。

## 3. 词表的克制：宁可漏报，不可指鹿为马

默认词表刻意**不放**裸 `retry`、裸 `skip`、`test` 这些高频词：

- `"retry uploads with backoff"` 是实现层的正当工作，不是测试修补；
- `"skip ci for docs-only change"` 是 CI 策略，与警报无关；
- 反过来，`fix flaky` / `stabilize` / `intermittent` / `rerun` / `偶现` / `随机失败` / `飘了` / `修测试` 这些词在提交消息里出现时，几乎只在谈论一个误鸣过的测试。

词表是**线索不是定罪**：solo 信号存在的原因之一就是给词表信号做交叉验证（一个含 `flaky` 的 commit 如果同时改了实现，更可能是根因修复；一个不含任何词表的纯测试 commit 则更需要 solo 来兜住）。`--signal-regex` 完全可替换，团队有约定俗成的消息黑话（比如 `greenify`）可以自己加。

## 4. 三条诚实条款

1. **出生不算修补**：`A` 状态（新建测试文件）永远清白，哪怕消息写着 "add flaky test"。TDD 的红-绿循环不是警报误鸣；一个测试带着 `skip` 出生（生而静音）在 v1 里也不入账——它从未误鸣过，只是从未响过（已知局限，见 §6）。
2. **解除静音是修复**：mute/retry/focus 全部只检测 **diff 的新增行**。删掉 `@unittest.skip` 的 commit（警报重新武装）不产生任何罚分——账本必须对称：装上电池免费，抠掉电池才收费，这样才有人愿意把电池装回去。
3. **删除进墓地，不进信用账**：被删除的测试文件入 graveyard，记录它死时的信用分。删除测试是终极 mute——把警报从墙上摘了——但对象已消失，继续记信用没有意义；墓志铭（`credit at death 70`）比任何判定更有叙事力。工作树存在性兜底处理 merge commit 内的删除与目录重构：一个「活着」但磁盘上不存在的测试文件就是被拆掉的警报。

## 5. 信用与偿还

- 起步 100，下限 0，四档判定 trusted(≥80)/shaky(≥60)/habitual(≥40)/deaf(<40)。档位不是统计推出来的，是**消费行为**的分界：≥80 红了就看；≥60 rerun 一次再决定；≥40 rerun 不过脑；<40 无人再看。
- 套件级指标用**中位数**而非平均数：一个 DEAF 测试 + 九个满分测试的平均数是 92（看着还行），中位数也遮住了它——所以报告同时给 `deaf` 计数：**中位数度量典型测试，deaf 数度量最弱一环，看报告永远两个一起看**。
- **信用可以偿还**：`--since` 只过滤修补事件、不过滤文件发现。半年前飘过、之后安静的测试，把窗口推到今天它就回到 100。这不是作弊而是语义正确：警报的消费者没有半年记性。想看全历史账本就不传 `--since`。

## 6. 边界情形的处置

| 情形 | 处置 | 理由 |
|---|---|---|
| merge commit | 完全不可见（`--no-merges`） | 它复述分支上已存在的真实 commit；两边都算会把每个合入的修补记两笔账 |
| 删除藏在 merge 里（目录重构） | 工作树存在性兜底入墓 | git 的 name-status 不展开 merge；磁盘上没有的「活」测试就是被拆了 |
| rename/移动的测试 | 旧路径入墓，新路径从零开始 | 不做 `--follow`：改名即断代。保守方向：宁可少记历史，不把两个文件的修补记到同一个头上 |
| 空提交、空消息 | 正常解析 | 消息为空不命中词表，不产生 signal；文件构成照常判定 solo |
| diff 预算 `--max-diff-commits` | 超出后最旧的 touching commit 降级为仅消息级 | `git show` 是唯一的开销大头；降级方向固定（丢最旧），且报告中明说 `capped`——mute/focus/retry 在预算外会漏检，signal/solo 不受影响 |
| 生而 skip 的测试 / CI 平台层 rerun | v1 不检测 | 前者从未误鸣；后者（Jenkins rerun 按钮、GitHub re-run）不在 git 里。见 §7 |
| 一个 commit 改多个测试文件 | 每个文件各记一笔 | mute/retry 本来就是文件级 diff；solo/signal 是 commit 级，对其中每个被改的测试文件都成立 |

## 7. 已知局限

- **看不到 CI 平台层的 rerun**：本工具只读 git。真正的误鸣率（红→rerun→绿）活在 Jenkins/GitHub Actions 的日志里，那需要平台 API 和网络——与「零依赖纯本地」的交付形态冲突。git 层的修补痕迹是误鸣的**下界**：每个 `fix flaky` commit 背后通常站着若干次没人记录的 rerun。
- **词表依赖语言习惯**：默认词表覆盖英文与中文的高频表达；法语/日语仓库请用 `--signal-regex`。solo/diff 级信号不受语言影响。
- **信号词的假阳性**：`fix flaky test` 修的可能是一个真 bug 的间歇性复现（警报其实没误鸣）。这类误差方向固定（多扣不少扣），对「找最伤信用的测试」这个排序用途无害。
- **信用分跨团队不可比**：罚分体系是序数不是基数——它排序同仓库内的测试很可靠，拿 A 团队的 70 和 B 团队的 70 比较没有意义（提交消息文化不同）。
- **删除即遗忘**：墓地里只留死时信用与日期，修补明细在 v1 的 audit 文本报告里不展开（`explain` 对墓中文件可用）。

## 8. FAQ

**Q: 为什么罚分是 30/25/20/10/5 这种整数？**
可解释性优先。信用账本的每一分都要能指着一笔 commit 讲成故事；对数或连续衰减曲线会让「为什么是 47 分」变成数学题。整十的罚分让 explain 的逐笔账本人人可以心算。

**Q: 一次诚实的重构把测试文件拆成三个，每个都变成「新建」，旧文件的修补史怎么办？**
旧文件入墓，三个新文件从 100 开始。这是 rename 断代的自然推论——账本宁可失忆，不可错认。

**Q: 我们的 flaky 治理流程是开 PR 标 `quarantine` 标签，不走 commit。**
词表与 glob 都可配；若标签只存在于 CI 平台，git 层确实看不见——这类流程属于 §7 说的平台层数据，v1 有意不碰。

**Q: 和 todo-rot / churn-hotspot 有什么不同？**
todo-rot 看实现代码里的承诺（TODO 注释）的偿还半衰期；churn-hotspot 看实现代码哪里流血最多；本件看**测试套件的警报信用**——三者共享「git 历史是账本」的世界观，度量的是三种不同的债：承诺债、维护债、信用债。

**Q: 修好一个 DEAF 测试后，信用怎么涨回来？**
拆掉 skip（解除静音）不扣分但也不加分——涨回来的唯一路径是时间加 `--since`。刻意没有「修复 PR 加分」机制：任何可以人工申报的加分项都会被申报污染，就像所有可以表演的指标最终都会被表演。

**Q: 为什么 exit 4 是 `--fail-under` 而不是「存在 DEAF 即失败」？**
门禁要的是**趋势可谈**：中位信用 60 的团队先守住 55 再谈 80；一刀切的 DEAF=失败会让有历史包袱的团队永远红着——永远红着的门禁，就是又一个没人看的警报。工具不做它自己反对的事。
