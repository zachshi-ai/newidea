# 增项镜 · Scope Creep

> 装修合同写着 ¥88,938，结算单写着 ¥103,664——中间的 ¥14,726 没有一笔是「意外」：防水不加楼下遭殃、找平不做瓷砖空鼓、清运不运没法住人，每一笔在它被提出来的那天都无比正确。**失控从来不在单笔里，只在加总里**；而加总只有在结算日才被第一次看见——那时钱已经付完了。

## 它是什么

一本手编的装修变更账本（3 个 TSV + 一个零依赖 Python CLI）。把**合同报价单、变更单流水、结算锚**钉成同一本账，在三个时刻给你三样从来没有人给过的东西：

| 时刻 | 账本回答的问题 | 命令 |
|---|---|---|
| 签约前 | 这份报价单里，哪些工序**没被写**？ | `census` |
| 施工中 | 照这个节奏，竣工时会超多少？这笔待签的变更该不该签？ | `report --as-of`、`court` |
| 结算时 | 到底超了多少、超在哪、是谁提的？ | `report`、`validate` |
| 比价时 | A 家比 B 家便宜的 ¥8,492，是便宜还是**沉默**？ | `compare` |

## 角色 / 场景 / 问题 / 价值

| | |
|---|---|
| **角色** | 第一次装修的家庭业主——装修是一生只做一两次的大额采购，正因为只做一次，经验值永远是零；10–30 万的客单价让每个百分点的增项都是几千到几万 |
| **场景** | ①拿着两三家报价单比价，各家拆项粒度不同，总价最低的可能恰恰漏项最多；②施工中工长隔三差五拿着变更单来「这个要加钱」；③竣工结算对着一叠单据想看清全貌 |
| **问题** | 报价单是静态的、施工是动态的，没有工具把两者钉成一本账。**报价单里没有的工序不是不会被施工，只是还没被报价**——低价签约、变更收网是行业公开套路；增项当场每笔都合理（防水真的不能省），失控只在结算日显形；「谁提的变更」被结算单淹没——业主主动升级与施工方伏兵长得一模一样 |
| **价值** | 签约前：缺席工序点名（缺席不是缺数据，是还没开价的负债）；施工中：变更率投影预警——样例账本第 61 天就亮出「照此节奏竣工 17.46%」，比结算日早 48 天；结算时：恒等式审计 + 变更分解 + **被动增项率**（样例 79.41% 的增项是施工方提出的——低价合同是分期付款买的）；比价时：把「表面差价」分解成「共同溢价 + 单方沉默」 |

## 样例账本讲了什么故事

老陈家，89m² 两居，全包合同 ¥88,938（2025-10-01 开工，计划 101 天）：

- **census（签约前就该跑）**：报价 15 项里没有防水、没有垃圾清运、没有管理费——三个 HIGH 缺席，`AMBUSH PRE-LOADED` exit 4。这三笔后来真的全部以变更单回来了，分文不少。
- **report --as-of 2025-12-01（第 61 天）**：变更率 10.55%（线 5%），投影 17.46% 越 15% 伏兵线——`FORESHADOW` exit 4。这一天掀桌谈判还来得及。
- **report（结算后）**：10 笔变更净 +¥14,726（+16.56%），`AMBUSH`；被动增项率 79.41%（线 50%）——`LOWBALL`，12,726 元的正变更是施工方提出的，业主自己升级只花了 3,300；按实结算重算占 36.17%——「水电预收 100m，实结 156m」。
- **court**：结算日工长还在喊最后一笔「壁龛 1,100 顺手做」——签完是 17.79%，`REDO` exit 4。
- **compare**：B 公司报价 97,430 贵 8,492，其中 5,920 是 A 报价里**沉默的工序**、共同工序 B 只贵 2,572；A 的实际结算 103,664 反超 B 的报价 6,234——低价是分期付款。

## 方法一句话

变更率 =（结算 − 合同）÷ 合同；投影 = 当前变更率 × 总工期 ÷ 已耗工期（只在开工后、结算前存在，拖期不放大量）；低价饵灯 = 施工方提出的正变更金额占比。

## 快速开始

```bash
python3 scope-creep/scope_creep.py \
  --quote scope-creep/examples/quote.tsv \
  --changes scope-creep/examples/changes.tsv \
  --meta scope-creep/examples/meta.tsv census

python3 scope-creep/scope_creep.py --help
```

三个 TSV（[examples/](examples/) 有完整样例）：

- `quote.tsv` —— 合同报价，一行一项：`category/item/unit/qty/price/amount`
- `changes.tsv` —— 变更单流水：`date/type/category/item/unit/qty/price/amount/who/reason`；**date 留空 = 现场喊价还没签字（pending），不进结算**；type ∈ add/deduct/upgrade/reaudit（重算按实结算，可正可负）；who ∈ owner/contractor
- `meta.tsv` —— 键值：`mode`（full 全包 / half 半包 / clean 清包，决定漏项先验的范围）、`start`、`plan`（计划竣工）、`settle`（实际结算日）、`settle_amount`（结算额，给定则 validate 钉恒等式）

类目支持中英别名归一（`waterproofing`≡防水、`泥工`≡瓦工、`按实结算`≡reaudit、`工长`≡contractor）。

## 判级与退出码

| 退出码 | 含义 |
|---|---|
| 0 | 绿/黄（HEALTHY、CREEP 披露、ACCEPT/NEGOTIATE） |
| 2 | 账坏（恒等式破、非法行、结算日后变更、引用未报价类目） |
| 3 | 薄账拒判（统计判级 DECLINE，算术照出） |
| 4 | 红灯（AMBUSH / FORESHADOW / LOWBALL / HIGH 缺席 / REDO） |

判级线全部可调：`--creep-line 5`（行规常态：增项 ≤5% 属正常误差）、`--ambush-line 15`（本件先验：低价饵收网区）、`--lowball-line 50`（施工方提出过半 = 系统性漏项）。部分城市有「增项超合同 8% 业主可拒付」的地方规定——把它设进 `--ambush-line` 即可。

## 诚实条款

- 账本**从不说某笔增项不该做**——防水是真的要做；它只说：谁提的、在不在报价里、签了之后账变成什么样。补不补防水、签不签壁龛，永远是人的决定。
- census 的缺席不是判决书：清包半包主材自理、老房改造拆改难免、有的公司把吊顶并进木工——类目粒度错位时用 `--extend` 教它，本地知识永远赢过通识。
- compare 不预测 B 家的结算——B 也可能增项；它只说 A 已经发生的账。
- 投影是线性外推的**预警不是预测**——增项后密前疏是常态，投影的价值是给出行动窗口，不是给出结算数。
- 不构成法律意见，不替你谈判；它把证据摆上桌，签字的手仍然是你的。

## 与近邻的边界

- **cart-line 凑单线**：同是「名义口径 vs 实付真相」，那边审计一次结算页的凑单幻觉，这边审计一份持续 6 个月的合同变更流；那边的恒等式是平台省略额 ≡ 凑单额，这边的恒等式是结算 ≡ 合同+变更。
- **move-line 挪窝线**：租房续约的涨租裁决（住房的持有成本），本件是装修施工的变更审计（住房的生产成本）。
- **optimism-tax 乐观税**：那边量「估算 vs 实际」的个人膨胀系数（时间），这边量「报价 vs 结算」的组织性漏项（钱）——机制形似，主体相反：一个是自己骗自己，一个是别人漏给你。
- **repair-ledger 续命账 / past-prime 超役**：那两本管买回来的东西的寿命与修换裁决；本件管一次性的建造过程本身。
- **redemption 赎契 / stealth-interest 暗息**：贷款与分期的利息数学；本件的 16.56% 不是利率，是范围蔓延——但「月供看着温和、总价早已越线」的直觉结构是同一个。
