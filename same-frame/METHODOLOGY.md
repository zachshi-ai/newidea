# METHODOLOGY · 同框 Same Frame

## 1. 核心洞察:缺席没有关机动画

家庭的重聚不会突然消失,只会把「全员到齐」的日期越拉越远。这个过程是渐进的,而渐进正是肉眼的结构性盲区:第一次缺了某个人,全家都记得;第二次有理由;第三次起它就成了新常态——**新常态不需要理由,这正是它危险的地方**。日历记你要去哪,相册记你拍过什么,家族群记你说过什么——没有任何一本账记录「全到齐」这件事的间隔,于是「我们多久没真正聚齐了」这个问题,每个家庭都答不出来,而且答错的方向永远一致(低估)。

本件的处理方式与仓库里所有「看不见的渐变」同族(fat-creep 的体重蠕涨、slow-leak 的用量蠕升):**不发明信号,只给分母**。间隔不是新发明的东西,它一直在那里,只是从没被数过;数过之后,「697 天」自己会说话。

## 2. 为什么判的是「组合间隔」而不是「谁的错」

账本里没有「谁没来」的灯,只有「谁多久没出现」的灯(FADED)和「全家多久没到齐」的灯(DRIFT)。这个区分是刻意的:

- **缺席者的账记给缺席者看,更记给在场者看。** 爷爷 652 天没出现在照片里——这个数字的读者不是爷爷,是每一个「以为上个春节他还在」的人。人的记忆会自动把最近一次「应该在场」当成「在场」,账本不给这个错觉留位置。
- **DRIFT 记给全体看。** 全家到齐不是任何一个人的责任,也不该由任何一个人独自张罗——但 697 天这个数字至少让「该张罗了」成为一句有出处的提议,而不是一句抱怨。

## 3. 为什么「从未全齐」比「隔太久」更响

DRIFT 灯有两个触发:间隔超线,或**从没有过全员同框**。后者更响,因为「从未」意味着「全员到齐」在这个账本的整个时间跨度里只是一个计划——它不是在变稀缺,它是没发生过。两种形态的文案不同(「last on …」vs「has never once happened」),exit 相同:4。

一个容易忽略的机制细节:成员注册是「首见即注册」,所以**只在第一行出现过的人,会把全员同框永久锚定在第一行**。这不是缺陷——他缺席了之后的所有聚会,每一次「不是全员」的聚会都在拉大这个间隔;锚定正是账本在说「他也在『全家』的定义里,尽管他不在场」。

## 4. 为什么没有「还能同框几次」

设计时被毙掉的功能。数据上它依赖寿命分布(人群先验抹到个人身上是伪精度);叙事上它把账本从「看见」推向「恐吓」——「爷爷还能同框 3 次」不是提醒,是威胁,而且极可能是错的。仓库的诚实条款在这里表现为一种克制:**账本不数还剩几次,只数已经空了多久**。看见空了多久的人自然会做该做的事;被「还剩几次」吓到的人只会关掉这个 App。

同理,没有 simulate:不模拟「如果每月聚一次会怎样」——聚不聚不由账本管,反事实的每一步都在暗示「按账本过日子就不遗憾」,这是在卖没有的东西。

## 5. 判级阈值与谦卑

| 灯 | 条件 | 说明 |
|---|---|---|
| 🔴 DRIFT | 全体同框间隔 > full-line(缺省 365 天);或从没有过全员同框 | 365 = 一年一聚的家庭刚好贴线不亮;半年一聚的家庭超过线就该被看见。恰线不亮:超一天才亮 |
| 🔴 FADED | 某成员未出现在任何一行 > fade-line(缺省 365 天) | 「他从照片里退出去」的判线;对春节型家庭,缺席一整轮聚会才会触发——不冤枉只是忙的人 |
| 薄账 DECLINE | 聚会 <2 次 | 间隔至少需要两个时间点;成员表照出——账本刚开始记,不是它的错 |

线是设计常数 + `--` 旗标翻案(与仓库多数件一致):缺省值服务最典型的「一年一两聚」家庭,半年一聚或每月一聚的家庭应该改线,而不是被别人的节奏判红或判绿。

## 6. FAQ

**Q:这不是让人焦虑吗?**
焦虑的反面不是不看见。真正让人难受的是多年后翻相册才发现「上一张全家福是三年前」——账本只是把那一刻提前到今天,而今天还有得选。红灯文案全程不催促、不指控、不预测,只给数字:看见,然后由你决定。

**Q:谁记?全家一起记吗?**
一个人记就够(通常是那个每次都喊「来拍照」的人)。拍完照发家族群时顺手记一行;账本是私有的,群里的照片是公开的,两不冲突。

**Q:成员名写乱了怎么办?**
`--alias 爷=爷爷` 事后归一;归一后若同一行出现撞重(比如「爷」和「爷爷」本来是两个人、归一后变重复)会 exit 2——宁可拒绝,不静默合并两个活人。

**Q:为什么「全体」是写过的并集,而不是我定义的名册?**
名册要维护,并集零维护;且并集有一个名册给不了的性质:**从没写进任何一行的人不存在于「全家」的定义里**——想让他进入「全体」,就去聚一次,把他的名字写上。账本的结构在轻轻推你做对的事。

**Q:和 drift-apart 用哪个?**
都记也不冲突:那边管线上(视频/电话/消息的间隔),这边管线下(同框的间隔)。一句实话作为分界:**聊得再多,替代不了一张全员到齐的照片**。

## 7. 开发中自纠(测试与对拍当场抓住的)

- **手算三连错,程序三连对**:697(我算 698——8 月有 31 天)、334(我算 333)、397(我算 398)。「样例数字先手算再钉测试」的流程第 N 次把错抓在手算侧——程序与手算不一致时,先怀疑闰年、月末天数和自己的减法。
- **测试构造两次踩中「全员行把 full house 锚到最后一行」**:想测「间隔超线」,结果构造的账本最后一行也是全员,full house 的 gap 永远是 0。修法:间隔类测试的第二行必须是**部分在场**——这个构造错误本身恰好演示了账本的核心语义(全员锚定)。
- **「爷」和「爷爷」不是重复**——账坏网格测试一开始把两个不同成员名当成重复;重复的定义是**同一行内同一名字出现两次**,alias 撞重的检查在归一之后。
- **快照子进程必须跑在账本落盘之后**:build_examples 初版把账本写入和快照生成放在同一次遍历里,冷启动时子进程读不到账本,快照内容变成 exit 3 的报错文案且两次运行不一致。修法:先写账本,再拍快照——有依赖的产物,顺序就是正确性。
