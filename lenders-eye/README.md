# 银行眼 · Lender's Eye

> 征信报告印给你的是流水,银行读到的是风险——**同一份档案,两种读法,中间没有翻译**。「我都结清了」在银行眼里是「他借过网贷,结清的记录也还在」;「我就点点看额度」是你亲手按下的硬查询扣分键;「每月正常还款」背后 86% 的额度使用率写着「这人缺钱」。被拒通知只有「综合评分不足」六个字的黑箱,而所有修复手段都吃时间——等看见问题时,房子往往已经看好了。本件把央行自查报告抄成三本手编账,从审批的通识口径把档案重读一遍:**时间能治的给你愈合日历,治不好的给你清单**。

---

## 一、角色 / 场景 / 问题 / 价值

| | |
|---|---|
| **角色** | 准备申请人生最大一笔贷款(房贷/车贷)的人;以及点过白条/花呗/借呗/月付、不知道这些在央行档案上留了痕的年轻人——他们自以为「没借过钱」,档案上是另一回事 |
| **场景** | 中介或客户经理说「你先去打一份征信」;或者刚被「综合评分不足」拒了,不知道差在哪;或者买房前三个月,该先养一养还是直接冲 |
| **问题** | 征信档案的「自我读法」与「银行读法」是两套语言:自我读法是「我都还清了、没逾期过、信用很好」;银行读法是「近半年 7 次硬查询 + 3 笔网贷账户(2 笔结清了记录还在)+ 86% 额度使用率 = 高风险」。报告印的是流水、不翻译风险;审批窗口(近 2 月/近 6 月硬查询)、网贷笔数、使用率这些**审批员实际在看的东西**,报告一行都不算;而修复手段全部吃时间(查询滚出窗口、逾期过线),没人告诉你哪天能滚完 |
| **价值** | 申请前 3–6 个月把银行眼里的自己摊开成五盏灯:①**硬查询双窗**(样例:短窗 61 天 2 笔已收敛,长窗 183 天 7 笔超线);②**在贷网贷**(白条 1,200 在贷——一笔也是伤);③**结清幽灵**(花呗/借呗结清未销户——「结清 ≠ 消失」);④**额度使用率**(86.4%——降到优档需还 56,400);⑤**新鲜逾期**(2024 年那笔 30 天,2026-11-20 恰好滚出 2 年窗)。`gate` 把窗口滚到你真正申请的那天——**时间已经治好了查询和逾期,剩下两盏必须动手**;`clock` 把这个结论拆成愈合日历与动手清单 |

**本件不是**:不是审批预测(审批是收入/流水/社保/房屋本身的多变量黑箱,本件只翻译档案侧看得见的部分)、不是贷款建议、不是征信修复服务(没有任何「洗白」——时间和小额结清是仅有的两种合法修复,本件只告诉你各自的日程)。

## 二、账本形态

一个目录三份手编 TSV(`--dir`,缺省当前目录)。数据源是**央行征信中心每年 2 次免费自查报告**(线上简版/线下详版),抄录关键行就是全部数据工程——十行,一年两次:

```tsv
# accounts.tsv —— 账户账(核心账,必需;含已结清/已关闭,它们仍在档案上)
name	type	opened	limit	balance	status	lender
招行信用卡	credit_card	2019-03-15	100000	86400	active	bank
花呗	online_loan	2022-01-10	30000	0	settled	online
京东白条	online_loan	2024-11-15	8000	1200	active	online
```

- **status** 三态:`active` 在贷 / `settled` 结清未销户(档案上的僵尸——本件存在的理由)/ `closed` 已销户;**lender** 二态:`bank` / `online`(花呗/白条/借呗/月付/消费金融都算 online——判定看放贷方,不看产品名)
- 信用卡 balance = 当前账单欠额;贷款 balance = 剩余本金

```tsv
# inquiries.tsv —— 查询账(可缺席=无记录;自查不记,个人自查不进任何窗口)
date	agency	reason
2026-08-08	某消费金融	loan_approval
2026-09-05	某银行	post_loan
```

- **reason** 决定软硬:`loan_approval` / `card_approval` / `guarantee` 是硬查询(审批敏感);`post_loan` / `personal` / `periodic` 是软查询(永不进窗)——hard 不用你填,**报告写了什么就是什么**,少填一处少错一处

```tsv
# delinq.tsv —— 逾期账(可缺席=无记录;征信只记月档,1-29 天不上账本)
date	account	days
2024-11-20	招行信用卡	30
```

## 三、四命令

```
python3 lenders_eye.py report                     # 银行眼快照:账户结构+硬查询明细+五盏灯
python3 lenders_eye.py gate --product mortgage \
                    --apply-date 2026-12-01       # 假设那天申请:窗口滚到那天,逐灯 PASS/FAIL
python3 lenders_eye.py clock                      # 愈合日历(时间能治的)+ 动手清单(治不了的)
python3 lenders_eye.py validate                   # 恒等式与账本体检
```

公共参数:`--dir`、`--as-of`(时间机器,缺省 = 三本账最大日期,零墙钟)。先验全部 `--` 可翻案:`--hq-short-days 61` / `--hq-long-days 183` / `--short-line` / `--long-line` / `--online-line` / `--util-line` / `--delinq-window 730` / `--delinq-days`。`gate --product {mortgage, car_loan, credit_card}` 借用三套审批口径(房贷最严),`--apply-date` 缺省 = as-of。

### 五盏灯

| 灯 | 语义 | 缺省线 | 恰线 |
|---|---|---|---|
| 🔴 HOT-QUERY (short) | 近 2 月硬查询 | 61 天窗 > 3 笔 | 恰 3 笔不亮 |
| 🔴 HOT-QUERY (long) | 近半年硬查询 | 183 天窗 > 6 笔 | 恰 6 笔不亮 |
| 🔴 ONLINE-DEBT | 在贷网贷(lender=online 且有余额) | > 0 笔 | 0 笔不亮 |
| 🔴 MAXED | 信用卡总额度使用率 | > 80%(50–80% 🟡 HEAVY-USE) | 恰 80.0% 不亮 |
| 🔴 FRESH-DELINQ | 窗内 30+ 天逾期 | 730 天窗内有即亮 | 恰 730 天出窗 |
| 🟡 SETTLED-GHOST | 结清未销户的网贷(只点名不动 exit) | — | — |
| 🟡 MULTI-LENDER | ≥3 个在贷贷款账户(信用卡不算) | — | — |

### 退出码语义

| 码 | 含义 |
|---|---|
| 0 | 绿(clock 恒 0——日历是规划不是警报) |
| 2 | 账坏:坏日期(不补零/不存在的日历日)、未知 type/status/lender/reason、balance 超限、settled/closed 带余额、重复账户名、逾期引用不存在账户、逾期早于开户、days 非 30/60/90 档 |
| 3 | 空账(accounts.tsv 缺失/零字节/纯注释/有表头零行——报错文案教建第一行);`--as-of` 早于一切开户日 |
| 4 | 账面红灯:任一 🔴 亮(gate 则任一 FAIL) |

## 四、样例:小陈的档案(2026-09,想年底买房)

招行信用卡欠 86,400(额度 100,000),花呗/借呗结清了没销户,京东白条还挂着 1,200;半年里点过 7 次硬查询(点借呗额度、办信用卡、开白条……),2024 年 11 月有一笔 30 天的逾期(年费没提醒)。`report`(as-of 2026-09-30):**四盏红灯**——长窗 7 笔查询、白条在贷、86.4% 使用率、逾期在窗。

- **gate mortgage @2026-12-01**:窗口滚到申请日——长窗只剩 4 笔(7 月前的 3 笔自己滚出去了,≤6 PASS),逾期 delta 741 天出窗(PASS)——**时间已经治好了两盏**;剩下 FAIL 的两盏是白条和使用率——**治不了,必须动手**:结清白条 1,200、还 6,400 到 80% 线(还 56,400 到 30% 优档)
- **clock**:愈合日历——长窗 2026-10-02 愈合(4 月那笔查询滚出 183 天),逾期 2026-11-20 愈合(恰满 2 年窗);动手清单三项,**none of the above heals by itself**
- **时间机器**(`--as-of 2026-06-30`):半年前看,钱的问题(白条/使用率/逾期)早就三盏红——**查询的债是 7 月以后才欠下的**;档案上每一步都有日期,只是从来没人替你回头看
- **产品先验**:同一份档案,`gate --product credit_card` 全绿(口径宽:短窗 5/长窗 10/网贷 2 笔/使用率 95%/逾期档 90 天)——**先申请哪张卡、后申请房贷,顺序本身就是策略**

## 五、验收标准

| # | 验收标准 | 验证方式 |
|---|---|---|
| 1 | reason→软硬映射:loan_approval/card_approval/guarantee 硬;post_loan/personal/periodic 永不进窗(100 笔软查询也不亮) | 网格测试 |
| 2 | 窗口边界:delta 恰 182 在窗、恰 183 出窗;恰 729 在窗、恰 730 出窗;恰线不亮(3 笔不亮 4 笔亮、6 不亮 7 亮) | 阈值测试 + 字面值 |
| 3 | 使用率:恰 80.0% 不亮红灯(黄档 HEAVY-USE 披露)、80.001% 亮;无信用卡不判;Σlimit=0 不判;多卡加总口径(50,000+50,000 额度、40,000+20,000 欠额 = 60.0%) | 阈值 + 字面值 |
| 4 | ONLINE-DEBT 看 lender 不看产品名:active+online+余额>0 亮;settled 进 GHOST 不进 DEBT;closed 两边都不进;active 但 balance=0 不亮 | 语义测试 |
| 5 | FRESH-DELINQ 分层:`--delinq-days 90` 时 30d 档不亮、90d 档亮;窗外逾期进「档案在身」披露(2023-08-05 那笔 → 2028-08-05 出档) | 翻案 + 披露测试 |
| 6 | gate 窗口随 apply-date 滚动:12-01 申请长窗剩 4 笔 PASS、10-01 申请 7 笔 FAIL;早于 as-of 的 apply-date 看不见未来行;产品先验表可被单旗标覆盖 | 滚窗测试 + 字面值 |
| 7 | clock 闭式解与逐日扫描双路径全等(样例 + 11 笔超线构造 + 干净档案);逾期愈合 = **最新**一笔出窗日(老者先出窗)——多笔构造钉死 | 对拍恒等测试 |
| 8 | 时间机器:`--as-of` 缺省 = 三账最大日期;未来行排除(非报错,「unwritten future」);6-30 回放:长窗 4 笔绿、钱的问题三盏红 | 回放测试 + 字面值 |
| 9 | 账坏九类 exit 2(网格);空账四形态 exit 3 且文案教建第一行;inquiries/delinq 缺席合法(「no agency pull on record」) | 网格测试 |
| 10 | 恒等式:Σbalance 双路径(直接 == 按 type 分组)、硬查询计数双路径(线性 == 排序游标),字面值 87,600 = 87,600、7 hard / 3 soft | validate + 引擎级断言 |
| 11 | 零墙钟:源码无系统时钟调用;as-of 缺省自锚定;同账双跑逐字节一致;报告只打印 basename | 源码断言 + 双跑比对 |
| 12 | exit code 语义:report/gate 红灯 4、clock 恒 0、账坏 2、空账 3;干净档案 gate mortgage exit 0 且文案承认「approval is still a black box」 | 语义测试 |

## 六、与近邻的边界

- **[暗息](../stealth-interest/)**(消费分期):那边管**已经借到的钱的真实价格**(费率翻译,负债的成本),本件管**还能不能借到下一笔**(档案体检,负债的门票)——同一笔分期,那边算它贵不贵,这边算它在银行眼里脏不脏。
- **[赎契](../redemption/)**(房贷):那边管**贷下来的钱怎么还最省**(还贷端,对着银行算摊销),本件管**怎么才能贷到**(获批端,对着央行档案算窗口)——同一条贷款的两端。
- **[僵尸账号](../ghost-login/)**:同是「审计你忘掉的存量」——那边审计账号的攻击面(怕被陌生人打开),本件审计档案的审批面(怕被银行看见);僵尸账号靠注销止血,僵尸网贷户靠销户止血——结构同构,领域无关。
- **[暗基数](../shadow-base/)**(社保):那边审**公司替你缴了什么**(法定福利的缴存水位,对手方是公司),本件审**央行记了你什么**(信用档案的审批视角,对手方是未来的银行审批员)——同是「系统里的另一个你」。
- **[欠条](../iou/)**(亲友借贷):那边是你借**给**别人的债权(催讨与时效),本件是你从机构借**来**的档案(窗口与愈合)——一个怕别人忘,一个怕系统记得太牢。

## 七、诚实条款

- **阈值是通识垫底,不是审批标准。** 硬查询 61/183 天窗、使用率 80%、网贷零容忍——全部是流传在贷款圈里的通识口径,银行间、分行间、客户经理间口径都不同,全部 `--` 可翻案,**信贷经理说的永远赢**。灯亮不等于拒贷,灯灭不等于放款。
- **「综合评分不足」的黑箱不能被完全打开。** 审批是收入、流水、社保、负债、房屋本身的多变量模型,本件只翻译档案侧看得见的五个信号;`gate` 全绿的文案明说「approval is still a black box」。
- **「结清 ≠ 消失」是档案事实,「建议关闭」是客户经理的常见先验。** 各平台销户操作不同,账本只点名,不代操作;不做任何「征信修复」——时间和小额结清是仅有的两种合法修复,本件只告诉你各自的日程。
- **软硬查询抄报告,不猜产品。** 某个按钮点下去算不算硬查询,以你报告上写的那行为准——账本只记报告写了什么,不预测平台的行为。
- **征信是最敏感的数据。** 账本只存本地,不连任何接口,不上传任何字节;报告只打印账本目录名,不回显路径;数据源是你自己每年两次的免费自查,抄录十行是全部数据工程。
- **零墙钟。** as-of 缺省锚定三本账最大日期,`--as-of` 是时间机器不是今天;源码无系统时钟调用,同一本账任何机器任何一天跑出的结果逐字节一致。

## 八、快速开始

```bash
cd lenders-eye
python3 lenders_eye.py report  --dir examples                     # exit 4:四盏灯,设计内
python3 lenders_eye.py gate    --dir examples --apply-date 2026-12-01   # exit 4:时间治好两盏,剩两盏要动手
python3 lenders_eye.py clock   --dir examples                     # exit 0:愈合日历+动手清单
python3 lenders_eye.py validate --dir examples
python3 -m unittest discover -s tests                             # 54 tests
```

维护成本:每年两次免费自查时抄十行——这本账的全部成本,是看一眼「银行眼里的我」的顺手。
