# 旱涝保收 · Smooth Sailing

> 自由职业者的进账按项目来，生活却按月来——两个节奏的差，就是过山车本身。
> A zero-dependency CLI that pays a freelancer a steady monthly salary out of an unsteady income: burn rate, runway, a three-clamp paycheck engine, a tax jar, and a replay that shows how much smoother life would have been.

---

## 一句话

四万的项目款到账那个月，生活方式悄悄升级了；连续三个月没单，信用卡开始流转；年底税务局一次性收走那笔从来没人替你预留的税；「这个月敢花多少」这个问题，每个月都要靠焦虑重新投票一次。记账 App 只回答「花了多少」，从不回答「敢花多少」——因为它们按月孤立记账，从不把**钱的节奏**和**生活的节奏**放在同一本账上对时。`smooth-sailing` 的立场：**收入的旱涝是天意，生活的旱涝是机制**。工具从一本手编的月度现金流账（月份/进账/支出/月底现金/实缴税）确定性算出六本账：**体检**（进账分布 P10/P50/P90、波动率 CV、丰饥比、烧钱率、跑道）；**月俸**（下月该给自己发的虚拟工资，三重 clamp：基线 → 现金可支撑 → 死水位，发不足时如实说被谁卡住）；**反事实**（如果过去 24 个月一直用月俸法，消费波动会从 25.7% 压到 0%，饥月生活从「当月挣多少花多少」的 5,100 地板被抬到 9,000）；**税罐**（每笔进账先划一角进罐，名义现金 − 罐欠 = 真实可支配——样例里 24,700 的现金只有 8,030 是你的，其余 16,670 是税务局存在你这里的）；**压测**（断粮与腰斩两个情景各能撑几个月）；**对账**（cash[t] = cash[t−1] + income − spend 逐月核验，账对不上先修账再谈结论）。工具不发钱、不理财，它只造一台虚拟发薪机——丰月自动蓄水，饥月自动放水；发多少俸、接不接低价单，仍是人的决定。

## 它解决谁的、什么场景下的、什么问题

| 维度 | 说明 |
|---|---|
| **角色** | 收入不规律的自雇者——自由职业者、副业者、佣金销售、项目制合同工；上一笔进账五位数、这一笔还没影的人；从没见过「发薪日」这三个字出现在自己生活里的人。 |
| **场景** | 一笔大项目款到账，下意识把生活方式升了一级；连续空窗时靠信用卡和花呗过桥；年底补税一次性缴懵，才开始后悔没预留；想接一个低价单又不知道「不接的话现金流还撑得住吗」；每次打开记账 App，只看到过去，看不到许可。 |
| **问题** | **两个节奏的差没有账本**：进账按项目、生活按月，收入波动被 1:1 传导给生活——丰月的生活方式升级，在饥月变成负债。①「敢花多少」没有机制，全凭当月进账和焦虑投票；② 名义现金不是你的钱：税没有预提，年底一次性清算时才发现现金里有大半从来就是税务局的；③「还能撑多久」没有数字：现金 ÷ 真实月烧钱 = 跑道，没有人算过，于是「恐慌」取代了「还有 2.7 个月」；④ 尖峰污染判断：买设备那个月、补税那个月把均值拉高，「我一个月要花一万六」的错觉由此而来。 |
| **价值与意义** | 1) **体检账**：`report` 算出进账分布（P10 3,460 / P50 9,000 / P90 18,570，丰饥比 P90/P50 = 2.06x，最肥月是最瘦月的 8.2 倍）、波动率 CV 57.9%（判级 WILD——生活正以 1:1 跟着进账坐过山车）；**烧钱率用 trailing 6 个月中位数**而不是均值（9,000 vs 9,917——补税尖峰月 16,600 就在窗口里，中位数把它按住）；**跑道** = 现金 24,700 ÷ 9,000 = **2.7 个月**，低于 3 个月死亡线 exit 4——「慌」第一次有了刻度。<br>2) **月俸引擎**：`paycheck` 回答下月发给自己多少——自动基线 = trailing 收入中位 × 提取率（样例 6,900 × 0.90 = 6,210），再过三重 clamp：基线 → 现金可支撑 → 死水位（= 1 个月烧钱率，永远不发穿底）；被卡住时明说「现金 clamp：付全额会把水库压到死水位以下」，而不是给一个做不到的数字。<br>3) **反事实重放**：`simulate` 把过去 24 个月按固定月俸 9,000 重放——消费 CV 从 25.7% 压到 **0%**（零击穿，水库全程没碰死水位）；饥月（12/24 个月进账低于俸）若按「挣多少花多少」只有 5,100 的地板，月俸制把它们抬到 9,000（**+76.5%**）；而俸禄定成 15,000 的妄想版重放里 18/24 个月发不出全额、CV 反升到 47.2%——「月俸是机制还是愿望」，重放一次就有答案。<br>4) **税罐**：`tax` 按 10% 预提率把每笔进账先划一角进罐：应提 24,470 − 已缴 7,800 = **罐欠 16,670**，占现金 67%，远超 30% 悬崖线 exit 4——名义现金 24,700 里的**真实可支配只有 8,030**。「现金不少怎么还是慌」的病根第一次被点名：你在花税务局的钱。<br>5) **压测**：`stress` 从下月起推演两个情景——断粮（进账 = 0）跑道 2.7 个月、2026-12 见底；腰斩（进账只剩一半）净烧 3,902/月、跑道 6.3 个月。假设全部披露（烧钱冻结、不借新债、不砍支出）——「真实情况只会更好」。<br>6) **零依赖 + 纯本地**：Python 3.8 标准库；现金流是个人最私密的账，一行不出电脑。 |

## 核心思想：把「按项目到账的现金」折成「按月发放的月俸」

自雇财务和工薪财务的根本差异：工薪族的现金流自带低通滤波（月薪是平的），自雇者的现金流是原始脉冲（进账是尖峰）。工具的五条机制纪律：

| 概念 | 规则 | 回答的问题 |
|---|---|---|
| **烧钱率 median 纪律** | burn = trailing 6 个月支出的**中位数**——设备月、补税月、人情月是脉冲不是台阶，均值会被脉冲劫持，中位数不会 | 「维持我现在的生活，一个月真实烧多少？」 |
| **跑道红线** | runway = 月底现金 ÷ 烧钱率；低于 `--red-runway`（默认 3 个月）→ exit 4 | 「按今天的烧法，还能撑几个月？」 |
| **月俸三重 clamp** | 基线（trailing 收入中位 × 提取率，或手定）→ min(基线, 现金 − 死水位)；死水位 = `--float` 个月烧钱率，永远不发穿底；clamp 生效时必须说明被谁卡住 | 「下个月我能给自己发多少俸？」 |
| **平滑恒等式** | 重放里：期初现金 + Σ进账 = Σ月俸 + Σ税提 + 期末水库 + 税罐（恒等式测试钉死）——月俸法不创造钱，它只搬移钱在时间上的位置 | 「平滑的代价和收益各是多少？」 |
| **对账与缺口** | cash[t] = cash[t−1] + income − spend 逐月核验，容差 0.01；累计漂移 > 2% 总进账 → exit 2 先修账；**断月是证据缺失不是账坏**——缺口两侧不硬对账，跳过并披露，永不插补 | 「这本账配不配得上结论？」 |
| **税罐悬崖** | 罐欠 = Σ进账 × 预提率 − Σ实缴；罐欠 > `--cliff` × 现金（默认 30%）→ 悬崖灯 exit 4；真实可支配 = 现金 − 罐欠 | 「现金里有多少从来就不是我的？」 |

三条边界刻在实现里：**拒判优先于猜测**——不足 6 个月不给波动判级（exit 3）、不足 3 个月不给自动基线（exit 3，手定俸可越过大样本检查但越不过现金 clamp）；**重放不是预测**——`simulate` 只重演已经发生的 24 个月，对未来它只说「这是过去账本上站得住的俸」，不说「未来会是」；**anchor 是账本自己的日历**——同一本账任何机器任何时间跑出的结果逐字节一致（examples 快照有 CI 字节级校验）。

## 安装（零依赖）

只需 Python 3.8+，无需 `pip install` 任何东西。

```bash
python3 smooth_sailing.py report ledger.tsv
```

## 命令速查

```bash
python3 smooth_sailing.py report   ledger.tsv                      # 体检：分布/CV/烧钱率/跑道/对账，超死亡线 exit 4
python3 smooth_sailing.py paycheck ledger.tsv                      # 下月月俸：自动基线 6,210（三重 clamp）
python3 smooth_sailing.py paycheck ledger.tsv --salary 9000        # 手定俸：现金约束依然生效
python3 smooth_sailing.py simulate ledger.tsv --salary 9000        # 反事实：CV 25.7%→0%，饥月 +76.5%，0 击穿
python3 smooth_sailing.py simulate ledger.tsv --salary 15000       # 妄想俸：18/24 击穿，越俸越颠 exit 4
python3 smooth_sailing.py tax      ledger.tsv                      # 税罐：欠 16,670 = 现金 67%，悬崖 exit 4
python3 smooth_sailing.py stress   ledger.tsv                      # 压测：断粮 2.7 个月 / 腰斩 6.3 个月
python3 smooth_sailing.py validate ledger.tsv                      # 账本体检：断月披露 / 现金恒等式核验
```

## 账本格式

TSV，一行一个月，手编，UTF-8，`#` 开头是注释：

```
month	income	spend	cash	tax_paid
2024-10	9600	8900	18700	0
2025-06	15600	17800	26100	0
2026-05	5800	16600	25900	7800
```

- `month`：YYYY-MM，升序、唯一；断月允许，会被披露且缺口两侧不对账。
- `income`：当月总进账（税前口径由你定义，记账后保持一致即可）。
- `spend`：当月总生活支出（含还贷还卡——它们也是「生活」）。
- `cash`：月底现金余额（活期 + 现金 + 可当日取用的货基；理财、公积金不算——跑道问的是「还能撑几个月」，不是「账面有多少」）。
- `tax_paid`：当月实际缴税，可选，默认 0。

## 验收标准

1. **烧钱率 median 纪律**：burn = trailing 6 个月支出中位数；样例窗口内含 16,600 尖峰月时 burn = 9,000 < 窗口均值 × 0.92——尖峰月按不住均值的错误结构不存在。
2. **跑道红线**：runway = 月底现金 ÷ burn；样例 24,700 ÷ 9,000 = 2.7 个月 < 3.0 → exit 4；`--red-runway 2.5` → exit 0。
3. **波动判级与拒判**：CV = 总体标准差 ÷ 均值；<25% STEADY、<50% CHOPPY、≥50% WILD（样例 57.9% WILD）；账本不足 6 个月 → exit 3 拒绝波动结论。
4. **对账恒等式**：相邻月 cash[t] = cash[t−1] + income − spend（容差 0.01）；样例 23 个月漂移 0.00；人为塞入 3,000 差额 → report 与 validate 均 exit 2（先修账再谈结论）；**断月两侧不对账**，跳过数披露（seam skipped），永不插补。
5. **月俸三重 clamp**：自动基线 = trailing 6 收入中位 × 0.90（样例 6,210）；现金不足时 clamp 到 现金 − 死水位 并说明原因（exit 4）；现金已低于死水位发 0（FLOODED，exit 4）；不足 3 个月无 `--salary` → exit 3；`--salary` 为负 → exit 2。
6. **平滑恒等式与不劣化保证**：重放满足 期初 + Σ进账 = Σ月俸 + Σ税提 + 期末水库 + 税罐（样例残差 0.00e+00，测试钉死）；可负担俸（≤ P50 且零击穿）的模拟消费 CV 不高于实际消费 CV——「平滑让生活更颠」在数学上不可能；俸高于收入节奏时击穿月数如实披露并 exit 4（样例 15,000 → 18/24 击穿）。
7. **税罐与悬崖**：罐欠 = Σ进账 × rate − Σ实缴（样例 24,470 − 7,800 = 16,670）；真实可支配 = 现金 − 罐欠（8,030）；罐欠 > 30% 现金 → 悬崖灯 exit 4；多缴显示 REFUND 且 exit 0；`--rate` / `--cliff` 均生效。
8. **压测两情景**：断粮跑道与 report 的 runway 同源一致（同一 burn 函数）；见底月份逐月推演（样例 2026-12）；腰斩情景 burn ≤ 半均值时判「可持续」而非给无穷跑道；假设三件套（烧钱冻结/不借新债/不砍支出）必须披露。
9. **格式守卫**：缺列、短行、非数字、负进账、重复月、乱序月、空账本 → exit 2；无参数/未知命令 → exit 2 + usage；缺文件 → exit 2。
10. **确定性**：同一账本任何机器任何时间输出逐字节一致（`examples/build_examples.py --check` 在 CI 中做字节级校验）。

以上 10 条全部转成自动化测试：`python3 -m unittest discover -s smooth-sailing/tests`（69 tests）。

## 边界与诚实条款

- **它不发钱，也不理财**：月俸是把已发生的现金流折成可执行的提取规则，不是收益建议；「该留几个月跑道」随行业与风险偏好，红线可调，但工具不替你调。
- **它不实现税法**：税罐的预提率由你自定（默认 10% 只是占位），各税种、专项扣除、汇算清缴一概不在职责内——它只回答「按你的预提率，现金里有多少其实是税」。
- **它只记你声称的事实**：cash 是你月底抄的余额，工具不扫银行 App；正因为如此，对账恒等式才有牙齿——抄错的那个月会被恒等式点名。
