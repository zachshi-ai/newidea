# METHODOLOGY · 旱涝保收

本文写清楚每个数字的口径、每个设计决定背后的取舍，以及这台虚拟发薪机「不做什么」。

## 1. 为什么是「月俸」而不是「预算」

预算类产品回答「下个月各品类花多少」，它默认下个月的收入是够的——对工薪族成立，对自雇者恰好不成立：自雇者缺的从来不是**分配方案**，是**确定性**。四万进账的月份不需要预算建议，零进账的月份预算建议是讽刺。

smooth-sailing 反着来：**不做分配，只做发放**。把不规律的进账堆进一个虚拟水库，每月从水库里给自己发一笔固定的月俸——工资制的全部心理红利（可预期、可规划、月底不用投票）由此恢复，而代价只是接受「俸 ≠ 本月进账」这一件事。水库的收入侧是老天决定的，支出侧从此是机制决定的：**过山车被限制在水库以内，不再直接开进生活**。

## 2. 口径精确定义

### 2.1 烧钱率（burn）

```
burn = median(spend[-6:])
```

**中位数是本工具的第一纪律。** 生活支出里全是脉冲：买电脑的月份 +9,200、补税的月份 +7,800、春节的月份 +2,000。均值会被任何一次脉冲劫持（样例：窗口含 16,600 尖峰月时均值 9,917，中位数 9,000——差额 917 全是尖峰的幽灵）；中位数要求六个里至少三个月是「正常月」，脉冲再多也劫持不了。跑道、死水位、压测全部烧钱率同源——**一把尺子量全库**，不允许 report 用一把尺、stress 用另一把。

### 2.2 跑道（runway）

```
runway = cash / burn        (月)
```

- 分子是**可当日取用的现金**：活期、现金、随时可赎的货基。理财、公积金、别人的欠款不算——跑道回答「还能撑几个月」，锁到年底的钱撑不了下个月的房租。
- 3 个月死亡线是默认值不是真理：单干咨询可以放宽到 6，家里有全职伴侣可以收紧到 2。`--red-runway` 存在的意义是让红线跟随处境，而不是让处境迁就红线。

### 2.3 波动率（CV）与丰饥比

```
CV = pstdev(income) / mean(income)        丰饥比 = P90 / P50
```

CV 量「整体多颠」，丰饥比量「好月份比寻常月份富多少」。两者互补：CV 对尖峰敏感（一个 40,000 的大单能把 CV 抬过红线），丰饥比稳定（P90/P50 只挪一点）。判级线 25% / 50% 是约数：25% 以下生活的波动已经可以被信用卡平滑掉，50% 以上生活实质上跟着进账 1:1 坐车。**不足 6 个月不出判级**——三个月的「稳定」和三年的「稳定」不是同一个词。

### 2.4 月俸三重 clamp

```
baseline  = median(income[-6:]) × rate          (rate 默认 0.90)
headroom  = cash − float × burn                 (float 默认 1.0 个月)
pay       = min(baseline, headroom)             (headroom ≤ 0 时 pay = 0)
```

- **为什么基线打九折**：trailing 中位收入是「过去六个月的常态」，不是「未来的承诺」。九折是给收入自然下滑留的缓冲，也是税罐的默认来源；自定俸的人可以绕过这个折扣，绕不过现金 clamp。
- **死水位为什么默认一个月**：水库见底的正确姿势是「最后一个月没钱」，而不是「俸照发、然后某天卡刷不出来」。死水位是把「cash 不得低于一个月烧钱率」写成硬约束——它把跑道红线的静态警告变成了发放时的动态闸门。
- **clamp 必须署名**：发不足时输出明说被谁卡住（现金 clamp / FLOODED）。一个不解释理由就少发钱的系统，月底会被人类自己推翻。

### 2.5 平滑恒等式

```
start_cash + Σincome = Σpay + Σtax_setaside + end_pool + jar
```

月俸法不创造钱，只搬移钱在时间上的位置——这条恒等式是它的守恒律，测试钉到机器精度。它的推论同样重要：**俸定得比收入节奏高，水库必然逐月失血**（样例：俸 15,000 时 18/24 个月击穿），此时 CV 反升——「越俸越颠」。平滑有可行域，超出可行域的平滑是杠杆。

### 2.6 税罐（tax jar）

```
owed = Σincome × rate − Σtax_paid       real_disposable = cash − owed
```

自雇者最大的单次现金流屠杀是汇算清缴：税藏在每一笔进账里，平时是「我的钱」，年底集中现形。税罐把现形提前到每一笔进账当天——**每进一元，先划一角进罐**。预提率不实现任何税法（税率、专项扣除、征收方式因人因城而异），它只是一个「你在替谁存钱」的自定比例；悬崖线（罐欠 > 30% 现金）不是税务建议，是「你在花税务局的钱」的报警器。

### 2.7 对账恒等式与缺口

```
cash[t] = cash[t−1] + income[t] − spend[t]        (容差 0.01)
```

三个月现金抄错五块钱不可怕，可怕的是错了没人知道——恒等式就是「抄对了吗」的逐月审计，累计漂移超过总进账 2% 直接 exit 2（先修账，再谈一切结论）。**断月是另一回事**：缺口意味着那几个月根本没记账，缺口两侧的现金没法直接对账——这是证据缺失，不是账目腐败。工具跳过缺口（seam skipped）并披露，永不插补。把「没记」当成「记错了」惩罚，只会教人编数。

## 3. 重放不是预测

`simulate` 只重演已经发生的月份：把历史进账灌进水库、按固定俸发放、记录水库每一刻的水位。它回答「**如果过去你一直这样发俸，会怎样**」，不回答「未来会怎样」。这是刻意的能力收窄：

- 预测需要未来进账的假设，而未来进账恰恰是这本账里唯一没有的信息；
- 重放的全部数字（CV 前后对比、饥月垫高、击穿月数）都有严格答案，可测试、可复现；
- 但重放天然悲观——它不含「你会因此更敢报高价/更敢拒绝烂单」的行为反馈。把重放读成上界，把行为反馈留给现实。

## 4. 拒绝的权利

| 情形 | 行为 | 理由 |
|---|---|---|
| < 6 个月求波动判级 | exit 3 | 三个月的 CV 是噪声不是画像 |
| < 3 个月求自动基线 | exit 3（可 `--salary` 手定） | 中位数至少要能站住 |
| 现金恒等式累计漂移 > 2% | exit 2 | 账对不上的账本配不上任何结论 |
| 俸 > 收入节奏 | 如实披露击穿 + exit 4 | 发不出的俸是愿望，不是工资 |
| 罐欠过悬崖 | exit 4 | 现金里的非现金部分必须现形 |

宁可沉默，不给没有证据的许可——发薪机最大的风险不是发少了，是**发了一个做不到的数**，让人按做不到的数生活三个月。

## 5. FAQ

**Q：月俸和「留够应急金」有什么区别？**
应急金是一个静态数字（「存够 6 个月就安心」），月俸是一个动态发放规则（「每月发 min(常态九折, 水位允许)」）。静态数字会过期——存够那天你觉得安全，花掉两个月后数字失效而你毫无察觉；发放规则没有过期日，它每个月根据当下水位重新裁决。

**Q：奖金、报销、借款算 income 吗？**
口径三问：它是**劳动或资产的对价**吗（奖金是，报销不是）；它是**你的钱**吗（借款不是，它是负现金）；它会**重复出现**吗（偶发的卖旧物可以记，但要接受它抬高 trailing 基线）。记账后口径保持一致，比选「正确」口径更重要——账本最怕的是口径漂移。

**Q：房贷月供算 spend 还是单独处理？**
算 spend（还贷也是「生活」，砍掉它不是降级是违约）。但注意：spend 含固定负债时，burn 会比「可自由支配的烧法」高——这是诚实的，跑道本就该按最保守的烧法量。

**Q：为什么数字全是「月」？周或旬不行吗？**
可以调（把账编成旬甚至周），但月是自雇现金流天然的结算粒度（平台月结、房租月付、税月报），也是心理节奏的最小稳定单位——周太抖，季太钝。

**Q：模拟里 CV 压到 0%，是不是太理想了？**
是字面真实的：月俸制下你每月的生活支出就是俸本身，方差为零。现实里俸之内仍有品类间的挪移，但那不影响总量稳定——本工具量的是**总量节奏**，不是品类纪律；品类是预算的事，确定性是月俸的事。

**Q：水库里已经有花呗/信用卡分期怎么办？**
建议口径：把授信视为负 cash 记入当月底余额（cash 是净头寸）。工具不做信贷建模——跑道对「借钱撑 runway」保持沉默，因为那是把死亡线画在纸上。

**Q：和记账 App 一起用？**
正是预期用法。记账 App 管「分类与记录」（它回答花了多少），smooth-sailing 管「节律与许可」（它回答敢花多少）。前者每月给你看后视镜，后者每月给你发俸。
