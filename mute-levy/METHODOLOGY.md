# METHODOLOGY · 哑税 · Mute Levy

## 1. 累计预扣法（逐月重放的算法）

工资薪金的月度预扣按国家税务总局公告 2018 年第 61 号的累计预扣法：

```
本期应预扣预缴税额 = (累计预扣预缴应纳税所得额 × 预扣率 − 速算扣除数) − 累计已预扣预缴税额
累计预扣预缴应纳税所得额 = 累计收入 − 累计免税收入 − 累计减除费用(5,000×任职月数)
                          − 累计专项扣除(三险一金个人部分) − 累计专项附加扣除 − 累计其他扣除
```

本件的实现要点：

- **按雇主独立重放**——预扣的义务人是各个发薪单位，各自从该员工任职月起算减除费用与累计。这是「换工作必然少缴」的算法根源：两家各自爬梯子，税率表的低档被各爬一遍，加总落后于合并口径。**没有任何一方违法**，执行层面每一分都扣对了。
- 累计应纳税所得额为负时本期预扣 0（不向个人退税，负数挂账待后续月份回补）；低薪首月、大额年中入职都可能遇到。
- 同月两家发薪：各一行，各自进入各自雇主的累计序列。
- 专项附加扣除若已在申报，公司预扣时就减除了——所以 `report` 的重放**用 claims 里覆盖该月的扣除额**，重放结果与实缴对不上（HIDDEN-ITEM）通常意味着账本外还有东西（奖金混入工资行、免税收入、未记录的扣除变更）。

## 2. 年度汇算（settle 的算法）

```
应纳税所得额 = 全年工资薪金收入 − 60,000(减除费用) − 三险一金个人部分 − 专项附加扣除 − 其他扣除
应纳税额 = 应纳税所得额 × 年度税率表 − 速算扣除数
应补(退)税额 = 应纳税额 − 已预扣预缴税额合计
```

- 覆盖不满 12 个月时，减除费用按账本覆盖月数折算（5000 × N），报告披露「覆盖 N/12 月」——**账本不外推没有记录的月份**，年度汇算请以全年工资为准。
- 税率表（综合所得，全国统一，2019 年起施行）：

| 全年应纳税所得额 | 税率 | 速算扣除数 |
|---|---|---|
| ≤ 36,000 | 3% | 0 |
| ≤ 144,000 | 10% | 2,520 |
| ≤ 300,000 | 20% | 16,920 |
| ≤ 420,000 | 25% | 31,920 |
| ≤ 660,000 | 30% | 52,920 |
| ≤ 960,000 | 35% | 85,920 |
| 以上 | 45% | 181,920 |

此表同时也是工资薪金的累计预扣率表（按累计口径查找）——所以单雇主、无中断的账本，逐月预扣合计 ≡ 年度应纳税额；`validate` 把这当作恒等式钉死。**双雇主的账本不满足这条恒等式，差额就是结构性少缴**——这是本件最重要的可判级事实。

## 3. 年终奖单独计税（bonus 的算法）

全年一次性奖金可选择不并入综合所得（财税〔2018〕164 号，优惠经财政部公告 2023 年第 30 号延续至 **2027 年 12 月 31 日**）：

```
单独计税：应纳税额 = 年终奖 × 按月换算税率 − 速算扣除数（以 年终奖 ÷ 12 查月度表）
```

月度换算表（仅用于年终奖）：

| 全年一次性奖金 | 税率 | 速算扣除数 |
|---|---|---|
| ≤ 36,000 | 3% | 0 |
| ≤ 144,000 | 10% | 210 |
| ≤ 288,000 | 20% | 1,410 |
| ≤ 420,000 | 25% | 2,660 |
| ≤ 660,000 | 30% | 4,410 |
| ≤ 960,000 | 35% | 7,160 |
| 以上 | 45% | 15,160 |

**悬崖是这条表的形状，不是任何人的错**：36,000 元税 1,080（3%），36,001 元税 3,390.10（10%）——多发一元、到手少 2,310.10。另有著名的 144,000 悬崖（14,190 → 27,390.20，跳 13,200.20）。bonus 命令把悬崖位置摆在两口径差额旁边，供谈薪时对照。

三条分支的含义：

- **SOLO**：并入会把全年应纳税所得额推进更高档——高收入者默认 Solo 更省（样例省 3,006）。
- **MERGE**：全年收入低于 60,000 减除额时，综合应纳税所得额为负——并入不但免税还「白用」了减除额度，样例（年入 48,000 + 奖 20,000）MERGE 省 360。
- **EVEN**：税基与奖金同处一档时两条路分毫不差（税基 26,400 + 奖 9,600，都在 3% 档内）。

## 4. 哑税审计（gap 的算法）

专项附加扣除不会自动生效——它是**申报制**，而申报的默认状态是空白。gap 把这件事定价：

```
沉默月 = 资格覆盖月 − 已申报覆盖月（逐项、逐月）
近似哑税 = Σ 沉默月扣除额 × 边际税率（当前汇算口径所在档）
精确哑税 = 补报前应补(退) − 补报后应补(退)（两次 settle 的差）
```

近似值只在补报不跨档时等于精确值——所以报告以精确值为准，近似值只披露税率。样例：赡养老人沉默 8 个月（24,000 扣除额）+ 继续教育沉默 7 个月（2,800）→ 精确哑税 2,680，把 2,520 的补税翻成 160 的退税。

**哑税不是偷漏税**：漏报扣除只会让你多缴，从不构成违规；它定价的是「没有人有义务告诉你的成本」。这也解释了为什么它无声——税务局的申报页会列出你已申报的项目，但没有工具会列出你**有资格却没出现**的项目，因为资格藏在你的生活事实里（父母满 60、孩子入学、拿到证书），只有你自己知道。

## 5. 专项附加扣除先验（2023 年提标后，全国统一）

| 项目 | 标准先验 | 备注 |
|---|---|---|
| 房贷利息 housing | 1,000/月 | 首套住房贷款，最长 240 个月；与租房**二选一** |
| 住房租金 rent | 1,500 / 1,100 / 800 /月 | 直辖市省会计划单列 / 市辖区户籍>100 万 / 其他；`--rent-tier` 切档 |
| 子女教育 child | 2,000/月/孩 | 年满 3 岁至全日制学历教育结束 |
| 婴幼儿照护 infant | 2,000/月/孩 | 出生当月即可扣 |
| 赡养老人 elderly | 3,000/月 | 父母任一方年满 60 当月起；**独生子女全额**，非独生分摊上限 1,500（`--elderly-monthly`） |
| 学历继续教育 continuing | 400/月 | 职业资格为 3,600/年（取证当年），本件无月度先验，请显式填 `monthly` |
| 大病医疗 medical | 无月度先验 | 年度限额 80,000（自付超 15,000 部分），汇算时才能扣——请显式填月额拆算 |

先验只是**没填时的下限垫底**：`monthly` 列显式金额、`--rent-tier`、`--elderly-monthly`、申报过的实际分摊——本地事实永远赢过通识标准。

## 6. 语义与可复现性

- **全件无墙钟**：账本 = 一个自然年的闭环事实（跨年账本 exit 2 要求拆分），没有「今天」、没有 `--as-of`——汇算口径下不存在「进行时」，只有「这一年」。同账任何机器任何一天跑出逐字节一致，CI 快照按字节校验。
- 覆盖月语义：claims/eligibles 的覆盖月与账本覆盖月**取交**，越界部分截断并在 validate 披露——账本不假装它知道账外的月份。
- 数值口径：金额一律两位小数展示；判级比较用分位容差 0.011 元——**恰好在线上不亮灯**（浮点尘埃不该决定要不要补税）。
- 报告只打印账本 basename，不回显调用路径。

## 7. 边界（不建模什么，为什么）

| 不建模 | 原因 |
|---|---|
| 劳务报酬 / 稿酬 / 特许权使用费 | 预扣公式与汇算并入规则不同（20% 起减除 800 或 20%），混入工资流会双算 |
| 股权激励 / 经营所得 / 财产租赁所得 | 单独计税或单独申报，与工资薪金预扣体系不同轨 |
| 社保公积金的基数合规 | shadow-base 暗基数的领地；本件把三险一金当给定的扣除列 |
| 汇算期后的补缴与滞纳金计算 | 滞纳金按日万分之五、起算日复杂，账本只披露「窗口关了会怎样」，不替税务局计息 |
| 退税到账时间 / 地方人才政策 | 与算术无关 |

## 8. FAQ

**Q：个税 App 在汇算期不是直接显示应退/应补吗？要这个干嘛？**
App 显示的是**基于你已申报信息**的结果——它永远不会告诉你「你漏了一项可申报的扣除」，不会告诉你「补报后你的补税会变退税」，更不会告诉你「你每月的扣税里有多少是换工作造成的结构性少缴」。官方口径回答「按你说的，是多少」；本件回答「你没说的，值多少」。

**Q：我每月工资条上的税和这个工具重算的对不上，是公司扣错了吗？**
先检查三件事：当月有没有奖金混入工资行、账本里的专项附加有没有变更、有没有免税收入没记。这些都会造成 HIDDEN-ITEM。重放假设「申报信息即全部信息」——信息不全时对不上是特性不是 bug：它告诉你账本外有东西。

**Q：settle 说应补 2,520，我是不是该少缴点避免补税？**
不该，也做不到——预扣是法定公式，公司没有裁量权。应补不是罚款，只是「平时少缴了、年底一次结清」，无息（只要窗口内申报）。本件的价值是让这个数在 6 月之前就已知。

**Q：为什么年终奖不直接进工资条账本？**
发了就是既成事实，没有「二选一」可言。bonus 命令的价值在**发之前**：谈 offer、谈年终奖、HR 给选项的时候，两口径差额和悬崖位置才是决策输入。已并入工资发放的奖金，直接记进 payslips 即可，账本照实重放。

**Q：哑税线为什么默认 500 元？**
低于 500 元/年的沉默月（比如漏报一两个月的低额扣除）不构成「需要行动的账」；把它设成 0 则每一分沉默都亮灯，`--mute-line` 留给你自己定。这条线不是政策，是注意力预算。

**Q：会连个税 App 或银行接口吗？**
不会，永远不会。三个 TSV 全部手编——抄工资条的一年 12 行，是本件要求的全部数据工程。工资是敏感数字，不上传任何字节。
