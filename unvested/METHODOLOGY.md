# METHODOLOGY · 未兑现 · Unvested

## 1. 一句话

把股权报酬的**时间结构**从授予协议里解放出来,变成一本可对账的账本:哪些股已经是你的(AVAILABLE)、哪些还在悬崖对面(UNVESTED)、哪些已经飞了(F_WIN/F_UNVEST)、哪天会飞(行权窗口/期权大限)、以及「纸面 ≠ 到手 ≠ 落袋」的翻译。

## 2. 为什么是账本

股权报酬的全部信息都写在签署那一刻的 PDF 里,之后**没有任何系统对持有者的时间利益负责**:ESOP 平台给日程表但不给倒计时警报,HR 在离职谈话时才提行权窗口,估值只存在于下一轮融资的新闻里。三样东西组成了这本账:

1. **授予账(grants.tsv)**——合同的静态事实:几股、什么价、什么节奏、什么状态。一行一份授予,同公司 top-up 合法。
2. **事件账(events.tsv)**——动态事实:行权(掏现金买下已归属的股)、变现(把股变回钱)。作废**故意不做事件**——它由离职与窗口推算得出,让你手填等于鼓励双重记账。
3. **日程覆盖(schedule.tsv)**——授予协议的原始日程表。公式(等额分期)只是缺省,协议永远赢。

## 3. 核心模型

### 3.1 归属日程(cliff + 等额分期)

总月数 M = vest_years × 12;悬崖份额 = shares × cliff_months ÷ M(整除);剩余份额在悬崖后按 interval 等额分期,**余数全部落末节点**(10,001 = 2,500 + 11×625 + 626)。月末钳制:1 月 31 日授予,2 月节点落 2 月 28 日(闰年 29)。cliff = 0 时全部节点(含授予日当天)平摊总股数。cliff = M 时一次性归属。

### 3.2 六桶状态机

```
总股数 ≡ UNVESTED + AVAILABLE + EXERCISED + TENDERED + F_UNVEST + F_WIN
          未归属      已归属在册   已行权持有   已落袋     离职/清算作废  窗口/大限作废
```

- option 的 AVAILABLE 是「可行权未行权」;rsu 的 AVAILABLE 是「已归属未变现」(归属即到手,无行权环节)。
- F_WIN 由**窗口几何**推出:option+left 的授予,窗口 = end_date + window_days;as-of 越过窗口且彼时已归属未行权 >0 → 归零入桶。option+active 越过大限(grant + term_years)同理。
- F_UNVEST 在离职日一次结清:shares − vested(end_date)。
- as-of 是状态机的时钟:**时间机器拨回窗口关闭前,BLOWN 未发生,27,000 股复活成在册**——账本的「过去」是活的。

### 3.3 事件分摊(FIFO)

同公司多份授予时,事件按授予日序分摊到池。分摊不下(事件超过全部池)直接抛 LedgerError——**宁可拒绝,不静默吞掉超额事件**(超额行权被吞会悄悄破坏恒等式,这类静默是账本的头号敌人)。

### 3.4 钱的三种形态

- **在册纸面** = in_stock × latest_price;option 附加「行权要先掏 strike × in_stock」——不掏,纸面永远不是你的。
- **已落袋** = Σ tender 事件按各自成交价——唯一离开纸面的钱,不用 latest_price。
- **作废记忆** = F_WIN × (price − strike) + F_UNVEST × price,按最后一轮价(过时则盖「旧地图」戳)——它不是钱,是**没人替你记的损失**。

## 4. 与直觉的三处对决

1. **「我的期权值 200 万」** → 拆成四行:在册纸面多少、行权先掏多少、净纸面多少、已落袋多少。不拆的市值是幻觉。
2. **「离职了期权就没了」** → 只对一半:未归属部分作废,已归属部分还给你 90 天——但这 90 天是一把静默的倒计时,BLOWN-WINDOW 灯记录的就是「倒计时走完而无人按铃」的样本。
3. **「等上市再说」** → 期权大限(通识 10 年)比上市更早到;样例 TERM-EXPIRED 测试钉死了这一点。

## 5. 开发中自纠(测试价值记录)

- **节点 0 重复计数**:cliff=0 的授予,首节点(授予日)落进等额分支但分母 k 只数 len−1 → Σ节点 = 625 > 总股数 500,恒等式必破。被「前向累加 == 补集」对拍网格当场抓住(丙公司 2023-06-01:125 != 0)。修正后:cliff=0 时全部节点平摊总股数。
- **手算三连错,程序三连对**:①青苔月度节点手算 220、程序 208(range 从 cliff+step 开始,k=36 → 7,500//36);②季付步进手算 +300、实际 +75(900 摊 12 季);③无悬崖年付认为 250/节点、实际 200(5 节点摊 1,000)。样例数字先手算再钉的传统再次把错抓在手算侧。
- **事件重放排序**:同日「归属 + 行权」合法(当天归属当天行权),归并流必须先进水后出水——按 (date, kind: vest<exercise<tender) 排序钉死。
- **超额分摊静默吞掉**:alloc_events 溢出时曾静默丢弃,FIFO 分摊的 for-else 现在直接抛账坏(iou 的「超额回款被吞」同款教训)。
- **strike 绑错估值**:初版把行权现金算在 priced grant 上,无价格的青苔 exit 显示「需掏 ¥0」——行权价是授予条款,与有没有估值无关。
- **stale 夹具自锚**:单授予账本里 price_date 就是最大日期 → as-of 锚到 pd 本身, staleness 恒 0,灯永远不亮——需要第二个锚点日期把 as-of 顶起来。

## 6. FAQ

**Q:为什么不做 offer 对比(两家公司期权包哪个值)?**
A:比较需要概率(公司成不成),发明概率就是算命。账本只对已签署的合同负责;offer 上的期权,签了再入账。

**Q:为什么不用黑石定价/BS 公式给期权估值?**
A:私有公司期权的价格 discoverable 于回购与融资,不 discoverable 于公式;BS 的波动率与期限参数对本件的用户是伪精度。latest_price 你抄什么算什么。

**Q:加速条款(single/double trigger)呢?**
A:条款空间无限,公式只做最常见形态;被加速的日程抄进 schedule.tsv——授予协议永远赢。

**Q:税呢?**
A:归属/行权的税务因地区、身份、上市与否千差万别,建模任何一档都是错的起点;行权现金(strike)是确定的,税是顾问的事。

**Q:多久看一次?**
A:三个时点:新授予入账时、动离职念头时(exit 推演)、每年看到融资新闻时(更新 latest_price)。灯会在该响的时候响。

## 7. 诚实条款(与 README 第七节同源)

纸面不是口袋;律所永远赢;它不建议你走或不走;作废是算出来的不是填的;已发生的损失记账不抹平;数据不出本机。
